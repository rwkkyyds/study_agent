## 问题 1：human_version 是怎么传进 human_edit 的？

### 1. 原问题

在 `demo3_edit_before_send.py` 里：

```python
def human_edit(state: ReplyState) -> dict:
    print("[暂停] 需要人工审核并可修改回复")
    edited_reply = interrupt(
        {
            "question": "请审核这段回复，可以直接通过，也可以修改后继续。",
            "customer_question": state["customer_question"],
            "draft_reply": state["draft_reply"],
        }
    )
    return {"final_reply": edited_reply}
```

客服修改后的 `human_version` 看起来没有作为参数传入 `human_edit(state)`，那它到底是怎么进去的？

### 2. 通俗解释

`human_version` 不是普通函数参数。

它是通过 LangGraph 的恢复机制传进去的。

第一次运行时：

```python
edited_reply = interrupt(...)
```

流程会暂停，`interrupt()` 把问题和草稿抛给外部。

第二次运行时：

```python
app.invoke(Command(resume=human_version), config=config)
```

LangGraph 会找到同一个 `thread_id` 对应的暂停流程，回到刚才 `interrupt()` 那一行。

然后让：

```python
interrupt(...)
```

直接返回：

```python
human_version
```

所以恢复后等价于：

```python
edited_reply = human_version
return {"final_reply": edited_reply}
```

### 3. 对应代码

第一次运行，流程暂停：

```python
first_result = app.invoke(
    {
        "customer_question": "我已经等了两天，为什么还没有退款？",
        "draft_reply": "",
        "final_reply": "",
        "sent": False,
    },
    config=config,
)
```

模拟人工修改：

```python
human_version = (
    "您好，抱歉让您等待。我们已经查询到您的退款申请，"
    "预计将在 1 个工作日内原路退回。感谢您的耐心。"
)
```

第二次运行，恢复流程：

```python
final_result = app.invoke(Command(resume=human_version), config=config)
```

### 4. 容易错的点

不要理解成：

```text
human_edit(human_version)
```

真实情况是：

```text
Command(resume=human_version)
  -> 恢复暂停流程
  -> interrupt() 返回 human_version
  -> edited_reply = human_version
```

### 5. 最终记忆句

```text
Command(resume=...) 传入的值，会变成上一次 interrupt() 的返回值。
```
