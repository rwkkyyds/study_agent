## 3. 核心 API 速记

### interrupt()

作用：

```text
暂停当前流程，把等待人工处理的信息抛出去。
```

常见写法：

```python
decision = interrupt(
    {
        "question": "是否批准？",
        "task": state["task"],
        "suggested_options": ["approve", "reject"],
    }
)
```

第一次执行：流程暂停。

恢复执行：`interrupt()` 返回人工输入。

### Command(resume=...)

作用：

```text
把人工结果交回给暂停中的流程。
```

常见写法：

```python
app.invoke(Command(resume="approve"), config=config)
```

也可以传结构化数据：

```python
app.invoke(
    Command(resume={"decision": "approve", "comment": "确认通过"}),
    config=config,
)
```

### MemorySaver

作用：

```text
保存暂停时的流程状态。
```

demo 写法：

```python
graph.compile(checkpointer=MemorySaver())
```

学习阶段够用，生产阶段要换成持久化方案。

### thread_id

作用：

```text
标识同一条流程，让第二次恢复能找到第一次暂停的位置。
```

常见写法：

```python
config = {"configurable": {"thread_id": "order-001"}}
```

## 4. 最小心智模型

把 HITL 理解成下面这条链：

```text
Agent 做到关键步骤
        ↓
interrupt() 暂停
        ↓
把上下文交给人
        ↓
人做决定或修改内容
        ↓
Command(resume=人的结果)
        ↓
流程从暂停点继续
```

## 5. 真实业务映射

### 客服退款

```text
用户申请退款
  -> Agent 判断金额和风险
  -> 小额自动处理
  -> 大额暂停给主管审批
  -> 审批通过后退款
  -> 记录审计日志
```

### 邮件发送

```text
Agent 生成邮件草稿
  -> 暂停给运营审核
  -> 人修改标题和正文
  -> 恢复流程
  -> 发送最终版本
```

### 数据删除

```text
Agent 找到待删除数据
  -> 暂停给管理员确认
  -> 管理员批准
  -> 执行删除
  -> 记录删除范围和审批人
```
