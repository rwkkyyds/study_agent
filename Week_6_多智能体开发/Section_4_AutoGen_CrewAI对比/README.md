# Week 6 Section 4: AutoGen / CrewAI 框架对比选型

## 这一节到底学什么

这一节是 Day39，教学大纲明确标注「压缩1天，了解即可」。

所以目标不是让你精通 AutoGen 或 CrewAI 的所有 API，而是：

```text
看懂这两个框架的编排思路有什么本质不同，
以后做技术选型时，能说清"为什么选这个、不选那个"。
```

可以先记一句话：

```text
AutoGen 偏"对话驱动"：多个 Agent 在一个会话里互相说话推进。
CrewAI 偏"任务驱动"：把一个目标拆成一串任务，按顺序分给不同角色。
```

这一节和上一节（Agent SDK 生态）是同一条线：
上一节看的是"单个 Agent 怎么定义/跑工具/约束输出"，
这一节看的是"多个 Agent 怎么编排到一起干活"。

## 两个框架的核心差异（先看这张表就够了）

| 维度 | AutoGen | CrewAI |
|------|---------|--------|
| 编排思路 | 对话驱动（多 Agent 互相说话） | 任务驱动（目标拆成任务串行/并行） |
| 基本单位 | ConversableAgent（会说话的角色） | Crew（一队人） + Task（任务） + Agent（角色） |
| 协作方式 | Agent 之间发消息，谁回话由流程控制 | 任务按顺序流给下一个 Agent，像流水线 |
| 典型场景 | 需要讨论、反复确认、头脑风暴 | 流程清晰、能拆成步骤、像流水线的业务 |
| 心智模型 | 像一个"群聊" | 像一个"项目组分工" |
| 控制粒度 | 谁先说、谁接话、说几轮 | 任务依赖、串/并行、上一个完成才下一个 |

一句话类比：

```text
AutoGen = 把几个专家拉进一个群，让他们自己聊出结论。
CrewAI = 给一个项目组派一串任务，每人做完自己的环节交棒。
```

## 为什么这一节不直接装真实框架

因为大纲标注「了解即可」，目标是理解思想，不是跑通生产代码。

真实 AutoGen / CrewAI 有两个门槛：

```text
1. 依赖重：AutoGen 装包会带一堆依赖，CrewAI 同理
2. 要大模型：真实多 Agent 协作必须调 LLM，没有 API Key 跑不动
```

所以本节用零依赖的轻量实现，把两个框架的"编排骨架"抽出来给你看。

等你真要做选型时，再对照这里的思路去读官方文档，会快很多。

## 开发里什么时候会用到

当你遇到这种需求时，就该考虑多 Agent 框架：

```text
一个 Agent 搞不定，需要不同角色配合
任务有多个环节，每个环节要不同能力
需要讨论/确认/审核，不是一次性出结果
流程能拆成步骤，希望可控可追溯
```

选型判断（经验，不是铁律）：

```text
任务能拆成清晰流水线      → 优先看 CrewAI 思路
需要多角色反复讨论/协商    → 优先看 AutoGen 思路
要精细控制状态机和分支     → 其实用 LangGraph 更合适（第6周前两节已学）
```

所以本节的结论不是"哪个更好"，而是：

```text
没有最好的框架，只有最匹配场景的编排思路。
```
