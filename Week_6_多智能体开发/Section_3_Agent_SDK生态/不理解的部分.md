# Week 6 Section 3：不理解的部分记录

## 1. Agent SDK 到底是不是又一个 LangChain？

不是完全等价。

你可以这样理解：

```text
LangChain 更像 LLM 应用组件库；
Agent SDK 更聚焦 Agent 的运行方式；
LangGraph 更聚焦复杂流程编排。
```

它们会有重叠，但关注点不一样。

不要纠结名字，重点看它解决什么问题。

## 2. 为什么 demo1 要自己写一个假的 SDK 骨架？

demo1 不是为了造轮子。

它是为了让你先看清楚所有 SDK 背后的共同结构：

```text
Agent
Tool
Runner
Result
```

你理解这个骨架后，再看任何 SDK 都不会懵。

比如看到 OpenAI Agents SDK：

```text
Agent 是 Agent
@function_tool 是 Tool
Runner.run 是 Runner
run result 是 Result
```

看到 PydanticAI 也是类似：

```text
Agent 是 Agent
tools 是 Tool
agent.run_sync 是 Runner
result.output 是 Result
```

## 3. PydanticAI 为什么强调结构化输出？

因为真实后端系统不能只吃自然语言。

比如模型返回：

```text
这个问题应该是支付类，优先级挺高，建议查订单。
```

人能懂，但程序不好判断。

如果返回：

```json
{
  "category": "payment",
  "priority": 4,
  "next_action": "查询订单状态"
}
```

程序就能继续处理：

```text
category 决定走哪个流程
priority 决定是否加急
next_action 展示给客服或进入下一节点
```

这就是结构化输出的意义。

## 4. TestModel 是不是模拟？为什么说是真实 demo？

`TestModel` 是 PydanticAI 官方提供的测试模型。

它不是真实大模型，但它是真实 SDK 的一部分。

本节用它的原因是：

```text
学习 SDK 结构时，不应该被 API Key、网络、费用干扰。
```

它适合验证：

- Agent 是否能创建
- output_type 是否生效
- result.output 是否是 Pydantic 模型
- 代码结构是否正确

等这些跑通后，再换真实模型。

## 5. OpenAI Agents SDK 为什么 demo3 没有 Runner.run？

因为真实 `Runner.run` 需要可用模型和 API Key。

这节的目标是先看懂：

```text
Agent 怎么定义
Tool 怎么声明
Tool 怎么挂到 Agent 上
```

所以 demo3 没有强行调用远程模型。

后面如果要接真实 OpenAI 或兼容 OpenAI API 的模型，再补 Runner.run 会更顺。

## 6. Agent SDK 和 LangGraph 怎么搭配？

可以这样记：

```text
LangGraph 管流程
Agent SDK 管单个 Agent 怎么工作
```

比如一个客服系统：

```text
LangGraph：
  分类 -> 订单处理 -> 人工确认 -> 回复

Agent SDK：
  在“订单处理”节点里调用模型和工具
```

它们不是必须二选一。

生产项目里经常组合使用。

## 7. 什么时候不要用 Agent SDK？

如果你的需求只是：

```text
给模型一个 prompt
拿一段文本回来
```

那直接用模型 API 就够了。

不要为了显得高级强行上 SDK。

SDK 适合在复杂度上来后使用：

```text
工具多
流程多
输出要校验
要接外部系统
要追踪和监控
要多人维护
```

## 8. 怎么快速看懂一个新 Agent SDK？

不要从第一页文档开始硬啃。

先找这几个问题：

```text
1. Agent 怎么定义？
2. Tool 怎么注册？
3. Runner 怎么执行？
4. Result 怎么获取？
5. 输出怎么约束？
6. 错误和日志怎么处理？
```

这几个找到了，就能先跑起来。

高级功能后面再补。

## 9. 本节最容易混淆的点

```text
Agent：角色和任务
Tool：外部能力
Runner：执行器
Result：执行结果
PydanticAI：强结构化输出
OpenAI Agents SDK：官方 Agent 工具调用生态
LangGraph：复杂流程编排
MCP：外部工具接入协议
```
