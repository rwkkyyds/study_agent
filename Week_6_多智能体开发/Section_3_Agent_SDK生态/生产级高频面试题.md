# Week 6 Section 3：生产级高频面试题

## 1. 什么是 Agent SDK？

Agent SDK 是用来构建 Agent 应用的一套开发框架。

开发视角可以这样回答：

```text
Agent SDK 通常会封装模型调用、工具注册、tool calling、结构化输出、运行追踪和安全边界，
让开发者不用每个项目都从零写一套 Agent 执行框架。
```

## 2. Agent SDK 解决的核心问题是什么？

核心问题是把 Agent 项目的通用工程能力标准化。

包括：

- Agent 定义
- 工具注册
- 模型调用
- 工具调用
- 结构化输出
- 运行日志
- 错误处理
- 多 Agent 协作
- MCP 工具接入

一句话：

```text
SDK 让 Agent 项目更容易维护、扩展和上线。
```

## 3. Agent、Tool、Runner、Result 分别是什么？

可以这样回答：

```text
Agent 是角色和任务定义；
Tool 是 Agent 可以调用的外部能力；
Runner 是执行器，负责运行 Agent；
Result 是运行后的输出结果。
```

举例：

```text
客服 Agent
  -> 工具：查订单、查知识库、计算退款
  -> Runner：根据用户输入执行 Agent
  -> Result：最终回复或结构化处理建议
```

## 4. 什么场景需要 Agent SDK？

适合用 Agent SDK 的场景：

- 需要多个工具
- 需要模型自动选择工具
- 需要结构化输出
- 需要多步骤执行
- 需要运行追踪
- 需要安全限制
- 需要多 Agent 协作
- 需要接入 MCP 等工具生态

不一定需要的场景：

```text
只是一次简单的 prompt 调用。
```

## 5. PydanticAI 适合解决什么问题？

PydanticAI 很适合结构化输出和类型约束。

面试表达：

```text
如果我的 Agent 输出需要进入后端系统，比如写数据库、进入工单流程或触发自动化动作，
我会倾向用 PydanticAI 或 Pydantic 模型约束输出，避免模型返回一段不可控文本。
```

## 6. 为什么结构化输出很重要？

因为生产系统不能只依赖自然语言文本。

自然语言适合人看，但程序更需要稳定字段。

例如：

```json
{
  "category": "payment",
  "priority": 4,
  "next_action": "查询订单状态"
}
```

这种输出可以被：

- API 使用
- 数据库存储
- 前端展示
- 工作流路由
- 监控统计

## 7. OpenAI Agents SDK 适合什么场景？

OpenAI Agents SDK 更适合 OpenAI 生态下的 Agent 开发。

常见能力包括：

- function tool
- handoff
- guardrails
- tracing
- MCP server 接入
- streaming

可以这样说：

```text
如果项目主要使用 OpenAI 模型，并且需要工具调用、handoff、guardrails 和 tracing，
OpenAI Agents SDK 是一个比较直接的选择。
```

## 8. LangGraph 和 Agent SDK 是什么关系？

LangGraph 更偏流程编排。

Agent SDK 更偏 Agent 开发抽象。

它们不是完全互斥。

可以这样理解：

```text
LangGraph 管流程怎么走；
Agent SDK 管 Agent 怎么调用模型和工具。
```

真实项目可以组合使用：

```text
LangGraph 负责分支、循环、HITL；
OpenAI Agents SDK 或 PydanticAI 负责单个节点里的 Agent 能力。
```

## 9. MCP 和 Agent SDK 是什么关系？

MCP 是工具接入协议。

Agent SDK 是开发 Agent 的框架。

可以这样回答：

```text
MCP 解决的是外部工具如何标准化暴露给 Agent；
Agent SDK 解决的是 Agent 如何使用模型、工具、输出和流程。
```

两者可以配合：

```text
MCP 提供工具
Agent SDK 调用工具
LangGraph 编排流程
```

## 10. 怎么做 Agent SDK 选型？

可以从项目痛点出发：

```text
流程复杂 -> LangGraph
结构化输出强 -> PydanticAI
OpenAI 官方生态 -> OpenAI Agents SDK
多 Agent 快速原型 -> CrewAI / AutoGen
外部工具标准化 -> MCP
```

不要只看框架热度。

要看项目需要什么：

- 可控性
- 类型安全
- 工具生态
- 多 Agent 协作
- 可观测性
- 部署复杂度

## 11. Agent SDK 项目上线有什么风险？

常见风险：

- 工具权限过大
- 输出结构不稳定
- 缺少运行日志
- 缺少重试和超时
- API Key 泄露
- 成本不可控
- 多 Agent 互相循环调用
- 缺少人工确认

生产建议：

```text
工具要最小权限，输出要校验，关键动作要 HITL，运行过程要可观测，成本和 token 要监控。
```

## 12. 如何设计一个生产级 Agent SDK 服务？

可以这样回答：

```text
我会先定义 Agent 的职责边界，再注册必要工具，并用 Pydantic 模型约束输出。
流程复杂的部分交给 LangGraph 编排，外部工具通过 MCP 或内部 API 接入。
同时加入日志、trace、metrics、超时、重试和关键操作的人审节点。
```

这个回答能体现你不是只会调模型，而是在考虑工程落地。

## 13. 什么情况下不建议上 Agent SDK？

不建议的情况：

- 只是简单聊天
- 只是一次 LLM 调用
- 没有工具调用
- 没有结构化输出要求
- 项目还在很早期验证 prompt

这时直接用模型 API 更简单。

等需求变复杂，再引入 SDK。


## 15. 面试一句话总结

```text
Agent SDK 的价值不是让模型更聪明，而是让 Agent 应用更工程化：工具可管理、输出可校验、流程可追踪、系统可维护。
```
