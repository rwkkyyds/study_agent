# Week 6 Section 3 学习资料：Agent SDK 生态到底怎么选

## 1. 先说人话

Agent SDK 不是一个神秘东西。

你可以把它理解成：

```text
帮你把“模型 + 工具 + 输出格式 + 执行流程 + 监控/安全”组织起来的一套开发框架。
```

如果你只是问大模型一句话：

```text
用户输入 -> LLM -> 文本输出
```

那你不一定需要 Agent SDK。

但如果你的项目开始变成这样：

```text
用户输入
  -> 判断任务类型
  -> 选择工具
  -> 调用数据库 / API / MCP
  -> 要求输出 JSON
  -> 校验结果
  -> 记录日志
  -> 必要时人工确认
```

这时候就需要 SDK 帮你把这些东西管起来。

## 2. Agent SDK 通常解决哪些问题

不管是 OpenAI Agents SDK、PydanticAI、LangGraph，还是 AutoGen、CrewAI，它们通常都在解决这几类问题：

```text
1. 怎么定义一个 Agent
2. 怎么给 Agent 挂工具
3. 怎么让 Agent 调用工具
4. 怎么约束输出格式
5. 怎么追踪运行过程
6. 怎么做多 Agent 协作
7. 怎么接入外部工具生态
```

所以你不要一开始就问：

```text
哪个框架最强？
```

更应该问：

```text
我的项目现在最需要哪种能力？
```

## 3. demo1：Agent SDK 的共同骨架

文件：

```text
demo1_sdk_common_runtime.py
```

这个 demo 没有绑定任何具体 SDK。

它故意用最简单的 Python 写出 SDK 背后的共同结构：

```text
Agent：定义角色、指令、工具列表
Tool：可以被调用的函数
Runner：负责执行 Agent
Result：最终返回结果
```

你可以把它理解成所有 Agent SDK 的“骨架模型”。

真实 SDK 只是把这些事情做得更完整：

```text
工具 schema 自动生成
模型 tool calling 自动处理
结构化输出自动校验
运行日志自动追踪
异常和重试自动管理
```

### 开发里什么时候用这个思路

当你看到一个新 SDK，不要先怕它 API 多。

先找这几个东西：

```text
Agent 怎么声明？
Tool 怎么注册？
Runner 怎么执行？
Result 怎么拿？
```

只要这四个看懂了，大部分 Agent SDK 就能快速上手。

## 4. demo2：PydanticAI 结构化输出

文件：

```text
demo2_pydantic_ai_structured_output.py
```

这个 demo 使用真实的 `pydantic-ai`。

核心不是模型回答了什么，而是：

```text
SDK 可以把输出约束成一个 Pydantic 模型。
```

比如我们定义：

```python
class TicketAnalysis(BaseModel):
    category: str
    priority: int
    next_action: str
```

那最后拿到的不是一段随意文本，而是：

```text
result.output.category
result.output.priority
result.output.next_action
```

这对真实开发很重要。

因为后端服务不喜欢这种输出：

```text
“这个用户大概是支付问题吧，我建议你查一下订单。”
```

后端更喜欢这种输出：

```json
{
  "category": "payment",
  "priority": 4,
  "next_action": "查询订单状态，并确认是否需要人工退款审批。"
}
```

结构化输出的价值就是：

```text
程序可以继续处理结果，而不是只能给人看。
```

### PydanticAI 适合什么场景

PydanticAI 很适合：

- 强调类型安全
- 强调结构化输出
- 想用 Pydantic 模型约束结果
- 后端服务需要稳定 JSON
- AI 输出要进入数据库、工作流或 API

比如：

```text
简历解析
工单分类
风控判断
订单意图识别
面试报告生成
结构化评分
```

## 5. demo3：OpenAI Agents SDK 的 Agent / Tool 形态

文件：

```text
demo3_openai_agents_tool_shape.py
```

这个 demo 使用真实 `openai-agents` 包。

它重点展示：

```text
怎么定义 Agent
怎么用 @function_tool 定义工具
怎么把工具挂到 Agent 上
```

核心代码形态是：

```python
@function_tool
def lookup_policy(topic: str) -> str:
    ...

agent = Agent(
    name="refund_assistant",
    instructions="...",
    tools=[lookup_policy],
)
```

这就是 OpenAI Agents SDK 的基本开发体验。

它适合你用 OpenAI 生态做：

- 工具调用
- 多 Agent handoff
- guardrails
- tracing
- MCP server 接入

本节 demo 没有直接 `Runner.run`，因为真实运行需要模型和 API Key。

但你已经看到了 SDK 的基本形态：

```text
Agent 是角色
instructions 是任务说明
tools 是可用能力
Runner.run 是真实执行入口
```

## 6. LangGraph、PydanticAI、OpenAI Agents SDK 怎么选

可以先用这个非常实用的判断：

| 你最关心什么 | 更适合优先看 |
|---|---|
| 流程复杂、分支多、HITL、多步骤编排 | LangGraph |
| 输出必须稳定成 Pydantic/JSON | PydanticAI |
| 想走 OpenAI 官方 Agent 生态、tools、handoff、guardrails | OpenAI Agents SDK |
| 多个角色协作、快速搭多 Agent 原型 | CrewAI / AutoGen |
| 外部工具标准化接入 | MCP |

不是只能选一个。

真实项目经常是组合：

```text
LangGraph 管流程
Pydantic 管输出结构
OpenAI / DeepSeek / 智谱 负责模型调用
MCP 负责接外部工具
Prometheus / LangSmith 负责观测
```

## 7. 作为开发，你应该怎么学 SDK

不要这样学：

```text
把每个 SDK 文档从头背到尾
```

应该这样学：

```text
先跑通最小 demo
再看 Agent / Tool / Runner / Result
再接入一个真实业务场景
最后再补高级能力
```

比如你现在就已经看到：

```text
demo1：所有 SDK 的共同骨架
demo2：PydanticAI 怎么约束输出
demo3：OpenAI Agents SDK 怎么声明 Agent 和工具
```

这比一上来背概念更实用。

## 8. 本节你真正要带走什么

一句话：

```text
Agent SDK 是为了让 Agent 项目从“能跑”变成“能维护、能扩展、能接工具、能被后端系统消费”。
```

你以后看任何 Agent SDK，都先问：

```text
它怎么定义 Agent？
它怎么挂工具？
它怎么执行？
它怎么约束输出？
它怎么观测和调试？
```

这几个问题问清楚，选型就不会乱。
