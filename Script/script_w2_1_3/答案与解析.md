### Q7：RRF 融合代码（修正版）

```python
def reciprocal_rank_fusion(
    results_list: list[list],  # 多个检索器返回的排序结果
    k: int = 60,               # RRF 参数，控制权重衰减速度
    top_n: int = 5             # 返回前N个结果
) -> list:
    """
    RRF（Reciprocal Rank Fusion）融合多个检索器的排序结果
    公式：score(d) = Σ 1 / (k + rank_i(d))
    """
    scores: dict[str, float] = {}     # 文档ID -> 融合分数
    doc_map: dict[str, any] = {}      # 文档ID -> 文档对象（保留第一个）

    for result in results_list:       # 遍历每个检索器的结果
        for rank, doc in enumerate(result):  # enumerate 获取排名（从0开始）
            doc_id = doc.metadata.get("id", doc.page_content[:50])  # 取文档唯一标识

            if doc_id not in scores:
                scores[doc_id] = 0.0
                doc_map[doc_id] = doc   # 保留文档对象

            # RRF 核心公式：排名越靠前，分数越高
            scores[doc_id] += 1.0 / (k + rank)

    # 按融合分数降序排序，取 top_n
    sorted_docs = sorted(scores.items(), key=lambda x: x[1], reverse=True)
    return [doc_map[doc_id] for doc_id, _ in sorted_docs[:top_n]]
```

### Q8：RAGAs 评估脚本（修正版）

```python
from datasets import Dataset
from ragas import evaluate
from ragas.metrics import (
    faithfulness,          # 忠实度：回答是否基于上下文
    answer_relevancy,      # 回答相关性：回答是否切题
    context_precision,     # 上下文精准度：排名靠前的是否相关
    context_recall,        # 上下文召回率：是否遗漏重要信息
)

def evaluate_rag_system(
    qa_pairs: list[dict],  # [{"question": ..., "contexts": [...], "answer": ..., "ground_truth": ...}]
    llm=None,              # 评估用的 LLM（RAGAs 内部用 LLM 做评判）
    embeddings=None        # 评估用的 Embedding 模型
) -> dict:
    """
    使用 RAGAs 评估 RAG 系统质量
    返回: 各项指标的平均分数
    """
    # 1. 构造 HuggingFace Dataset
    dataset = Dataset.from_dict({
        "question":     [p["question"] for p in qa_pairs],
        "answer":       [p["answer"] for p in qa_pairs],
        "contexts":     [p["contexts"] for p in qa_pairs],
        "ground_truth": [p["ground_truth"] for p in qa_pairs],
    })

    # 2. 调用 RAGAs 评估
    result = evaluate(
        dataset=dataset,
        metrics=[faithfulness, answer_relevancy, context_precision, context_recall],
        llm=llm,
        embeddings=embeddings,
    )

    # 3. 返回评估结果
    return result
```

### Q9：场景题（你的回答 ✓）

**问题分析：** 用户问"Python 和 Java 的区别是什么？"，但检索只返回 Python 相关文档。

**根因：** 用户问题太短、太抽象，与文档的表述存在语义鸿沟（vocabulary mismatch）。

**解决方案（组合使用）：**
1. **多查询改写** — 把问题改写成多个角度：
   - "Python 的特点和应用场景"
   - "Java 的特点和应用场景"
   - "Python 和 Java 的对比差异"
2. **HyDE** — 让 LLM 生成一个假设性的对比回答，用这个回答做向量检索
3. **RRF 融合** — 合并多路检索结果
4. **Rerank 重排** — 用 Cross-Encoder 精排，选出最相关的文档

## Part 3：概念辨析

### Q10：一句话区分

| 对比项 | 一句话区分 |
|--------|-----------|
| **粗检索 vs 精排** | 粗检索（BM25+Bi-Encoder 向量检索）负责"快速召回一批候选文档"，精排（Cross-Encoder Rerank）负责"对候选文档逐对打分，重新排序" |
| **Context Precision vs Faithfulness** | Context Precision 衡量"检索环节"——排名靠前的文档是否和问题相关；Faithfulness 衡量"生成环节"——回答是否忠于检索到的上下文，有没有编造 |
| **HyDE vs Multi-Query** | HyDE 是"让 LLM 先写一个假设回答，用回答做检索"（解决语义鸿沟）；Multi-Query 是"把原问题改写成多个不同角度的 query，分别检索后合并"（提高召回覆盖面） |
