# Week 5 Section 6: Grafana 监控大盘 — 学习笔记

## 核心一句话

Grafana 不负责采集指标，只负责把 Prometheus 里的数字变成图，让人一眼看懂系统健康状态。

## 架构关系

```
FastAPI 服务
  └─ 暴露 /metrics（prometheus_client 格式）
       └─ Prometheus 定时抓取 /metrics
            └─ Grafana 连接 Prometheus（DataSource）
                 └─ Dashboard 画出请求量、错误率、P95 耗时
```

## 关键概念

### 1. 三大指标类型（prometheus_client）

| 类型 | 特点 | 适用场景 | 示例 |
|------|------|----------|------|
| **Counter** | 只增不减 | 请求总数、错误总数 | `demo_http_requests_total` |
| **Histogram** | 分桶统计 | 请求耗时分布，算 P95/P99 | `demo_http_request_duration_seconds` |
| **Gauge** | 可增可减 | 当前在线用户、队列长度 | `demo_active_users` |

### 2. Grafana 核心概念

- **DataSource**：数据源，告诉 Grafana 去哪查数据（Prometheus URL）
- **Dashboard**：大盘，一张包含多个 Panel 的面板
- **Panel**：单个图表（折线图、柱状图、统计数字）
- **Provisioning**：自动导入配置，启动时自动创建 DataSource 和 Dashboard

### 3. 常用 PromQL

```promql
# 请求量（按路径和状态码分组）
sum by (path, status) (rate(demo_http_requests_total[1m]))

# 5xx 错误量
sum by (path) (rate(demo_http_requests_total{status=~"5.."}[1m]))

# P95 耗时
histogram_quantile(0.95, sum by (le, path) (rate(demo_http_request_duration_seconds_bucket[1m])))

# 当前活跃用户
demo_active_users
```

## 运行流程

1. 启动 FastAPI 指标服务：`uvicorn demo1_fastapi_metrics_app:app --reload --port 8000`
2. 启动 Prometheus + Grafana：`docker compose up -d`
3. 制造流量：`python demo2_load_generator.py`
4. 打开 Grafana：`http://localhost:3000`（admin/admin）
5. 查看自动导入的 `FastAPI Prometheus Overview` 大盘

## 开发者需要关注的三件事

1. 请求量有没有变化
2. 错误数有没有变化
3. 请求耗时有没有变化

## 常见问题

- **大盘是空的**：Prometheus 没抓到数据，检查 `prometheus.yml` 中 targets 地址
- **图表没数据**：服务没被访问，运行 load_generator 制造流量
- **P95 算不出来**：Histogram bucket 配置不合理，范围要覆盖实际耗时
