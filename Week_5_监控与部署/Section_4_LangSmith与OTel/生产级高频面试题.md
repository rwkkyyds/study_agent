# 第5周 Section_4：生产级高频面试题

## 1. 什么是可观测性？它和日志有什么区别？

可观测性是通过日志、指标、追踪等信号理解系统内部状态的能力。

日志回答“发生了什么”，指标回答“发生了多少、性能如何”，追踪回答“一次请求经过了哪些步骤”。

生产回答重点：

- 日志适合排查离散事件。
- 指标适合监控趋势和告警。
- 追踪适合定位跨服务链路瓶颈。

## 2. trace 和 span 有什么区别？

- `trace`：一次完整请求的链路。
- `span`：trace 中的一个子操作。

例如一次 RAG 请求可以是一个 trace，其中包含：

- 检索 span
- 重排 span
- Prompt 构造 span
- LLM 调用 span
- 结果后处理 span

## 3. LangSmith 和 OpenTelemetry 分别解决什么问题？

LangSmith 更关注 LLM 应用链路，比如 Prompt、模型输入输出、工具调用、RAG 上下文。

OpenTelemetry 是通用可观测性标准，更关注服务链路，比如 HTTP、数据库、Redis、消息队列、外部 API。

面试中可以这样说：

```text
LangSmith 帮我看清 AI 调用内部发生了什么，OpenTelemetry 帮我看清系统请求链路发生了什么。
```

## 4. 为什么生产系统不能只靠 print 或普通日志？

普通日志通常缺少结构化关联信息，很难回答：

- 这次用户请求对应哪些下游调用？
- 哪一步最慢？
- 错误发生在哪个子步骤？
- 多服务之间如何串起来？

trace 能用同一个 trace id 把多个步骤串起来，更适合复杂系统排障。

## 5. FastAPI 中如何接入请求级追踪？

常见方式有两种：

- 使用 OpenTelemetry 官方或社区 instrumentation 自动埋点。
- 自定义 middleware，手动创建 span 并记录 method、path、status_code、cost_ms。

教学和小项目可以先用 middleware 理解原理，生产项目通常会结合自动埋点和自定义业务 span。

## 6. 什么信息适合放进 span attribute？

适合放：

- `http.method`
- `http.route`
- `http.status_code`
- `db.system`
- `retrieval.doc_count`
- `llm.model`
- `llm.output_length`

不适合放：

- 密码
- token
- 身份证
- 手机号
- 大段 prompt 或完整用户隐私内容

## 7. 什么是高基数字段？为什么要避免？

高基数字段是取值非常分散的字段，比如 user_id、request_id、完整 URL、完整问题文本。

风险：

- 存储成本高
- 查询聚合慢
- 监控系统压力大

生产中要谨慎把高基数字段作为 metric label 或 trace attribute。

## 8. 采样率是什么？为什么需要采样？

采样率决定多少请求会被上报 trace。

高流量系统如果所有请求都上报，会带来：

- 网络开销
- 存储成本
- 后端分析压力

常见策略：

- 正常请求低比例采样
- 错误请求尽量保留
- 慢请求提高采样
- 关键业务链路单独采样

## 9. OTel Collector 的作用是什么？

OTel Collector 是应用和观测后端之间的中转层。

它可以：

- 接收应用上报的 trace、metric、log
- 做采样、过滤、脱敏、批处理
- 转发到 Jaeger、Tempo、Datadog 等后端

生产环境通常不让每个应用直接对接多个观测平台，而是统一发给 Collector。

## 10. RAG 系统应该追踪哪些关键步骤？

建议追踪：

- 请求入口
- 查询改写
- 向量检索
- BM25 检索
- Rerank 重排
- Prompt 构造
- LLM 调用
- 输出解析
- 错误和降级路径

这样才能定位到底是检索慢、重排慢、模型慢，还是 Prompt 上下文质量差。

## 11. 如何排查一次 LLM 请求慢？

可以按 trace 拆解：

```text
总耗时
  -> 检索耗时
  -> 重排耗时
  -> Prompt 构造耗时
  -> LLM 首 token 延迟
  -> LLM 总生成耗时
  -> 后处理耗时
```

如果 LLM 总生成耗时高，可以看输出 token 数；如果首 token 慢，可以看模型服务或网络；如果检索慢，可以看向量库索引和过滤条件。
