# Section_4 生产级高频面试题

## 1. trace、span、log 有什么区别？

`trace` 描述一次完整请求，`span` 描述请求中的一个时间片段，`log` 是某个时刻输出的事件记录。生产系统通常通过 `trace_id` 把三者关联起来。

## 2. 为什么要在入口生成 trace_id？

入口生成后，后续检索、模型调用、数据库访问都可以继承同一个 ID。这样可以把分散在多个模块甚至多个服务中的日志串成一次请求。

## 3. 如何处理跨服务调用？

通过 HTTP header 传播上下文，常见做法是 W3C Trace Context，例如 `traceparent`。服务收到后继续使用父上下文，并创建自己的子 span。

## 4. 为什么不能把原始 prompt 全量写入 tracing？

原始 prompt 可能包含密码、Token、个人信息或企业机密。应先脱敏、截断、分级采样，并明确数据保留周期。

## 5. OpenTelemetry 和 LangSmith 是什么关系？

OpenTelemetry 更偏标准化的采集、上下文传播和导出协议；LangSmith 更偏 LangChain/Agent 调试、运行追踪和评估平台。两者可以组合使用。

## 6. 生产环境如何降低追踪开销？

可以采用采样、异步导出、批量发送、限制属性大小和只保留关键 span。错误请求和慢请求通常应提高采样优先级。

## 7. 看到请求耗时升高，如何定位？

先按 trace 查看总耗时，再比较各子 span 的耗时分布，判断瓶颈是在检索、模型、数据库还是网络调用，最后结合错误率和资源指标验证假设。
