# 第5周 Section_4 学习笔记：LangSmith 与 OpenTelemetry

## 1. 本节核心目标

可观测性不是简单打印日志，而是让你知道一次请求从进入系统到返回结果，中间经历了哪些步骤、每一步花了多久、哪里出错。

本节关注两类工具：

- LangSmith：更适合观察 LLM、Agent、RAG 的输入输出和中间链路。
- OpenTelemetry：通用可观测性标准，适合服务、数据库、消息队列、外部 HTTP 等系统链路。

## 2. trace 和 span 的关系

```text
trace：一次完整请求
  ├── span：检索文档
  ├── span：构造 Prompt
  ├── span：调用模型
  └── span：返回结果
```

可以这样理解：

- `trace` 是整条流水线。
- `span` 是流水线里的一个工位。
- `attribute` 是给 span 打标签，例如 `http.status_code=200`。
- `event` 是 span 中发生的关键事件，例如 `request.received`。

## 3. LangSmith 适合看什么

LangSmith 主要解决 AI 应用调试问题，尤其适合：

- 查看用户输入和模型输出
- 查看 Prompt 最终长什么样
- 查看 RAG 检索到了哪些上下文
- 查看 Agent 调用了哪些工具
- 比较不同 Prompt、模型、检索策略的效果

`demo1_langsmith_trace.py` 中用 `@traceable` 标记函数：

```python
@traceable(name="answer_question", run_type="chain")
def answer_question(...):
    ...
```

被标记的函数会成为一段可追踪调用。父函数里调用子函数时，会形成父子链路。

## 4. 为什么 demo1 没有 API Key 也能跑

真实 LangSmith 在线追踪需要：

```powershell
$env:LANGSMITH_TRACING="true"
$env:LANGSMITH_API_KEY="你的 LangSmith API Key"
$env:LANGSMITH_PROJECT="ai-agent-bootcamp"
```

但教学阶段不能让 API Key 成为阻塞，所以代码里用：

```python
with tracing_context(enabled=enabled):
    response = answer_question(request)
```

如果没有 `LANGSMITH_API_KEY`，就关闭在线上报，只演示本地链路执行。

## 5. OpenTelemetry 适合看什么

OpenTelemetry 是跨语言、跨系统的可观测性标准。它不只服务于 LLM，也能观测：

- HTTP 请求
- 数据库查询
- Redis 调用
- 消息队列任务
- 外部 API 调用
- 后台异步任务

这类数据通常会被发送到：

- OpenTelemetry Collector
- Jaeger
- Grafana Tempo
- Datadog
- New Relic

## 6. 手动 span 的基本写法

`demo2_otel_manual_span.py` 的核心结构：

```python
with tracer.start_as_current_span("rag_request") as root_span:
    root_span.set_attribute("app.query_length", len(query))
    root_span.add_event("request.received")

    with tracer.start_as_current_span("retrieve_documents"):
        docs = retrieve_documents(query)
```

关键点：

- 外层 span 表示完整请求。
- 内层 span 表示子步骤。
- attribute 用来记录后续可筛选、可聚合的信息。
- event 用来记录某个时间点发生了什么。

## 7. FastAPI 中间件为什么适合做请求观测

FastAPI middleware 会包住每一次 HTTP 请求：

```text
请求进入
  -> middleware 开始计时
  -> 执行接口函数
  -> middleware 拿到响应状态码
  -> 记录耗时和状态
```

所以它适合统一记录：

- 请求方法：GET / POST
- 请求路径：/chat /health
- 响应状态码：200 / 422 / 500
- 耗时：cost_ms
- 异常：exception

`demo3_fastapi_otel.py` 就是这个思路。

## 8. 日志、指标、追踪的区别

```text
日志 logs：发生了什么
指标 metrics：发生了多少、快不快
追踪 traces：一次请求经过了哪些步骤
```

例子：

- 日志：用户 alice 登录成功。
- 指标：过去 1 分钟 QPS 是 120，P99 延迟是 800ms。
- 追踪：这次请求先查 Redis，再查 PostgreSQL，最后调用 LLM。

三者不是替代关系，而是互补关系。

## 9. 生产环境注意事项

- 不要在 trace 里记录密码、身份证、手机号、完整 token。
- attribute 要控制数量和长度，避免产生高基数字段。
- trace 采样率要根据流量调整，高流量系统不能全量上报。
- 错误请求要记录异常类型、状态码和关键上下文。
- OTel Collector 通常比应用直接上报后端更稳定。

## 10. 本节最小复盘

你需要掌握 4 个判断：

1. LangSmith 更适合 AI 链路，OpenTelemetry 更适合系统链路。
2. trace 是完整请求，span 是请求中的子步骤。
3. middleware 可以统一观测 FastAPI 请求。
4. 生产环境不能把敏感数据写进 trace。
