# Section_4 学习笔记：LangSmith 与 OpenTelemetry

## 1. 本节主线

一次 Agent 请求通常不是一个函数，而是一条调用链：

```text
HTTP request
  -> agent.run
      -> retriever.search
      -> llm.generate
```

可观测性就是把这条链路记录下来，方便回答三个问题：

- 哪一次请求出了问题？
- 问题发生在哪个步骤？
- 哪一步最慢？

## 2. trace 与 span

- `trace`：一次完整请求的总记录。
- `span`：请求中的一个步骤。
- `trace_id`：把同一次请求的日志串起来。
- `parent_id`：表示 span 的父子关系。

本节的 `demo1_otel_span_basic.py` 用标准库模拟了这些概念。生产环境可以把内部实现替换为 `opentelemetry-api` 和 `opentelemetry-sdk`。

## 3. FastAPI 请求级追踪

中间件适合做请求级工作：

1. 从 `X-Trace-Id` 读取外部链路 ID，没有时自动生成。
2. 保存到 `request.state.trace_id`。
3. 统一记录请求方法、路径、状态码和耗时。
4. 通过响应头把 trace ID 返回给调用方。

异常日志必须带上 trace ID，否则排查线上问题时很难从用户请求定位到服务日志。

## 4. LangSmith 的边界

LangSmith 属于外部可观测平台。接入通常需要：

- 安装 `langsmith`
- 配置 `LANGCHAIN_API_KEY` 或 `LANGSMITH_API_KEY`
- 配置项目名和追踪开关

本节 demo 默认不主动发送网络请求，避免在学习阶段意外上传输入内容。生产环境使用时，还要做敏感信息脱敏和数据保留策略。

## 5. 复盘清单

- 是否能解释 trace 和 span 的区别？
- 是否能用 trace ID 找到一次请求的全部日志？
- 是否能区分“请求失败”和“某个子步骤失败”？
- 是否能指出为什么不能把密码、JWT、身份证号直接写进 span 属性？
