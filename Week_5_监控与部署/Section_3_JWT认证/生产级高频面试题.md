# 第5周 Section_3：生产级高频面试题

## 1. JWT 是加密吗？为什么不能把敏感信息放进 JWT？

JWT 默认不是加密，而是签名。Header 和 Payload 只是 Base64Url 编码，任何拿到 token 的人都能解码看到里面的字段。

生产回答重点：

- JWT 的签名用于防篡改，不用于隐藏内容。
- Payload 只放用户 ID、角色、过期时间等少量非敏感信息。
- 密码、手机号、身份证、账户余额等敏感信息不能放进 JWT。

## 2. JWT 认证流程是什么？

标准流程：

```text
登录接口校验用户名密码
  -> 服务端签发 access_token
  -> 客户端保存 token
  -> 后续请求放入 Authorization: Bearer <token>
  -> 服务端校验签名、过期时间和用户状态
  -> 通过后进入业务接口
```

面试中要强调：服务端不是“信任客户端传来的用户信息”，而是信任自己用密钥签发且验证通过的 token。

## 3. access_token 和 refresh_token 有什么区别？

- `access_token`：访问业务接口，生命周期短，例如 15-30 分钟。
- `refresh_token`：用于换新的 access_token，生命周期更长，例如 7-30 天。

生产设计通常会让 access_token 短期有效，refresh_token 可撤销、可轮换、可入库管理。

## 4. 401 和 403 的区别是什么？

- 401：认证失败。比如没带 token、token 过期、token 无效。
- 403：授权失败。比如已登录的普通用户访问管理员接口。

一句话：401 是“不知道你是谁或身份无效”，403 是“知道你是谁但你没权限”。

## 5. JWT 如何实现强制用户下线？

JWT 是无状态的，单靠 access_token 很难立即失效。常见方案：

- Redis 黑名单：把被吊销的 token jti 写入 Redis，直到 token 自然过期。
- 用户 token_version：JWT 中放版本号，数据库或 Redis 中保存当前有效版本。
- 短 access_token + 可撤销 refresh_token：降低 access_token 泄露后的风险窗口。

## 6. 密码为什么不能用 MD5？bcrypt 的价值是什么？

MD5 太快，容易被暴力破解和彩虹表攻击。bcrypt 是专门用于密码哈希的算法，特点是：

- 自带 salt。
- 计算成本可调。
- 速度故意较慢，增加暴力破解成本。

生产环境还可以选择 Argon2、scrypt 等密码哈希算法。

## 7. OAuth2PasswordBearer 在 FastAPI 中做了什么？

它主要从请求头提取 Bearer Token，并配合 Swagger UI 生成认证入口。它不会自动校验用户名密码，也不会自动验证 JWT。

真正的 token 解码、用户查询、异常处理，需要在 `get_current_user()` 这类依赖函数里实现。

## 8. JWT 的签名算法怎么选？

常见选择：

- `HS256`：对称密钥，简单，适合单服务或内部系统。
- `RS256`：非对称密钥，私钥签发、公钥验证，适合多服务、开放平台、网关架构。

如果多个服务只需要验证 token，不应该都持有签发密钥，优先考虑 RS256。

## 9. 如何设计角色权限？

简单系统可以在 JWT 中放 `role`，接口用 `require_role()` 判断。

复杂系统建议使用 RBAC：

```text
User -> Role -> Permission -> API/Resource
```

JWT 里可以只放用户 ID 和少量角色信息，详细权限从数据库或缓存中查询，避免 token 太大或权限变更不及时。

## 10. JWT 泄露后怎么办？

应急和长期方案：

- 立即轮换密钥会让旧 token 全部失效，但影响面大。
- 使用黑名单吊销指定 token。
- 缩短 access_token 生命周期。
- 对 refresh_token 做服务端存储和撤销。
- 全站 HTTPS，避免传输泄露。
- 前端避免把 token 放在容易被 XSS 读取的位置。

## 11. 认证中间件和依赖注入怎么选？

依赖注入适合按接口精细控制，比如有些接口公开、有些接口需要登录、有些接口需要管理员。

中间件适合全局逻辑，比如记录请求日志、统一 trace id、全局 CORS、全局安全头。

FastAPI 项目里常见组合是：全局中间件处理通用逻辑，`Depends()` 处理具体接口认证和权限。
