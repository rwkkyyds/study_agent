# 第5周 Section_3 学习笔记：OAuth2.0 / JWT 认证

## 1. 本节核心链路

JWT 认证的主线不是“加密用户信息”，而是让服务端签发一个可验证的访问凭证。

```text
用户提交用户名密码
  -> 后端校验密码哈希
  -> 校验成功后签发 JWT
  -> 客户端请求时携带 Authorization: Bearer <token>
  -> 后端解析并验证 token
  -> 通过用户身份和角色决定能否访问接口
```

本节 3 个 demo 按递进关系组织：

- `demo1_jwt_login_basic.py`：登录校验 + JWT 签发。
- `demo2_security_dependency.py`：Bearer Token 提取 + 当前用户解析。
- `demo3_role_permission.py`：角色权限控制 + 403 权限不足。

## 2. 密码为什么要存哈希

密码不能明文入库。后端只保存 `password_hash`，登录时把用户输入的明文密码重新参与 bcrypt 校验。

```python
bcrypt.checkpw(
    plain_password.encode("utf-8"),
    password_hash.encode("utf-8"),
)
```

关键点：

- bcrypt 每次 `gensalt()` 都会生成不同盐值，所以同一个密码的哈希结果也可能不同。
- 校验密码时不要自己比较字符串，要交给 `bcrypt.checkpw()`。
- 数据库泄露时，哈希比明文安全得多，但仍然需要强密码和限流保护。

## 3. JWT 里应该放什么

本节的 JWT payload 包含：

```python
payload = {
    "sub": username,
    "role": role,
    "exp": expire_at,
}
```

字段含义：

- `sub`：Subject，表示 token 属于哪个用户。
- `role`：用户角色，用于基础权限判断。
- `exp`：过期时间，PyJWT 解码时会自动校验。

JWT 不适合放敏感信息。不要把密码、手机号、身份证、私密业务数据放进 token，因为 JWT payload 只是 Base64Url 编码，不是加密。

## 4. 401 和 403 的区别

认证和授权要分开理解：

```text
401 Unauthorized：你是谁还没验证通过
403 Forbidden：知道你是谁，但你没有权限访问
```

本节对应关系：

- 没带 token、token 无效、token 过期：返回 401。
- 普通用户访问管理员接口：返回 403。

## 5. OAuth2PasswordBearer 的作用

`OAuth2PasswordBearer(tokenUrl="login")` 主要做两件事：

- 从请求头里提取 `Authorization: Bearer <token>`。
- 告诉 Swagger UI 登录换 token 的接口地址。

它不会自动验证 JWT，也不会自动查询用户。真正的解析和校验逻辑在 `get_current_user()`。

## 6. FastAPI 安全依赖的价值

`Depends(get_current_user)` 把“解析当前用户”的逻辑变成可复用依赖。

```python
@app.get("/me")
def read_me(current_user: UserProfile = Depends(get_current_user)):
    return current_user
```

好处：

- 业务接口不用重复解析 token。
- 认证失败可以在依赖层统一返回 401。
- 后续接数据库、Redis、权限表时，只需要扩展依赖逻辑。

## 7. 角色权限如何复用

`require_role("admin")` 返回一个依赖函数，用于检查当前用户角色。

```python
@app.get("/admin/reports")
def read_admin_reports(
    admin_user: UserProfile = Depends(require_role("admin")),
):
    ...
```

这是一种常见写法：外层函数接收权限参数，内层函数执行真实校验。这样可以复用到多个接口：

- `require_role("admin")`
- `require_role("operator")`
- `require_role("auditor")`

## 8. 生产环境还缺什么

本节 demo 是教学链路，不是完整生产认证系统。生产环境通常还需要：

- `SECRET_KEY` 从环境变量读取，并定期轮换。
- 使用数据库存储用户、角色和密码哈希。
- 增加刷新令牌 `refresh_token`。
- 增加 token 黑名单、用户 token 版本号或强制下线机制。
- 登录失败限流，防止暴力破解。
- HTTPS，避免 token 在传输层泄露。

## 9. 本节最小复盘

你需要真正掌握的是这 4 个判断：

1. 登录成功为什么返回 token，而不是每次都传用户名密码。
2. token 为什么需要签名和过期时间。
3. `Depends(get_current_user)` 为什么能保护接口。
4. 401 和 403 分别应该在什么场景返回。
