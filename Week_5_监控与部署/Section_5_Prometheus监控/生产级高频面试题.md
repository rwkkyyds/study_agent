# 第5周 Section_5：生产级高频面试题

## 1. Prometheus 是做什么的？

Prometheus 是监控系统，主要负责采集、存储和查询指标。

开发视角可以这样回答：

```text
我用 Prometheus 观察服务是否健康，比如请求量、错误率、接口耗时、队列长度、业务事件次数。
```

## 2. Prometheus 是推模式还是拉模式？

Prometheus 默认是拉模式。

应用暴露 `/metrics`，Prometheus 定时来抓。

这意味着应用不用主动把指标发出去，只要保证 `/metrics` 可访问即可。

## 3. Counter、Gauge、Histogram 怎么选？

- Counter：累计次数，比如请求总数、错误总数。
- Gauge：当前状态，比如在线用户数、队列长度。
- Histogram：耗时分布，比如接口延迟、LLM 调用耗时。

一句话：

```text
次数用 Counter，状态用 Gauge，耗时用 Histogram。
```

## 4. 为什么接口耗时不用 Gauge？

Gauge 只能表示“当前某个值”，不适合分析大量请求的延迟分布。

接口耗时要看 P95、P99，应该用 Histogram 或 Summary。

Histogram 会记录不同耗时桶，后续可以计算延迟分位数。

## 5. 什么是 label？有什么风险？

label 是指标维度，比如：

```text
http_requests_total{method="POST",path="/chat",status="200"}
```

风险：

- label 过多会导致时间序列数量暴涨。
- 不要放 user_id、request_id、完整问题文本。
- 不要放密码、token、手机号等敏感信息。

## 6. FastAPI 项目如何接入 Prometheus？

常见做法：

1. 使用 `prometheus-client` 定义 Counter、Gauge、Histogram。
2. 用 middleware 统计请求次数、状态码和耗时。
3. 暴露 `/metrics` 接口返回 `generate_latest()`。
4. Prometheus 配置 scrape target 抓取该接口。

## 7. 如何监控 AI Agent 服务？

建议监控：

- HTTP 请求量和延迟
- LLM 调用次数和耗时
- LLM token 数
- Agent 工具调用次数
- 工具调用失败次数
- RAG 检索耗时
- 队列长度和任务失败数

这类指标能帮助你判断系统慢、贵、不稳定分别来自哪里。

## 8. Prometheus 和 Grafana 分别负责什么？

Prometheus 负责采集、存储、查询指标。

Grafana 负责把指标画成可视化图表和大盘。

简单说：

```text
Prometheus 管数据，Grafana 管看图。
```

## 9. Prometheus 和 OpenTelemetry 有什么区别？

Prometheus 主要看整体指标趋势。

OpenTelemetry trace 更适合看单次请求链路。

例子：

- 最近 5 分钟 `/chat` 错误率升高：Prometheus
- 某一次 `/chat` 请求为什么慢：OpenTelemetry trace

## 10. 生产环境如何设置告警？

常见告警：

- 5xx 错误率超过阈值
- P95/P99 延迟超过阈值
- 服务实例不可用
- 队列长度持续增长
- LLM 调用失败率升高

告警要避免太敏感，否则容易报警疲劳。

## 11. 本节可以怎么写到简历里？

可以这样表达：

```text
为 FastAPI AI 服务接入 Prometheus 指标监控，
通过 middleware 统计 HTTP 请求量、状态码、错误数和耗时分布，

```
