# 第5周 Section_5 学习资料：Prometheus 在开发里到底有什么用

## 1. 先说人话

Prometheus 是用来回答这些问题的：

```text
我的服务现在还健康吗？
接口是不是变慢了？
错误是不是突然变多了？
某个业务动作今天发生了多少次？
模型调用耗时是不是越来越高？
```

它不是让业务功能变强的工具，而是让你上线后不再“裸奔”的工具。

如果没有 Prometheus，你可能只能靠用户说“系统好像卡了”才知道出事。  
有了 Prometheus，你可以提前看到：

```text
/chat 接口 5xx 错误上升
LLM 调用耗时变高
队列堆积越来越多
用户请求量突然增加
```

## 2. 作为开发，什么时候会用到它

### 场景1：接口上线后怕它挂

你写了一个 FastAPI 服务，上线后最基本要看：

- 请求量有多少
- 错误率多少
- 延迟有没有变高

这时候用 Prometheus 暴露 `/metrics`，让它定时来抓。

### 场景2：老板或产品问“今天用了多少次”

比如 AI 面试系统里：

- 生成了多少份面试题
- 完成了多少次 AI 面试
- 生成了多少份报告

这些都可以用 Counter 记录。

### 场景3：RAG 或 Agent 服务突然变慢

你可以分别统计：

- 检索耗时
- 重排耗时
- LLM 调用耗时
- 整体接口耗时

不用拍脑袋猜，而是看指标。

### 场景4：异步任务积压

如果后面用 Celery/RabbitMQ，可以用 Gauge 记录：

- 当前队列长度
- 当前运行中的任务数
- 当前失败任务数

队列越来越长，就说明消费能力不够。

## 3. 三个 demo 分别对应什么开发能力

### demo1：看懂指标长什么样

`demo1_metrics_plain_text.py` 让你知道 `/metrics` 返回的其实就是文本。

重点不是手写指标，而是看懂：

```text
# HELP app_request_total Total number of handled requests.
# TYPE app_request_total counter
app_request_total 5
```

以后你看到这类输出，就知道 Prometheus 抓的是什么。

### demo2：FastAPI 接口自动统计

`demo2_fastapi_metrics_middleware.py` 更接近真实开发。

它做的事情是：

```text
每个请求进来
  -> middleware 开始计时
  -> 接口处理
  -> middleware 记录状态码和耗时
  -> /metrics 暴露给 Prometheus
```

这个能力很常用。你做 FastAPI 后端时，几乎所有服务都需要类似监控。

### demo3：真实 prometheus-client 写法

`demo3_prometheus_client_real.py` 使用真实 `prometheus-client` 包。

它就是你后面项目里更推荐使用的方式。因为标准库会帮你处理很多细节，比如：

- Counter 的累计值
- Histogram 的分桶
- `_count`、`_sum`、`+Inf` 这些标准输出

## 4. 三种指标怎么选

```text
Counter：累计次数
Gauge：当前状态
Histogram：耗时分布
```

开发时可以这么用：

| 你想知道什么 | 用什么 |
|--------------|--------|
| 请求总数 | Counter |
| 登录失败次数 | Counter |
| 当前在线人数 | Gauge |
| 队列当前长度 | Gauge |
| 接口耗时 | Histogram |
| LLM 调用耗时 | Histogram |

## 5. 你在项目里可以怎么落地

如果做 AI Agent 服务，我建议至少加这些指标：

```text
http_requests_total
http_request_duration_seconds
agent_tool_calls_total
agent_errors_total
rag_retrieval_duration_seconds
llm_request_duration_seconds
llm_tokens_total
```

这样以后排查问题会很舒服：

- 用户说慢：看耗时指标
- 用户说报错：看错误指标
- 成本升高：看 token 指标
- Agent 不稳定：看工具调用失败次数

## 6. 这一节你真正要带走什么

你不需要背 Prometheus 底层模型。

你只要记住：

```text
服务上线后，我需要用指标知道它是否健康。
Prometheus 负责定时抓 /metrics。
Counter 记次数，Gauge 记当前值，Histogram 记耗时。
Grafana 下一节负责把这些指标画成图。
```
