# 03 文本分块与检索服务

## 1. TextChunker

`TextChunker` 默认使用 `chunk_size=500`、`chunk_overlap=50`。切分步长为：

```text
step = chunk_size - chunk_overlap
```

重叠区域用于降低边界截断造成的信息损失。每个结果包含 `content` 和 `chunk_index`，空白输入返回空列表，非法参数立即抛出 `ValueError`。

当前策略按字符窗口切分，适合阶段三教学和接口验证。企业文档落地时，应根据 Markdown 标题、段落、表格和代码块增加结构化切分，并保留文档版本和页码元数据。

## 2. Retriever

`Retriever.index_chunks()` 接收 `(id, text, metadata)`，批量生成向量后写入存储。`Retriever.search()` 接收查询文本，生成查询向量并返回 `RetrievedChunk`。

```text
index_chunks
  ├── 提取文本
  ├── 批量 Embedding
  ├── 组装 VectorRecord
  └── upsert

search
  ├── 校验非空查询
  ├── 查询 Embedding
  ├── vector_store.search
  └── 转换 RetrievedChunk
```

## 3. 元数据约定

阶段四至少应携带：`document_id`、`chunk_index`、`source` 和 `title`。阶段五可增加 `tenant_id`、`document_version` 和权限标签，并在向量库检索时执行服务端过滤，不能只在返回后过滤。

## 4. 当前限制

本阶段没有 HTTP 入库接口，因此不会绕过认证直接暴露知识库写入能力。后续需要在 API 层增加管理员权限、文件类型和大小校验、病毒扫描、异步解析任务以及失败重试。
