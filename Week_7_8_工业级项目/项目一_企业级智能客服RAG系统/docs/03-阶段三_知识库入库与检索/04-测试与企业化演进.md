# 04 测试与企业化演进

## 1. 测试范围

`tests/test_rag.py` 覆盖：

- Embedding 确定性、维度、归一化和批量顺序。
- Chunker 空文本、重叠切分和非法参数。
- Vector Store 相似度排序、幂等覆盖和维度校验。
- Retriever 入库、查询、元数据返回和空查询拒绝。

## 2. 验证命令

```powershell
python -m pytest tests/test_rag.py -v
python -m pytest tests/ -v
```

测试必须从项目根目录执行。Windows 环境如果直接执行 `pytest` 导致 `ModuleNotFoundError: app`，优先使用 `python -m pytest`，确保当前项目根目录在模块搜索路径中。

## 3. 阶段四衔接

阶段四将把 `Retriever.search()` 包装为知识库搜索 Tool，并由 LangGraph 条件路由决定是否检索、是否查询订单或转人工。阶段四不得在节点中复制 Embedding 和 Vector Store 逻辑。

## 4. 企业化演进清单

1. 用 Protocol 定义 `EmbeddingProvider` 和 `VectorStore`，增加依赖注入配置。
2. 实现 Milvus 持久化适配器，补充 collection 与索引生命周期管理。
3. 将文档和 Chunk 的数据库记录与向量记录绑定，支持版本化和幂等重建。
4. 增加召回质量评估集，记录 Recall@K、MRR、命中率和空召回率。
5. 增加超时、重试、熔断和降级，禁止向量库不可用时阻塞客服主链路。
6. 在阶段五接入 Redis 缓存和 Prometheus 指标，在阶段六完成 Docker Compose 编排。
