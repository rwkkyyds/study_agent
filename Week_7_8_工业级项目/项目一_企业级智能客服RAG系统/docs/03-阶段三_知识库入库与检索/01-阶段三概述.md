# 01 阶段三概述

## 1. 目标与非目标

阶段三实现知识库检索的最小生产架构：文本经过分块后生成向量，写入向量存储，再通过查询向量执行 Top-K 相似度检索。

本阶段不实现真实文件上传、Milvus 网络连接、LLM 生成和客服对话路由。这些能力分别属于后续基础设施接入或阶段四工作流。

## 2. 分层架构

```text
业务入口 / 阶段四 Agent Tool
          │
          ▼
Retriever 应用服务
          │
    ┌─────┴─────┐
    ▼           ▼
Embedding    VectorStore
 Provider     Adapter
    │           │
MockEmbedding InMemoryVectorStore
```

`Retriever` 只依赖两个抽象职责：把文本转换为向量，以及保存和搜索向量。因此真实 Embedding Provider 或 Milvus 可以在基础设施层替换，不影响上层工作流。

## 3. 核心链路

```text
原始文档
  │
  ▼
TextChunker.split_text
  │
  ▼
TextChunk.content + chunk_index
  │
  ▼
MockEmbedding.embed_documents
  │
  ▼
VectorRecord
  │
  ▼
VectorStore.upsert

用户查询
  │
  ▼
MockEmbedding.embed_query
  │
  ▼
VectorStore.search
  │
  ▼
RetrievedChunk
```

## 4. 设计原则

- 确定性：同一文本在相同维度下生成相同向量，便于测试和复现。
- 快速失败：维度、窗口和查询参数错误在边界处抛出明确异常。
- 可替换：检索服务不绑定具体向量数据库和外部模型。
- 可观测预留：`RetrievedChunk` 保留 `score` 和 `metadata`，后续可记录召回质量与来源。
- 安全边界：当前模块不记录原文到日志，不读取密钥，也不接受任意文件路径。
