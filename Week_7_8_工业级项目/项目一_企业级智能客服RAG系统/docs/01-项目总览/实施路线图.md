# 实施路线图

## 6 个阶段概览

```text
阶段一 ──→ 阶段二 ──→ 阶段三 ──→ 阶段四 ──→ 阶段五 ──→ 阶段六
骨架搭建    认证+数据    入库+检索    客服工作流    稳定性     部署
```

## 阶段一：项目骨架（已完成）

**目标**：建立 FastAPI 应用基础框架，可启动、可测试。

**交付物**：FastAPI 应用入口、环境配置、SQLite 会话、健康检查接口和测试。

**验证方式**：`python -m pytest tests/test_health.py -v`

## 阶段二：身份认证与数据层（已完成）

**目标**：用户系统、业务数据模型和 JWT 认证。

**交付物**：User、Document、Chunk、Ticket、Message 模型，注册登录，Token 校验和角色权限。

**验证方式**：`python -m pytest tests/test_auth.py -v`

## 阶段三：知识库入库与检索（已完成）

**目标**：建立可替换的检索内核，为客服 Agent 提供知识库搜索能力。

**交付物**：

- MockEmbedding（SHA-256 稳定生成 768 维向量，无需 API Key）
- InMemoryVectorStore（余弦相似度搜索、维度校验、幂等覆盖）
- TextChunker（固定大小、重叠切分）
- Retriever（查询向量化、Top-K 搜索、领域结果封装）
- 阶段三开发文档和 11 个测试用例

**验证方式**：`python -m pytest tests/test_rag.py -v` 与全量测试。

## 阶段四：客服 LangGraph 工作流（已完成）

**目标**：使用 LangGraph 编排客服 Agent 的意图分类、条件路由和领域工具。

**交付物**：IntentClassifier、知识库搜索 Tool、订单查询 Tool、转人工 Tool、StateGraph、JWT 保护的 `POST /chat`、阶段四开发文档和 8 个测试用例。

**验证方式**：`python -m pytest tests/test_workflow.py tests/test_chat.py -v` 与全量测试。

阶段五：企业级稳定性（已完成）

**目标**：在客服接口前增加稳定性边界，支持 Redis 共享限流与会话记忆，并提供重试、熔断和 Prometheus 指标。

**交付物**：`app/stability/` 稳定性组件、`POST /chat` 限流与会话记录、`GET /metrics` 指标接口、阶段五文档和稳定性测试。

**验证方式**：`python -m pytest tests/ -v`

## 阶段六：容器化与部署（已完成）

**目标**：Docker Compose 编排 PostgreSQL、Redis 和应用，完善部署文档和项目总结。

**交付物**：

- 多阶段 `Dockerfile`（依赖安装阶段 + 运行时阶段，最小化镜像体积）
- `.dockerignore`（排除本地文件，优化构建上下文）
- `docker-compose.yml`（编排 App + PostgreSQL + Redis，Milvus 可选）
- 部署文档（环境准备、构建、启动、监控、备份、回滚、安全注意事项）
- 项目总结文档（6 个阶段技术演进回顾、核心决策、后续规划）

**验证方式**：`docker compose up --build -d` 后所有服务正常启动，健康检查通过。
