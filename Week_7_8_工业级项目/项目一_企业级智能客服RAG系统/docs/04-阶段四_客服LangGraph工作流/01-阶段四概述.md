# 01 阶段四概述

## 1. 目标

阶段四把“检索能力”升级为“可路由的客服工作流”。系统收到问题后，不直接把所有请求交给同一个处理器，而是先识别意图，再选择最小必要工具。

## 2. 核心链路

```text
POST /chat
    │
    ▼
JWT get_current_user
    │
    ▼
CustomerServiceWorkflow
    │
    ▼
classify_intent
    │
    ├── knowledge → knowledge_search → RetrievedChunk
    ├── order     → order_lookup     → OrderResult
    └── human     → transfer_to_human → Ticket + Message
```

## 3. 分层职责

- API 层：校验请求、注入用户和工作流、转换响应。
- Schema 层：限制问题长度和响应字段形状。
- Workflow 层：管理状态图、节点和条件路由。
- Tools 层：封装检索、订单适配和工单写入。
- RAG 层：负责阶段三的向量检索，不被工作流复制。
- Model 层：负责阶段二的工单和消息持久化。

## 4. 企业级原则

工作流只负责编排，不直接拼接 SQL；工具只负责单一领域动作；API 不直接调用向量库；所有入口先完成身份认证。后续替换 LLM 分类器、真实订单服务或 Milvus 时，不改变 Chat API 契约。
