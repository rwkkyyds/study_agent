# 阶段二：身份认证与数据层

> 在阶段一项目骨架上，加入用户、知识库文档、客服工单的数据模型，以及 JWT 登录认证和角色权限校验。

## 阶段目标

- 理解 SQLAlchemy 2.0 声明式模型
- 建立 User、Document、Chunk、Ticket、Message 五个业务实体
- 理解密码哈希与明文密码验证
- 理解 JWT 的签发、解析、过期校验
- 使用 FastAPI 依赖注入保护需要登录的接口
- 使用角色依赖实现 `admin`、`agent`、`customer` 权限边界
- 为后续 RAG 入库和客服工作流预留数据基础

## 本阶段交付物

| 类型 | 文件 | 作用 |
|------|------|------|
| 模型 | `app/models/user.py` | 用户、角色、账号状态和审计时间 |
| 模型 | `app/models/document.py` | 知识库文档及其切分块 |
| 模型 | `app/models/ticket.py` | 客服工单和工单消息 |
| Schema | `app/schemas/auth.py` | 注册、登录、Token、用户响应结构 |
| 服务 | `app/services/auth.py` | 密码、用户、JWT、角色权限业务逻辑 |
| API | `app/api/auth.py` | 注册、登录、当前用户接口 |
| 测试 | `tests/test_auth.py` | 8 个认证场景 |

## 接口清单

| 方法 | 路径 | 是否需要登录 | 说明 |
|------|------|--------------|------|
| `POST` | `/auth/register` | 否 | 注册用户 |
| `POST` | `/auth/login` | 否 | 登录并获取 JWT |
| `GET` | `/auth/me` | 是 | 获取当前用户 |

## 完成标准

- 用户注册成功返回 `201`
- 重复用户名返回 `400`
- 正确账号密码登录返回 Bearer Token
- 错误密码或不存在用户返回 `401`
- 有效 Token 可以访问 `/auth/me`
- 无效或缺失 Token 不能访问受保护接口
- `python -m pytest tests/ -v` → `10 passed`
