# 03 - 知识库与工单模型

对应文件：

- `app/models/document.py`
- `app/models/ticket.py`

## 一、Document：知识库文档

`Document` 映射 `documents` 表，保存一篇完整的企业知识文档。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | `int` | 文档主键 |
| `title` | `str` | 文档标题 |
| `content` | `Text` | 原始文本内容 |
| `source` | `str` | 来源，默认 `manual` |
| `doc_metadata` | `JSON` | 可选扩展元数据 |
| `created_at` | `datetime` | 创建时间 |
| `updated_at` | `datetime` | 更新时间 |

一个文档可以拥有多个 `Chunk`：

```text
Document 1 ──< Chunk 1
              Chunk 2
              Chunk 3
```

## 二、Chunk：文档切分块

`Chunk` 映射 `chunks` 表，是后续向量检索的最小文本单元。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | `int` | 分块主键 |
| `document_id` | `int` | 外键，指向 `documents.id` |
| `content` | `Text` | 当前分块文本 |
| `chunk_index` | `int` | 在原文中的顺序 |
| `created_at` | `datetime` | 创建时间 |

`ForeignKey("documents.id", ondelete="CASCADE")` 表示删除文档时可以级联删除分块；`relationship(..., cascade="all, delete-orphan")` 则让 ORM 层同步维护这个关系。

当前阶段只定义表，不执行文档上传、切分和向量化，这些属于阶段三。

## 三、Ticket：客服工单

`Ticket` 映射 `tickets` 表，表示一次需要跟进的客服问题。

| 字段 | 类型 | 默认/约束 | 说明 |
|------|------|-----------|------|
| `id` | `int` | 主键、自增 | 工单编号 |
| `title` | `str` | 非空 | 工单标题 |
| `description` | `Text` | 非空 | 问题描述 |
| `status` | `str` | `open` | `open/assigned/resolved/closed` |
| `priority` | `str` | `normal` | `low/normal/high/urgent` |
| `customer_id` | `int` | 外键 | 提交工单的用户 |
| `agent_id` | `int?` | 可空外键 | 分配的客服，可为空 |
| `created_at` | `datetime` | 数据库默认 | 创建时间 |
| `updated_at` | `datetime` | 更新时刷新 | 修改时间 |

## 四、Message：工单消息

`Message` 映射 `messages` 表，记录工单中的对话内容。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | `int` | 消息主键 |
| `ticket_id` | `int` | 所属工单 |
| `sender_id` | `int` | 发送者用户 id |
| `sender_role` | `str` | 发送者角色 |
| `content` | `Text` | 消息正文 |
| `msg_type` | `str` | `text/image/system`，默认 `text` |
| `created_at` | `datetime` | 创建时间 |

## 五、关系总图

```text
User
 ├── customer_id ──< Ticket
 ├── agent_id ─────< Ticket
 └── sender_id ────< Message

Document ──< Chunk
Ticket ────< Message
```

## 六、当前阶段边界

这些模型是后续阶段的数据基础，但当前没有新增对应 CRUD API。不要因为模型已经存在，就认为文档上传、工单创建和消息发送已经完成。
