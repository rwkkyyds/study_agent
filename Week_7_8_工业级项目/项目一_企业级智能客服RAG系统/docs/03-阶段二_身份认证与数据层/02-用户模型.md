# 02 - 用户模型（User）

> 对应文件：`app/models/user.py`

## 一、模型定义

`User` 映射数据库表 `users`，表示系统账号。

| 字段 | 类型 | 约束 | 用途 |
|------|------|------|------|
| `id` | `int` | 主键、自增 | 用户唯一标识 |
| `username` | `str` | 非空、唯一、索引 | 登录用户名 |
| `hashed_password` | `str` | 非空 | 密码哈希，绝不存明文 |
| `role` | `str` | 非空，默认 `customer` | `admin/agent/customer` |
| `is_active` | `bool` | 非空，默认 `True` | 账号是否允许登录 |
| `created_at` | `datetime` | 非空、数据库默认当前时间 | 创建时间 |
| `updated_at` | `datetime` | 非空、更新时刷新 | 修改时间 |

## 二、三个角色

| 角色 | 含义 | 当前阶段定位 |
|------|------|--------------|
| `admin` | 管理员 | 可通过角色校验访问所有角色范围 |
| `agent` | 客服人员 | 处理客服业务 |
| `customer` | 普通用户 | 发起咨询和工单 |

角色目前保存为字符串，注册 Schema 通过正则限制为三个合法值：

```text
^(admin|agent|customer)$
```

## 三、为什么返回用户时没有密码

`UserResponse` 只包含：`id`、`username`、`role`、`is_active`、`created_at`。虽然 ORM 对象有 `hashed_password`，但 FastAPI 的 `response_model` 会按照响应 Schema 过滤字段，避免密码哈希泄露。

## 四、注意事项

- `username` 唯一约束和 service 层重复检查共同保证用户名不重复。
- `is_active=False` 的用户即使拥有旧 Token，也会在 `get_current_user()` 中被拒绝。
- `created_at` 和 `updated_at` 使用数据库函数 `func.now()`，不是由客户端传入。
- `__repr__()` 只打印 id、用户名和角色，不打印密码哈希。

## 五、阅读代码时的顺序

1. 看 `__tablename__`，知道表名。
2. 看每个 `mapped_column()`，理解字段约束。
3. 看 `role` 和 `is_active`，理解认证与授权的基础。
4. 对照 `app/schemas/auth.py` 的 `UserResponse`，找出哪些字段允许返回给客户端。
