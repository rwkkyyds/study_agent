# 04 — 部署环境与运维

> 容器化之后的部署、监控、日志、备份和常见运维操作。

## 一、部署前准备

### 1. 环境要求

| 资源 | 最低要求 | 推荐 |
|------|----------|------|
| CPU | 1 核 | 2 核 |
| 内存 | 2 GB | 4 GB |
| 磁盘 | 10 GB | 20 GB |
| Docker | 24+ | 最新 |
| Docker Compose | 2.20+ | 最新 |

### 2. 安装 Docker

```powershell
# Windows 和 macOS：安装 Docker Desktop
# 下载地址：https://www.docker.com/products/docker-desktop

# Ubuntu / Debian
sudo apt-get update
sudo apt-get install -y docker.io docker-compose-v2

# CentOS / RHEL
sudo yum install -y docker
sudo systemctl enable docker
sudo systemctl start docker
```

### 3. 克隆项目

```bash
git clone https://github.com/rwkkyyds/study_agent.git
cd "Week_7_8_工业级项目/项目一_企业级智能客服RAG系统"
```

## 二、首次部署

```powershell
# 1. 创建 .env 文件，设置 JWT_SECRET_KEY
# 建议使用以下命令生成密钥：
#   python -c "import secrets; print(secrets.token_urlsafe(32))"

# 2. 构建并启动
docker compose up --build -d

# 3. 查看启动日志
docker compose logs -f app

# 4. 验证健康检查
curl http://localhost:8000/health

# 5. 验证 API 文档
curl http://localhost:8000/docs

# 6. 验证指标接口
curl http://localhost:8000/metrics
```

## 三、环境变量配置

以下是生产环境需要配置的关键变量：

| 变量 | 说明 | 默认值 |
|------|------|--------|
| `JWT_SECRET_KEY` | JWT 签名密钥，至少 32 字节 | 必须设置 |
| `DATABASE_URL` | 数据库连接字符串 | `postgresql://...` |
| `REDIS_URL` | Redis 连接地址 | `redis://redis:6379/0` |
| `RATE_LIMIT_REQUESTS` | 每个用户每分钟最大请求数 | `60` |
| `RATE_LIMIT_WINDOW_SECONDS` | 限流窗口 | `60` |
| `SESSION_TTL_SECONDS` | 会话过期时间 | `3600` |
| `SESSION_MAX_MESSAGES` | 会话最大消息数 | `20` |
| `LOG_LEVEL` | 日志级别 | `INFO` |

## 四、日志与监控

### 1. 查看日志

```powershell
# 实时查看应用日志
docker compose logs -f app

# 查看最近 100 行
docker compose logs --tail=100 app

# 按时间过滤
docker compose logs --since=10m app
```

### 2. 指标监控

应用暴露 `GET /metrics` 接口，返回 Prometheus 文本格式：

```text
# HELP customer_service_requests_total 进入客服处理的请求总数
# TYPE customer_service_requests_total counter
customer_service_requests_total 42

# HELP customer_service_rate_limited_total 被限流的请求总数
# TYPE customer_service_rate_limited_total counter
customer_service_rate_limited_total 3

# HELP customer_service_http_responses_total 按状态码统计响应数量
# TYPE customer_service_http_responses_total counter
customer_service_http_responses_total{status_code="200"} 39
customer_service_http_responses_total{status_code="429"} 3

# HELP customer_service_intents_total 按意图统计数量
# TYPE customer_service_intents_total counter
customer_service_intents_total{intent="knowledge"} 25
customer_service_intents_total{intent="order"} 10
customer_service_intents_total{intent="human"} 4
```

### 3. Prometheus + Grafana 集成

在 `prometheus.yml` 中添加抓取目标：

```yaml
scrape_configs:
  - job_name: 'rag-app'
    static_configs:
      - targets: ['app:8000']
```

## 五、数据备份

### 1. PostgreSQL 备份

```powershell
# 备份数据库
docker exec rag-postgres pg_dump -U rag_user rag_db > backup_$(date +%Y%m%d).sql

# 恢复数据库
cat backup_20250101.sql | docker exec -i rag-postgres psql -U rag_user rag_db
```

### 2. 定期备份建议

```bash
# 在 cron 中添加每日备份
0 3 * * * cd /opt/rag && docker exec rag-postgres pg_dump -U rag_user rag_db > backups/rag_$(date +\%Y\%m\%d).sql && find backups/ -name "rag_*.sql" -mtime +30 -delete
```

## 七、常见运维操作

### 健康检查

```powershell
# 应用健康检查
curl http://localhost:8000/health

# PostgreSQL 健康检查
docker exec rag-postgres pg_isready -U rag_user -d rag_db

# Redis 健康检查
docker exec rag-redis redis-cli ping
```

### 查看资源使用

```powershell
# 查看所有容器资源使用
docker stats

# 查看单个服务日志
docker compose logs --tail=50 app
```

### 清理

```powershell
# 清理未使用的镜像和容器
docker system prune -f

# 清理所有数据卷（谨慎使用）
docker compose down -v
```

## 八、安全注意事项

- **JWT_SECRET_KEY 绝对不能硬编码到代码或提交到仓库**。
- PostgreSQL 使用强密码，并通过 `.env` 文件注入。
- 应用默认不暴露管理端口，生产环境建议使用 Nginx 反向代理。
- `/metrics` 接口只对监控网络开放，不直接暴露给公网。
- 定期更新 Docker 镜像，修复安全漏洞。
- 限制容器 CPU 和内存使用，防止资源耗尽。
- 启用 Docker 内容信任（Docker Content Trust）确保镜像完整性。
