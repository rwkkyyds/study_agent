# 阶段六：容器化与部署概述

> 将前五个阶段的应用打包为 Docker 镜像，使用 Docker Compose 编排应用、数据库、缓存和向量库，完成从"本地可运行"到"容器化可部署"的转变。

## 一、为什么阶段五之后做容器化

阶段五已经让系统具备了限流、熔断、降级和指标监控能力。但此时系统仍然依赖本地开发环境：

- 数据库使用 SQLite，重启后数据丢失。
- 限流和会话记忆只在单进程内共享。
- 没有统一的依赖声明和启动流程。
- 部署到新的环境需要手动安装 Python、依赖和配置。

阶段六解决这些问题，把整个系统封装为 Docker 容器，让开发、测试和生产环境保持一致。

## 二、本阶段目标

1. **多阶段构建优化镜像**：分离依赖安装和运行时，最终镜像只包含运行所需的最小文件。
2. **Docker Compose 编排依赖**：应用、PostgreSQL、Redis 一键启动，互不干扰。
3. **生产级数据库配置**：使用 PostgreSQL 替换 SQLite，支持持久化存储。
4. **共享状态外置**：Redis 作为共享限流和会话记忆的后端，多实例部署时状态一致。
5. **Milvus 可选接入**：向量数据库作为可选依赖，按需启用，不增加基础部署负担。
6. **健康检查与自动重启**：每个服务都配置健康检查，异常时自动恢复。
7. **完善部署文档**：覆盖环境准备、构建、启动、监控和运维。

## 三、本阶段架构

```text
                          ┌──────────────┐
                          │  Nginx 反向代理  │  （可选，生产推荐）
                          │  443 → 80      │
                          └──────┬───────┘
                                 │
                          ┌──────▼───────┐
                          │  FastAPI 应用  │
                          │  :8000        │
                          └──┬──────┬────┘
                             │      │
                    ┌────────▼──┐ ┌─▼──────────┐
                    │ PostgreSQL │ │  Redis      │
                    │  :5432     │ │  :6379       │
                    │  持久化    │ │  共享状态    │
                    │  数据      │ │  限流+会话   │
                    └────────────┘ └─────────────┘

                    ┌──────────────────────────────┐
                    │  Milvus（可选）               │
                    │  :19530                       │
                    │  etcd + MinIO + 向量库         │
                    └──────────────────────────────┘
```

## 四、与阶段五的区别

| 方面 | 阶段五（本地开发） | 阶段六（容器化部署） |
|------|-------------------|---------------------|
| 数据库 | SQLite 文件 | PostgreSQL 持久卷 |
| 缓存 | 进程内回退 | Redis 共享 |
| 向量库 | InMemory | InMemory（可选 Milvus） |
| 启动方式 | `uvicorn app.main:app` | `docker compose up` |
| 环境隔离 | 依赖本地 Python | 容器内完全隔离 |
| 多实例 | 不支持 | 支持（通过 Redis 共享） |
| 部署流程 | 手动安装 | 一键构建+启动 |

## 七、完成标准

- 执行 `docker compose up --build -d` 后所有服务正常启动。
- `GET /health` 返回 `{"status": "ok"}`。
- `GET /docs` 可访问 Swagger 文档。
- 服务日志中可以看到 PostgreSQL 和 Redis 连接成功。
- 容器重启后数据不丢失（PostgreSQL 持久卷）。
- 停止容器后 `docker compose down -v` 可以清理所有资源。
- 阶段一到阶段五的测试在容器构建时同步验证。
