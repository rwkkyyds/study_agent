# 03 - 测试与运行

> 本文对应 `tests/test_stability.py`，用于验证阶段五稳定性组件，并进行全量回归。

## 一、测试前准备

阶段五的默认配置不要求 Redis。只要项目虚拟环境已经安装依赖，就可以运行本地测试：

```powershell
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

检查应用是否可以导入：

```powershell
.venv\Scripts\python.exe -c "import app.main; print('app import ok')"
```

如果需要测试 Redis 分支，再启动本地 Redis，并在当前终端配置：

```powershell
$env:REDIS_URL="redis://localhost:6379/0"
```

Redis 分支不是默认单元测试的前置条件，因为测试必须在没有外部服务时也能重复执行。

## 二、专项测试内容

运行阶段五专项测试：

```powershell
.venv\Scripts\python.exe -m pytest tests/test_stability.py -v -s
```

### 1. 限流测试

`test_rate_limiter_rejects_after_limit` 使用 `limit=2`：

```text
同一用户第 1 次 → 允许
同一用户第 2 次 → 允许
同一用户第 3 次 → 拒绝
另一个用户第 1 次 → 允许
```

它同时验证了限制数量和用户隔离。如果实现错误地使用全局计数，另一个用户的请求也会被拒绝。

### 2. 会话记忆测试

`test_session_memory_keeps_recent_messages` 将最大消息数设置为 2，再追加 3 条消息，确认只保留最后两条。这防止会话无限增长。

`test_session_memory_rejects_blank_content` 确认空白消息不会污染会话历史。

### 3. 指标测试

`test_metrics_render_prometheus_text` 写入 200 和 429 两种请求，检查输出中包含请求总数、限流总数和意图标签。测试关注指标契约，不依赖 Prometheus Server。

### 4. 重试测试

`test_call_with_retry_retries_then_succeeds` 使用一个前两次失败、第三次成功的模拟函数，确认 `retries=2` 会执行三次并最终返回结果。

### 5. 熔断测试

`test_circuit_breaker_opens_after_failures` 将失败阈值设为 2，连续失败两次后，第三次调用应直接抛出 `CircuitOpenError`，不会执行真实 operation。

## 三、全量回归测试

阶段五不能破坏前四阶段，因此还要执行：

```powershell
.venv\Scripts\python.exe -m pytest tests/ -v -s
```

通过标准：

- 阶段一健康检查和版本接口通过。
- 阶段二注册、登录、JWT 和角色测试通过。
- 阶段三 Embedding、分块、向量存储和 Retriever 测试通过。
- 阶段四工作流、Chat API 和 JWT 保护测试通过。
- 阶段五稳定性专项测试全部通过。

## 四、接口运行验证

启动服务：

```powershell
.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000
```

### 1. 健康检查

```powershell
curl.exe http://127.0.0.1:8000/health
```

### 2. 指标接口

```powershell
curl.exe http://127.0.0.1:8000/metrics
```

初始状态至少应看到以下指标名称：

```text
customer_service_requests_total
customer_service_rate_limited_total
customer_service_http_responses_total
customer_service_intents_total
```

### 3. Chat 限流验证

使用有效 JWT 访问 `/chat`。当配置很小的 `RATE_LIMIT_REQUESTS` 后，在窗口内连续请求，超出阈值应返回：

```text
HTTP 429
Retry-After: <window_seconds>
```

限流身份来自 JWT 的 `current_user.id`，不是请求体中的字段。

## 五、生产运行检查清单

- `JWT_SECRET_KEY` 使用至少 32 字节随机值，不能继续使用默认值。
- `REDIS_URL` 指向可用的 Redis，并完成 `PING` 验证。
- 多实例部署时确认所有实例使用同一 Redis 数据库和 key 前缀。
- 检查 Redis key 的 TTL，避免会话永久占用内存。
- 为真实 HTTP、数据库、LLM 和向量库客户端配置连接超时与读取超时。
- 将 `/metrics` 限制在监控网络，避免公开暴露内部运行信息。
- 观察 429 比例、请求错误率、熔断次数和外部依赖延迟。
- 如果 Redis 不可用，确认进程内回退只作为短期降级，并及时恢复共享状态。

## 六、常见问题

### 运行测试提示找不到 `fastapi` 或 `pytest`

通常是终端使用了系统 Python，而不是项目虚拟环境。统一使用：

```powershell
.venv\Scripts\python.exe -m pytest tests/ -v
```

### 没有 Redis 还能运行吗

可以。默认使用进程内限流和会话记忆；但多进程或多实例场景下不具备共享一致性。

### 为什么没有直接安装 `redis` 依赖

当前实现将 Redis 客户端作为可选能力，避免教学阶段和单元测试强依赖外部服务。配置 `REDIS_URL` 并安装 `redis` 包后，工厂会自动尝试连接。
