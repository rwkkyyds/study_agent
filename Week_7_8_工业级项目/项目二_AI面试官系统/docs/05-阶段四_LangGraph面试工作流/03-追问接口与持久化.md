# 03 - 追问接口与持久化

> 相关路径：`app/api/interviews.py`、`app/services/interviews.py`、`app/models/interview.py`、`alembic/versions/202608190001_add_interview_follow_ups.py`

## 新增接口

文件路径：`app/api/interviews.py`

接口：`POST /interviews/follow-up`

这个接口用于根据候选人对某一道题的回答生成追问。

路由层负责：

- 接收 `InterviewFollowUpRequest`
- 注入当前登录用户
- 注入数据库 Session
- 调用 `InterviewPersistenceService.generate_follow_up`
- 将找不到会话的情况转换成 404
- 将输入问题转换成 422

## 请求模型

文件路径：`app/schemas/interview.py`

模型：`InterviewFollowUpRequest`

字段：

- `session_id`：当前面试会话 ID
- `question_id`：要追问的原题 ID
- `answer`：候选人对该题的回答

## 响应模型

文件路径：`app/schemas/interview.py`

模型：`InterviewFollowUpResponse`

字段：

- `session_id`
- `question_id`
- `follow_up_questions`
- `reason`
- `workflow_trace`

`workflow_trace` 是阶段四特意加的学习字段，用来观察一次请求经过了哪些节点。

## service 层

文件路径：`app/services/interviews.py`

方法：`generate_follow_up`

职责：

1. 根据 `session_id` 和当前用户 ID 查询面试会话
2. 如果会话不存在，返回 None
3. 调用 `InterviewWorkflow.generate_follow_up`
4. 保存追问快照
5. 更新会话状态为 `follow_up_generated`
6. 返回追问响应

这里的关键点是会话查询条件必须带上当前用户 ID，否则会出现越权风险。

## ORM 模型

文件路径：`app/models/interview.py`

模型：`InterviewFollowUp`

保存字段：

- 面试会话数据库 ID
- 原题 ID
- 候选人回答
- 追问列表
- 追问原因
- 工作流 trace
- 创建时间

面试会话 `InterviewSession` 通过 `follow_ups` 关系关联多条追问记录。

## 数据库迁移

文件路径：`alembic/versions/202608190001_add_interview_follow_ups.py`

迁移创建 `interview_follow_ups` 表，并通过 `session_db_id` 外键关联 `interview_sessions.id`。

这样一次面试可以保存多次追问记录，为后续多轮面试和面试房间页面做准备。

## 学习重点

- 多轮追问是“回答之后的下一步工作流”，不是题目生成的一部分
- 追问必须绑定面试会话，否则无法复盘上下文
- service 层要先做用户归属校验，再调用工作流
- 保存 `workflow_trace` 可以让后续调试和教学更透明
