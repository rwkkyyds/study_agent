# 项目二总览：AI 面试官系统

## 业务背景

求职者准备 AI 应用开发岗位时，常见问题不是没有项目，而是：

- 简历项目很多，但讲不清业务价值
- 面试官追问技术细节时容易断层
- 不知道自己的回答是否有结构、有证据、有生产化意识
- 缺少针对岗位的模拟面试和复盘报告

本项目要做一个 AI 面试官系统，帮助候选人围绕目标岗位进行模拟面试，并输出评分报告和改进建议。

## 核心业务闭环

1. 简历输入：候选人上传或粘贴简历
2. 岗位输入：选择目标岗位、难度、题目数量
3. 题目生成：系统根据简历和岗位生成结构化面试题
4. 面试作答：候选人逐题回答，后续支持 SSE 流式追问
5. 评分报告：系统按技术匹配度、表达结构、项目理解、风险意识评分
6. 改进建议：输出追问题、学习建议、简历表达优化方向

## 项目价值

- 对学习者：把项目经验转化成可面试表达
- 对面试官：模拟真实技术追问链路
- 对简历项目：反向发现项目业务逻辑和生产化短板

## 技术关键词

- FastAPI
- Pydantic
- LangGraph
- RAG
- 简历解析
- 题目生成
- 评分 Agent
- SSE 流式面试
- 通义千问增强
- JWT 认证
- PostgreSQL
- Redis
- Docker Compose


## 文档学习路径

建议按阶段阅读，而不是直接跳进代码：

1. 先读 `01-项目总览`，理解为什么要做 AI 面试官系统
2. 再读 `02-阶段一_项目骨架`，理解 FastAPI 应用、配置、Schema、工作流和测试如何搭起来
3. 然后读 `03-阶段二_数据层与认证`，理解 JWT、用户隔离、SQLAlchemy 落库和 Alembic 迁移
4. 再读 `04-阶段三_简历解析与岗位画像`，理解简历输入如何变成可复用画像
5. 再读 `05-阶段四_LangGraph面试工作流`，理解节点、状态、追问和评分报告链路
6. 再读 `06-阶段五_RAG与题库`，理解岗位题库、检索服务和 RAG 节点如何影响题目生成
7. 再读 `07-阶段六_前端与流式面试`，理解 Vue 前端工程、FastAPI 静态托管、短期 stream token、SSE 追问接口和可选通义千问增强
8. 再读项目根目录 `DOCKER_RUN.md`，理解阶段七 Docker Compose、本地 PostgreSQL 和环境变量注入方式
9. 每完成一个阶段，都回到 `实施路线图.md` 对照验收标准检查

文档写法以“关键机制解释”为主，不展开具体代码实现，目标是在做项目时同步理解工业级后端的设计取舍。
