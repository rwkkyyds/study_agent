# AI 面试官系统实施路线图

## 阶段一：项目骨架与最小业务闭环

目标：
- 创建独立项目目录
- 跑通 FastAPI 服务
- 提供健康检查
- 提供题目生成接口
- 提供评分报告接口
- 编写基础测试

验收：
- python -m pytest -q 通过
- /health 返回 ok
- /interviews/questions 能根据简历生成题目
- /interviews/evaluate 能根据回答生成评分报告

## 阶段二：数据层与认证

目标：
- 用户模型
- 面试会话模型
- 问题模型
- 回答模型
- 报告模型
- JWT 认证
- PostgreSQL + Alembic

验收：
- /auth/register、/auth/login、/auth/me 可用
- /interviews/questions 必须带 JWT，生成后保存会话和题目快照
- /interviews/evaluate 必须带 JWT，只能评估当前用户自己的会话
- 回答和评分报告保存到数据库
- Alembic 初始迁移可创建全部阶段二表
- python -m pytest -q 通过

## 阶段三：简历解析

目标：
- 支持 text/markdown/PDF
- 提取项目经历、技能栈、年限、岗位关键词
- 形成候选人画像

验收：
- /resumes/parse 可解析 text/markdown 正文并保存画像
- /resumes/upload 可接收 text/markdown/PDF 文件
- 用户只能读取自己的候选人画像
- /interviews/questions 可通过 resume_profile_id 生成题目
- 面试会话保存使用的 resume_profile_id
- Alembic 阶段三迁移可创建画像表和会话关联字段
- python -m pytest -q 通过

## 阶段四：LangGraph 面试工作流

目标：
- 简历解析节点
- 岗位画像节点
- 题目生成节点
- 候选人回答节点
- 追问节点
- 评分报告节点

验收：
- `app/workflow/interview_graph.py` 提供图式节点工作流
- `/interviews/questions` 返回题目生成节点 trace
- `/interviews/follow-up` 可生成并保存多轮追问
- `/interviews/evaluate` 返回评分报告节点 trace
- 追问记录保存到 `interview_follow_ups`
- 非本人会话不能生成追问
- 阶段四迁移可创建追问表
- `tests/test_interview_graph_workflow.py` 覆盖核心链路

## 阶段五：RAG 与题库

目标：
- 建立岗位知识库
- 支持按岗位技能点检索题目
- 简历项目和题库混合生成问题
- 支持题目难度分层

验收：
- `app/knowledge/question_bank.py` 提供本地结构化岗位题库
- `app/services/question_bank.py` 支持关键词抽取、打分排序和题目转换
- `/question-bank/search` 可按岗位、简历和难度检索题库
- `app/workflow/interview_graph.py` 新增 `rag_retrieval_node`
- `/interviews/questions` 的 workflow_trace 包含 `rag_retrieval_node`
- 面试题结果中混入题库来源题目
- `tests/test_question_bank.py` 覆盖题库 API、retriever 和工作流接入
- python -m pytest -q 通过

## 阶段六：前端与流式面试

目标：
- 新增 `frontend/` Vue 3 + Vite 企业级 HR/面试官后台源码
- 在 FastAPI 内继续挂载 `/web` 面试房间构建产物
- 支持企业后台登录、数据看板、历史会话、题目生成、作答、流式追问和报告展示
- 新增短期 stream token，解决浏览器 `EventSource` 不能设置 Authorization 请求头的问题
- 新增 `/interviews/sessions` 和 `/interviews/sessions/{session_id}` 历史查询接口
- 新增 `/interviews/follow-up/stream-token`
- 新增 `/interviews/follow-up/stream?token=...`
- 支持可选通义千问增强题目和追问，失败时回落本地规则
- 复用已有面试会话、题目、追问和报告模型，不新增迁移
- 使用 Element Plus + ECharts，不创建 Next.js，不新增数据库表

验收：
- 
pm run build` 输出企业后台 `app/web/index.html` 和 `app/web/assets/*` 可访问
- 未登录不能创建 stream token
- 当前用户只能给自己的 session 创建 stream token
- 非本人 session 创建 stream token 返回 404
- 合法 stream token 返回 `text/event-stream`
- SSE 输出包含 `trace`、`follow_up`、`done`
- 流式追问完成后写入 `interview_follow_ups`
- `InterviewSession.status` 更新为 `follow_up_generated`
- 非法、过期或用途不匹配 token 返回 401
- 未启用 Qwen 时保持确定性规则输出；启用 Qwen 时 trace 可显示增强或降级节点
- `tests/test_qwen_llm.py` 覆盖 Qwen 客户端、工作流增强和失败降级
- `tests/test_interview_streaming.py` 和 `tests/test_web_assets.py` 覆盖阶段六链路，静态资源测试适配 Vite hash 文件名
- python -m pytest -q 通过

## 阶段七：Docker 与部署硬化

目标：
- 新增多阶段 `Dockerfile`，构建 Vue 前端并由 FastAPI `/web` 托管
- 新增 `docker-compose.yml`，使用 `app + postgres` 两个服务完成本地部署
- PostgreSQL 数据使用 Docker volume 持久化
- `/health/ready` 增加数据库就绪检查
- 生产环境禁止使用默认 JWT 密钥
- 简历上传增加大小限制
- 新增 `.dockerignore`、`.env.example` 和 Docker 运行说明

验收：
- `python -m pytest -q` 通过
- `cd frontend && npm run build` 通过
- `docker compose config` 可解析
- `docker compose up --build -d` 后 `/health`、`/health/ready`、`/docs`、`/web/` 可访问
- 容器启动时自动执行 `alembic upgrade head`
- PostgreSQL 不暴露到宿主机，普通 `docker compose down` 后数据不丢
- 真实通义千问 Key 只通过环境变量注入，不进入仓库
