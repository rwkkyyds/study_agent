# 03 - 工作流接入

> 文件路径：`app/workflow/interview_graph.py`

## 用途

阶段五把题库检索作为一个独立节点接入图式工作流。

这一步很重要：RAG 不应该藏在题目生成函数内部，而应该作为清晰节点出现在 trace 中。这样后续排查问题时，可以知道题目为什么出现、来自简历信号还是题库检索。

## 新增节点

节点名称：`rag_retrieval_node`

方法名：`_rag_retrieval_node`

所在路径：`app/workflow/interview_graph.py`

执行位置：

```text
resume_parse_node -> job_profile_node -> rag_retrieval_node -> question_generation_node
```

## 节点输入

`rag_retrieval_node` 使用以下 state 字段：

- `state.job_title`
- `state.resume_text`
- `state.difficulty`
- `state.job_profile`

其中 `state.job_profile` 必须先由岗位画像节点生成，否则检索节点会拒绝执行。

## 节点输出

`rag_retrieval_node` 会写入：

- `state.retrieved_questions`
- `state.workflow_trace`

`state.retrieved_questions` 是已经转换成 `InterviewQuestion` 的题库问题，因此后面的 `question_generation_node` 不需要关心题库内部结构。

## 题目混合策略

文件路径：`app/workflow/interview_graph.py`

方法名：`_build_questions`

阶段五的题目列表由几类题混合组成：

1. 通用项目深挖题
2. 岗位画像题
3. 题库检索题
4. 系统设计题
5. 简历信号题，例如 RAG、Agent、部署
6. 自我复盘题

这样既保留了原有简历定制能力，也让岗位题库参与题目生成。

## 为什么把题库题插在前面

题库题通常更接近岗位能力要求，适合尽早进入面试。

阶段五将题库检索题放在项目深挖和岗位画像题之后，系统设计题之前。这样一次有限数量的问题中，更容易出现来自题库的专业问题。

## trace 的意义

`workflow_trace` 会从阶段四的：

```text
resume_parse_node -> job_profile_node -> question_generation_node
```

升级为阶段五的：

```text
resume_parse_node -> job_profile_node -> rag_retrieval_node -> question_generation_node
```

这个字段用于教学、调试和测试。前端未来也可以把它作为“题目生成来源说明”的一部分展示给学习者。

## 学习重点

- RAG 检索应该作为独立节点进入工作流
- 工作流节点只消费稳定输入和输出，不直接依赖存储细节
- trace 能帮助定位题目来自哪一步
- 题目混合策略决定了最终面试体验，不只是技术实现问题
