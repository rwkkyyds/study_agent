# 01 - 岗位题库设计

> 文件路径：`app/knowledge/question_bank.py`

## 用途

岗位题库是阶段五的知识库数据源。

真实工业项目里，这部分可能来自数据库、运营后台、面试官沉淀题库、岗位 JD、历史面试记录或向量库。当前阶段先用结构化 Python 数据保存题库，是为了让学习重点放在“题库字段怎么设计”和“检索链路如何接入工作流”。

## 题库字段

`app/knowledge/question_bank.py` 中每条题库数据包含：

| 字段 | 含义 |
|------|------|
| `id` | 题库题目的稳定 ID |
| `skill` | 题目考察技能，例如 RAG、Agent、Backend |
| `difficulty` | 难度分层：junior、mid、senior |
| `question_type` | 面试题类型，用于前端展示和统计 |
| `question` | 题干 |
| `expected_points` | 期望回答要点 |
| `keywords` | 检索关键词 |
| `source` | 题目来源，用于报告和审计 |

## 为什么题库要有 difficulty

面试题不是越难越好，而是要和候选人阶段、岗位目标匹配。

阶段五使用 `difficulty` 做简单分层：

- `junior`：偏基础解释、流程理解
- `mid`：偏项目实现、工程落地
- `senior`：偏评估体系、架构设计、稳定性和回滚

检索服务会优先返回与请求难度一致的题目。

## 为什么先不用真实向量库

阶段五的目标是先跑通 RAG 形状，而不是马上引入 Milvus 或 pgvector。

先用本地题库有几个好处：

- 测试稳定，不依赖外部服务
- 数据结构清晰，适合学习
- 方便看懂打分排序规则
- 后续替换为向量检索时，API 和 workflow 不需要大改

## 后续升级方向

`app/knowledge/question_bank.py` 后续可以迁移到：

- PostgreSQL 题库表
- JSON/YAML 可运营题库文件
- Milvus / pgvector 向量库
- 管理员后台维护题库
- 基于历史面试报告自动沉淀题库

## 学习重点

- RAG 的第一步不是模型，而是知识库结构设计
- 题库数据要带来源、技能、难度和检索关键词
- 本地题库可以作为向量库接入前的稳定替身
- 数据结构稳定后，检索实现可以渐进替换
