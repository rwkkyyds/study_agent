# 03 - 面试联动

> 相关文件：`app/services/interviews.py`、`app/models/interview.py`

## 用途

阶段三让面试题生成可以复用已解析的候选人画像。

这意味着候选人不需要每次生成题目都重新粘贴简历，系统也能把一次面试会话和当时使用的画像关联起来。

## 两种生成题目的方式

### 直接使用简历文本

这是阶段一和阶段二已有路径。

适合快速试用：一次请求里直接提供简历文本、岗位、难度和题目数量。

### 使用候选人画像 ID

这是阶段三新增路径。

用户先解析简历得到画像，再用 `resume_profile_id` 生成题目。服务层会读取当前用户自己的画像，把画像中的标准化文本交给面试工作流。

## 为什么要关联画像

面试会话保存 `resume_profile_id` 有几个好处：

- 回看报告时知道这次面试基于哪份简历
- 后续可以比较同一简历多次练习效果
- 简历更新后，新旧画像不会混淆
- LangGraph 工作流可以从画像读取技能和项目上下文

## 用户隔离

用户只能使用自己的画像生成题目。

如果 A 用户传入 B 用户的画像 ID，系统不会返回 B 的数据，也不会用它生成题目。

这和阶段二的面试会话隔离是一致的：用户 ID 是所有候选人数据的权限边界。

## 学习重点

- 面试系统不要每次都从原始简历重新开始
- 画像是简历和面试工作流之间的中间层
- 会话关联画像后，报告可追溯性更强
- 权限校验要在读取画像时完成，而不是依赖前端不传错 ID
