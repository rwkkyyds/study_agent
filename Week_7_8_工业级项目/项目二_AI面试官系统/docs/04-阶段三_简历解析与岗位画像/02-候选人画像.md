# 02 - 候选人画像

> 相关文件：`app/models/resume.py`、`app/schemas/resume.py`

## 用途

候选人画像是简历解析后的结构化结果。

它不是把简历全文简单存一遍，而是把面试系统最关心的信息提取出来，方便后续生成题目、追问、评分和复盘。

## 核心字段

| 字段 | 业务意义 |
|------|----------|
| 来源类型 | 区分 text、markdown、PDF |
| 来源名称 | 文件名或用户提供的来源说明 |
| 原始文本 | 保留解析前内容，便于追溯 |
| 标准化文本 | 后续工作流实际使用的清洗文本 |
| 摘要 | 对候选人能力的短描述 |
| 技能栈 | 从简历识别出的技术关键词 |
| 项目经历 | 可被面试官深挖的项目线索 |
| 年限 | 候选人经验强度的粗略信号 |
| 岗位关键词 | 简历和目标岗位交集形成的追问方向 |

## 抽取策略

阶段三使用确定性规则抽取。

这样做的目的不是追求最终解析效果，而是先把画像结构稳定下来。后续可以把规则替换成 LLM 简历解析 Agent，但不需要重写接口、数据库和测试。

当前抽取重点：

- 技能关键词，例如 FastAPI、RAG、LangGraph、Docker
- 项目线索，例如包含“项目”“系统”“平台”“Agent”的句子
- 年限表达，例如“3 年项目经验”“4 年后端经验”
- 岗位匹配词，例如 AI 应用岗位对应 LLM、RAG、Agent、向量检索

## 学习重点

- 画像是后续智能工作流的稳定输入
- 原文和标准化文本都要保存，分别用于追溯和处理
- JSON 字段适合保存早期半结构化结果
- 画像字段设计要服务后续面试追问，而不是为了抽取而抽取
