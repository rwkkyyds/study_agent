## Q1：async/await 是什么？协程和多线程有什么区别？

**答：**

| 维度 | 协程 (asyncio) | 多线程 (threading) |
|------|---------------|-------------------|
| 切换代价 | ~100ns（用户态） | ~1-10μs（内核态） |
| 切换时机 | 主动 await 让出 | OS 抢占式 |
| 内存 | ~KB/协程 | ~8MB/线程 |
| 并发 | 单线程协作式 | 多线程并行 |
| GIL 影响 | 无（单线程） | 有（Python GIL） |

**关键：** 协程是"协作式多任务"，await 处主动让出；线程是"抢占式"，OS 强制切换。10000 个协程只占几 MB，10000 个线程占 80GB。

## Q2：asyncio.gather 和 asyncio.create_task 的区别？

**答：**

- **gather**：同时启动多个协程，**阻塞等待**全部完成才返回结果列表
- **create_task**：创建 Task 对象立即返回，**不阻塞**当前协程。需要手动 await task 获取结果

```python
# gather：等全部完成
results = await asyncio.gather(task_a(), task_b())

# create_task：后台运行，主协程继续
t1 = asyncio.create_task(long_task())
# 主协程做其他事...
result = await t1
```

## Q3：FastAPI 中 async def 和 def 端点有什么区别？

**答：**

- **async def**：由事件循环直接调用，适合 IO 密集型。但如果在里面调 `time.sleep()`，会卡死整个事件循环
- **def**：FastAPI 在线程池中执行，不会阻塞事件循环，但有线程开销

```python
# IO 密集 → async def
@app.get("/api")
async def get_data():
    data = await db.fetch()  # 非阻塞
    return data

# CPU 密集 → def 或 run_in_executor
@app.get("/compute")
async def compute():
    loop = asyncio.get_running_loop()
    return await loop.run_in_executor(None, heavy_cpu_task)
```

## Q4：为什么 async def 里不能调用 time.sleep()？

**答：** `time.sleep()` 是同步阻塞调用，会让**整个线程**（包括事件循环）暂停。事件循环无法调度其他协程，所有请求都排队。

```python
@app.get("/bad")
async def bad():
    time.sleep(5)   # ❌ 卡死整个服务 5 秒
    return "ok"

@app.get("/good")
async def good():
    await asyncio.sleep(5)  # ✅ 让出控制权，其他请求正常处理
    return "ok"
```

## Q5：Python 的 GIL 对 asyncio 有影响吗？

**答：基本没有。**

- asyncio 是单线程模型，不涉及多线程竞争
- GIL 只限制同一时刻只有一个线程执行 Python 字节码
- asyncio 只有一个线程，所以 GIL 不影响协程调度

**例外：** 用 `run_in_executor()` 时，线程池里会有多个线程，这些线程受 GIL 限制。所以 CPU 密集任务建议用 `ProcessPoolExecutor`。

## Q6：如何用 asyncio 做并发 HTTP 请求？有什么常见坑？

**答：**

```python
import httpx

async with httpx.AsyncClient() as client:
    responses = await asyncio.gather(
        *(client.get(url) for url in urls)
    )
```

**常见坑：**
1. 用同步 `requests.get()` 代替 `httpx.AsyncClient`——会阻塞事件循环
2. 忘记设 timeout——一个慢请求拖死全部
3. 不限制并发数——瞬间打爆目标服务（用 `asyncio.Semaphore` 限流）
