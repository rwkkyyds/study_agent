# Section 1 学习笔记：Redis 工程化

## 一、Redis 核心定位

Redis = 内存数据库 + 键值存储 + 丰富的数据结构

```
请求 → Redis（内存，μs级）→ 命中 → 直接返回
  ↓ miss
PostgreSQL（磁盘，ms级）→ 查询 → 写入缓存 → 返回
```

适用场景：缓存、会话存储、限流、消息队列、排行榜

## 二、五种基础数据结构

| 结构 | 命令 | 适用场景 |
|------|------|---------|
| String | SET/GET/SETEX/INCR | 缓存、计数器、分布式锁 |
| Hash | HSET/HGET/HGETALL    ======    hgetall返回值  eg: {"name": "Alice", "age": 30} | 对象存储（用户信息、会话状态） |
| List | LPUSH/RPOP/LRANGE | 对话历史、任务队列 |
| Set | SADD/SMEMBERS/SINTER  ===== smembers 返回值 eg: {"tag1", "tag2"} smembers 作用： 获取集合中的所有成员 | 标签、权限、去重 |
| SortedSet | ZADD/ZRANGE/ZRANK =====  zrange 作用： 按分数范围获取元素 zrank 作用： 获取元素的排名 | 排行榜、滑动窗口限流 |

## 三、Cache-Aside 旁路缓存（最常用）

```
读流程：
  1. 查 Redis → 命中 → 返回
  2. 未命中 → 查 DB → 写入 Redis（带 TTL）→ 返回

写流程：
  1. 更新 DB
  2. 删除 Redis 缓存（非更新，避免并发不一致）
```

**为什么删除而非更新缓存？**
并发场景下，更新缓存可能导致脏数据。删除后下次读自动从 DB 加载最新。

## 四、缓存三大问题

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 穿透 | 查询不存在的数据，缓存永远 miss | 布隆过滤器 / 缓存空值 |
| 击穿 | 热点 key 过期，大量请求同时打 DB | 互斥锁 / 永不过期+后台刷新 |
| 雪崩 | 大量 key 同时过期，DB 压力暴增 | TTL 加随机偏移 / 多级缓存 |

## 五、Redis 会话存储

```python
# 创建会话
r.setex(f"session:{sid}", 3600, json.dumps(session_data))

# 添加消息
session["messages"].append({"role": "user", "content": "..."})
r.setex(key, ttl, json.dumps(session))

# 获取历史
history = json.loads(r.get(key))["messages"][-10:]
```

对比 MemorySaver：
- MemorySaver：内存存储，进程重启丢失
- Redis：持久化存储，支持多进程共享，生产级方案

## 六、限流算法

### 固定窗口
```
key = ratelimit:{user}:{窗口时间戳}
每次 INCR，超过 limit 则拒绝
问题：窗口边界处可能短暂允许 2x 流量
```

### 滑动窗口（生产推荐）
```
key = ratelimit:{user}（Sorted Set）
ZADD 添加当前时间戳
ZREMRANGEBYSCORE 清除窗口外记录
ZCARD 统计窗口内请求数
```

## 七、Pub/Sub

```
发布者 → r.publish(channel, message)
订阅者 → pubsub.subscribe(channel) → pubsub.listen()
```

适用场景：Agent 事件通知、实时日志、任务分发。
