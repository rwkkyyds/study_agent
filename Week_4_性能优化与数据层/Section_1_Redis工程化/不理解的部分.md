## Q1: sliding_window_check 中的 pipeline、zremrangebyscore、zadd、zcard 看不懂

### 答疑内容

#### 1. Pipeline（管道）
**概念**：将多个 Redis 命令一次性发送，减少网络往返。

| 不用 pipeline | 用 pipeline |
|---|---|
| 3 次网络请求 | 1 次网络请求 |
| 慢 | 快（高并发时差异明显）|

```python
# 用法
pipe = r.pipeline()
pipe.zremrangebyscore(key, 0, window_start)
pipe.zadd(key, {f"{now}": now})
pipe.zcard(key)
results = pipe.execute()  # 一次性执行 3 个命令
```

#### 2. Sorted Set（有序集合）结构
- Redis 中的数据结构：**(成员, 分数) 的集合**，按分数排序
- 在滑动窗口限流中：存储**请求的时间戳**
  - 成员：时间戳字符串（如 `"1000.5"`）
  - 分数：时间戳数值（如 `1000.5`）

#### 3. zremrangebyscore - 删除指定分数范围的元素
```python
pipe.zremrangebyscore(key, 0, window_start)
# 删除所有分数在 [0, window_start] 范围内的元素
```

**在限流中的作用**：
```
now = 1000.0，window = 60，window_start = 940.0

时间轴：
940.0 ←─────────────── 1000.0 (现在)
 ┌──────── 60 秒窗口 ────────┐
 删除        │          保留
 ❌ < 940.0 │          ✅ ≥ 940.0
```
- 删除 60 秒前的请求，只保留最近 60 秒的请求

#### 4. zadd - 添加元素到 Sorted Set
```python
pipe.zadd(key, {f"{now}": now})
# 添加当前请求到集合中
# 成员：时间戳字符串，分数：时间戳数值
```

#### 5. zcard - 统计集合元素个数
```python
pipe.zcard(key)
# 返回集合中有多少个元素 = 最近窗口内有多少个请求
count = results[2]
if count > limit:  # 超过限制
    return False
```

#### 6. 完整流程演示
```python
# 限流：最多 3 次请求 / 10 秒
第 1 次（t=1.0）：
  zremrangebyscore 清空（没有旧记录）
  zadd 添加 t=1.0
  zcard = 1 ✅ 通过

第 2 次（t=2.0）：
  zcard = 2 ✅ 通过

第 3 次（t=3.0）：
  zcard = 3 ✅ 通过

第 4 次（t=4.0）：
  zcard = 4 > limit(3) ❌ 拒绝

第 5 次（t=11.0）：
  zremrangebyscore 删除 t ≤ 1.0 的请求
  zadd 添加 t=11.0
  zcard = 2 ✅ 通过（保留了 t=2,3,4）
```

**核心理念**：
- `zremrangebyscore`：自动清理过期数据
- `zadd`：记录新请求
- `zcard`：检查是否超限
- 三步一体，用 pipeline 优化性能

## Q2: 为什么滑动窗口限流的所有请求都通过了？不应该第4个被拒绝吗？

### 问题描述
运行代码时看到：
```
--- 滑动窗口限流（3次/10秒）---
请求1: 通过 (1/3)
请求2: 通过 (2/3)
请求3: 通过 (2/3)   ← 还是 2？
请求4: 通过 (3/3)
请求5: 通过 (3/3)
```
5 个请求全部通过，但应该在第 4 个被拒绝。

### 根本原因：time.time() 精度 Bug

**问题**：所有请求在同一毫秒内执行，`time.time()` 返回相同的值：
```python
请求1：now = 1000.700
请求2：now = 1000.700  # 相同！
请求3：now = 1000.700  # 相同！
```

**关键点**：Sorted Set 的 `zadd` 行为
- 当成员名相同时，`zadd` 会**覆盖**而不是**添加新元素**

```python
# 错误的做法（会重复覆盖）
zadd(key, {f"{now}": now})  # 成员名 = f"{now}" = "1000.700"

请求1：zadd(key, {"1000.700": 1000.700})  # zcard = 1
请求2：zadd(key, {"1000.700": 1000.700})  # 覆盖！zcard = 1（不增加）
请求3：zadd(key, {"1000.700": 1000.700})  # 覆盖！zcard = 1（不增加）
```

结果：`zcard` 永远无法达到 4，所有请求都通过！

### 修复方案：使用唯一 ID 作为成员名

**修改前**：
```python
pipe.zadd(key, {f"{now}": now})  # 成员只用时间戳，可能重复
pipe.zrem(key, f"{now}")         # 删除也用时间戳，可能删错
```

**修改后**：
```python
import uuid

request_id = str(uuid.uuid4())  # 生成唯一 ID
pipe.zadd(key, {request_id: now})  # 成员 = 唯一 ID，分数 = 时间戳
pipe.zrem(key, request_id)         # 删除用唯一 ID
```

这样每个请求都有唯一成员名，不会被覆盖。

### 修复后的输出 ✅
```
--- 滑动窗口限流（3次/10秒）---
请求1: 通过 (1/3)
请求2: 通过 (2/3)
请求3: 通过 (3/3)
请求4: 拒绝 (4/3)  ✅ 正确拒绝！
请求5: 拒绝 (4/3)  ✅
```

### 教训
1. **高精度计数**：当需要计算请求数量时，不能只用时间戳作为唯一标识
2. **Sorted Set 的 zadd 特性**：相同成员会被覆盖，不会增加元素个数
3. **生产级方案**：务必用唯一 ID（UUID）+ 时间戳（分数）的组合
