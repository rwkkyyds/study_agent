# pgvector 向量扩展 — 学习笔记

## 一、核心概念

### 1.1 pgvector 是什么

pgvector 是 PostgreSQL 的一个扩展，让 PG 原生支持**向量存储和相似度检索**。不用额外部署 Milvus / FAISS / Chroma，一套 PG 搞定业务数据 + 向量数据。

```
传统 PG：存储结构化数据（用户、订单、文章）
pgvector：额外存储 embedding 向量，支持 SQL 里做相似度搜索
```

### 1.2 向量（Embedding）长什么样

一个文本 → Embedding 模型（如 BGE-small-zh-v1.5）→ 一个浮点数数组（512 维）：

```python
"PostgreSQL 是开源数据库" 
→ [0.045, -0.076, 0.049, ..., 0.035]  # 512 个浮点数
```

语义越接近的文本，向量之间的距离越小。

### 1.3 三种距离算子

| 算子 | 名称 | 范围 | 越小表示 | 适用场景 |
|------|------|------|----------|----------|
| `<=>` | Cosine Distance | [0, 2] | 方向越近 | 语义搜索（推荐） |
| `<->` | L2 Distance | [0, ∞) | 位置越近 | 绝对距离敏感场景 |
| `<#>` | Inner Product（负） | (-∞, ∞) | 越相似 | 需归一化向量 |

```sql
-- 余弦相似度检索 Top-3
SELECT content, embedding <=> :query_emb AS distance
FROM documents
ORDER BY embedding <=> :query_emb
LIMIT 3;
```

## 二、向量索引

### 2.1 为什么需要索引

5000 条数据全表扫描 ≈ 8ms，500 万条 ≈ 8 秒——不可接受。索引把 **O(n)** 降到 **O(log n)**。

### 2.2 IVFFlat vs HNSW

| 维度 | IVFFlat | HNSW |
|------|---------|------|
| 原理 | K-Means 聚类 → 只搜最近的几个桶 | 多层图结构，逐层导航 |
| 构建速度 | 快 | 慢（需构建图） |
| 查询速度 | 较快 | **很快** |
| 精度 | 中（近似） | **高（可调）** |
| 内存占用 | 低 | 高（存储图结构） |
| 生产推荐 | 次选 | ✅ **首选** |

```sql
-- IVFFlat
CREATE INDEX ON docs USING ivfflat (embedding vector_cosine_ops) WITH (lists = 100);

-- HNSW
CREATE INDEX ON docs USING hnsw (embedding vector_cosine_ops) WITH (m = 16, ef_construction = 64);
```

**参数说明：**
- `lists`：聚类中心数，建议 rows/1000 ~ rows/100
- `m`：每层最多邻居数，默认 16，越大精度越高内存越大
- `ef_construction`：构建时搜索深度，默认 64，越大精度越高构建越慢

### 2.3 查索引是否生效

```sql
EXPLAIN ANALYZE SELECT ... ORDER BY embedding <=> :q LIMIT 10;
```
- `Seq Scan` → 没走索引
- `Index Scan using idx_hnsw` → 索引生效 ✅

## 三、混合检索（Hybrid Search）

### 3.1 核心思想

| 检索方式 | 优势 | 劣势 |
|----------|------|------|
| 全文检索（tsvector） | 精确匹配关键词 | 不理解语义（"汽车"≠"轿车"） |
| 向量检索（pgvector） | 理解语义相似度 | 可能漏掉精确关键词匹配 |
| **混合检索** | **两者融合** | 实现复杂度高 |

### 3.2 RRF 融合公式

```
RRF(d) = Σ 1/(k + rank_i(d))

k = 60（平滑常数）
rank_i(d) = 文档 d 在第 i 个检索源中的排名

示例：
- 文档 A：全文排名第1，向量排名第3
  RRF(A) = 1/(60+1) + 1/(60+3) = 0.0164 + 0.0159 = 0.0323
  
- 文档 B：全文排名第2，向量排名第2
  RRF(B) = 1/(60+2) + 1/(60+2) = 0.0161 + 0.0161 = 0.0322

A 胜出（综合排名更高）
```

### 3.3 PostgreSQL 全文检索

```sql
-- tsvector：将文本解析为可搜索的词位列表
-- GIN 索引：加速 tsvector 检索
CREATE INDEX ON articles USING GIN (to_tsvector('simple', content));

-- 全文检索查询
SELECT *, ts_rank(to_tsvector('simple', content), plainto_tsquery('simple', :q)) AS rank
FROM articles
WHERE to_tsvector('simple', content) @@ plainto_tsquery('simple', :q)
ORDER BY rank DESC;
```

> ⚠️ PostgreSQL 内置分词器对**中文**不友好，需要 `zhparser` 扩展才能正确分词。英文场景开箱即用。

## 四、pgvector RAG 全链路

```
用户问题："什么是 HNSW？"
    ↓
1. Embedding 模型 → 查询向量
    ↓
2. pgvector 检索 → Top-K 相关文档片段
    ↓
3. 构造 Prompt：文档上下文 + 用户问题
    ↓
4. DeepSeek/LLM 生成 → 基于文档的回答
```

### 4.1 pgvector vs 其他向量库

| 维度 | pgvector | FAISS/Chroma | Milvus |
|------|----------|-------------|--------|
| 部署 | PG 自带 | 额外安装 | Docker 服务 |
| 事务 | ACID ✅ | ❌ | ❌ |
| 混合检索 | 原生 SQL ✅ | 需拼接 | 部分支持 |
| 性能 | 中等 | 快 | 很快 |
| 适合 | 已有 PG 的项目 | 原型验证 | 大规模生产 |

**选型原则：** 已有 PG → pgvector；百万级向量 → Milvus；快速验证 → FAISS/Chroma。

## 五、关键代码片段

### 5.1 SQLAlchemy ORM 定义

```python
from pgvector.sqlalchemy import Vector

class Document(Base):
    __tablename__ = "docs"
    id = Column(Integer, primary_key=True)
    content = Column(String)
    embedding = Column(Vector(512))  # 维度固定，不可后续修改
```

### 5.2 向量相似度查询

```python
stmt = text("""
    SELECT content, 1 - (embedding <=> :q) AS similarity
    FROM docs ORDER BY embedding <=> :q LIMIT 5
""")
rows = session.execute(stmt, {"q": str(query_emb)}).fetchall()
```
