# Section 2: PostgreSQL 进阶 - 生产级高频面试题

## 一、索引优化（必考）

### Q1: PostgreSQL 有哪些索引类型？各自适用什么场景？

**答：**

| 索引类型 | 适用场景 | 示例 |
|---------|---------|------|
| B-tree | 等值、范围、排序 | `WHERE id = 1`, `WHERE price < 100` |
| GIN | JSONB、全文搜索、数组 | `WHERE tags @> '["热销"]'` |
| GiST | 地理数据、范围类型、相似度 | PostGIS、pgvector |
| BRIN | 大表按时间顺序存储 | 日志表、时序数据 |

**追问：B-tree 和 Hash 索引有什么区别？**
- B-tree 支持范围查询（`<`, `>`, `BETWEEN`），Hash 只支持等值查询（`=`）
- 实际生产中几乎只用 B-tree，Hash 索引很少用

---

### Q2: 什么是复合索引的最左前缀原则？

**答：**
复合索引 `(A, B, C)` 相当于同时创建了三个索引：
- `(A)` — 只查 A 时可用
- `(A, B)` — 查 A+B 时可用
- `(A, B, C)` — 查 A+B+C 时可用

```sql
-- 索引 (category, price)
WHERE category = 'x' AND price < 100  -- ✅ 完全命中
WHERE category = 'x'                  -- ✅ 命中前缀
WHERE price < 100                     -- ❌ 不命中（跳过了 category）
```

**设计原则：** 高选择性（区分度高）的列放前面。

---

### Q3: 什么是覆盖索引？为什么能提升性能？

**答：**
覆盖索引 = 索引本身包含查询需要的所有列，不需要"回表"。

```sql
-- 普通索引 idx_category(category)
-- 查询 SELECT name, price FROM products WHERE category = '电子产品'
-- 执行计划：Index Scan → 回表取 name, price

-- 覆盖索引 idx_cover(category) INCLUDE (name, price)
-- 同样的查询
-- 执行计划：Index Only Scan → 不回表，直接从索引返回
```

**性能差距：** Index Only Scan 比 Index Scan 快 2-5 倍（省去了随机 I/O）。

---

### Q4: 什么是部分索引？什么时候用？

**答：**
部分索引 = 只索引满足 WHERE 条件的行。

```sql
-- 只索引活跃商品（占 80%）
CREATE INDEX idx_active ON products(price) WHERE is_active = true;
```

**适用场景：**
- 数据分布不均匀（如 90% 是正常订单，10% 是异常订单）
- 只需要查询某个子集
- 好处：索引更小、维护成本更低

---

### Q5: 如何判断一个查询是否需要加索引？

**答：**
```sql
EXPLAIN ANALYZE SELECT ...;
```

看执行计划：
1. **Seq Scan（全表扫描）** → 考虑加索引
2. **rows 估算 vs 实际行数差距大** → 执行 `ANALYZE table` 更新统计信息
3. **Rows Removed by Filter 很多** → 大量行被过滤，浪费了扫描

**不加索引的情况：**
- 数据量很小（< 1000 行）
- 频繁写入、很少查询
- 选择性很低（如 gender 只有 M/F）

## 二、连接池（常考）

### Q6: 为什么需要数据库连接池？

**答：**
每次创建数据库连接需要：TCP 三次握手 + PostgreSQL 认证 + SSL 握手 ≈ 5-20ms。

连接池预先创建一批连接，反复复用：
- 省去了连接建立/销毁的开销
- 控制并发连接数，防止数据库被压垮
- 支持连接健康检测（pool_pre_ping）

---

### Q7: SQLAlchemy 连接池参数怎么配置？

**答：**
```python
engine = create_engine(
    "postgresql+psycopg2://...",
    pool_size=20,         # 保持 20 个空闲连接
    max_overflow=10,      # 突发最多再创建 10 个
    pool_timeout=30,      # 等不到连接等 30 秒
    pool_recycle=3600,    # 连接 1 小时后重建
    pool_pre_ping=True,   # 用前 ping 检测
)
```

**生产建议：**
- `pool_size = CPU核心数 * 2 + 1`
- `max_overflow = pool_size`
- PostgreSQL `max_connections` 默认 100，多实例要规划好总连接数

---

### Q8: 同步连接池和异步连接池有什么区别？

**答：**

| 维度 | 同步（psycopg2） | 异步（asyncpg） |
|------|-----------------|----------------|
| 阻塞 | 阻塞当前线程 | 不阻塞事件循环 |
| 性能 | 基准 | 快 2-5 倍 |
| 适用 | 普通 Web、脚本 | FastAPI 高并发 |
| Session | `Session(engine)` | `AsyncSession(async_engine)` |

FastAPI 推荐：`asyncpg + AsyncSession`

## 三、查询优化（高频）

### Q9: 什么是 N+1 查询问题？怎么解决？

**答：**
N+1 = 查询 1 次主表 + N 次关联表。

```python
# N+1 问题
users = session.query(User).all()       # 1 次 SQL
for user in users:
    print(user.orders)                  # 每个用户 1 次 → N 次
```

**解决方案：Eager Loading**
```python
# joinedload（LEFT JOIN，1 次查询）
users = session.query(User).options(joinedload(User.orders)).all()

# selectinload（IN 子查询，2 次查询）
users = session.query(User).options(selectinload(User.orders)).all()
```

**选择：** 一对多用 `selectinload`，多对一/一对一用 `joinedload`。

### Q10: EXPLAIN ANALYZE 输出怎么看？关注哪些指标？

**答：**
```sql
EXPLAIN ANALYZE SELECT * FROM orders WHERE user_id = 42;
```

**关键指标：**
1. **Seq Scan vs Index Scan** — 全表扫描还是索引扫描
2. **rows 估算 vs 实际** — 差距大说明统计信息过时，需要 `ANALYZE table`
3. **actual time** — 实际执行时间
4. **Rows Removed by Filter** — 被过滤的行数，越多越浪费
5. **Nested Loop vs Hash Join** — 小表 Nested Loop，大表 Hash Join

### Q11: 什么是窗口函数？和 GROUP BY 有什么区别？

**答：**
```
GROUP BY：多行合并成一行（折叠）
窗口函数：每行保留，同时计算聚合值（不折叠）
```

```sql
-- GROUP BY：只能看到部门平均工资
SELECT dept, AVG(salary) FROM employees GROUP BY dept;

-- 窗口函数：每个员工旁边标上部门平均工资
SELECT name, dept, salary,
       AVG(salary) OVER (PARTITION BY dept) as dept_avg
FROM employees;
```

**常用窗口函数：** `ROW_NUMBER`, `RANK`, `SUM OVER`, `LAG`, `LEAD`

`ROW_NUMBER`：行编号，连续不重复，同值也会分配不同序号，无并列。
例：分数相同，分别标 1、2、3`

`RANK`：排名，並列会跳号，相同值同名次，跳过中间数字。
例：两个 90 分都是第 1，下一个 85 直接第 3。

`SUM OVER`：窗口求和，分组内累计 / 分区汇总，不压缩行数。
不加ORDER BY：分区总和；
加ORDER BY：逐行累加累计和。

 `LAG`：取当前行上 N 行数据，常用于环比、上期值对比。
例：LAG (score,1) 取出上一条记录分数。

`LEAD`：取当前行下 N 行数据，用于查看下一条记录。
例：LEAD (score,1) 取出后一条记录分数。

### Q12: 什么是 CTE？比子查询好在哪？

**答：**
CTE（Common Table Expression）= `WITH` 子句，给子查询起名字。

```sql
-- 子查询（嵌套 3 层，看不懂）
SELECT * FROM (
    SELECT *, RANK() OVER (...) as rk
    FROM (SELECT ... GROUP BY ...) t1
) t2 WHERE rk = 1;

-- CTE（分步，清晰）
WITH totals AS (SELECT ... GROUP BY ...),
ranked AS (SELECT *, RANK() OVER (...) as rk FROM totals)
SELECT * FROM ranked WHERE rk = 1;
```

**优势：**
1. 可读性：逻辑分步骤
2. 可复用：同一 CTE 可被引用多次
3. 支持递归：树形结构查询（组织架构、评论回复）

## 四、综合场景题

### Q13: 一个查询很慢，你怎么排查？

**答：**
1. `EXPLAIN ANALYZE` 看执行计划
2. 是不是 Seq Scan？→ 加索引
3. rows 估算差距大？→ `ANALYZE table` 更新统计
4. 是不是 N+1？→ 改用 Eager Loading
5. 是不是 SELECT *？→ 只取需要的列
6. 数据量太大？→ 分页（LIMIT OFFSET / keyset pagination）


### Q15: Top-N 问题怎么解？（每个部门工资最高的 3 个人）

**答：**
```sql
WITH ranked AS (
    SELECT *, ROW_NUMBER() OVER (
        PARTITION BY dept ORDER BY salary DESC
    ) as rn
    FROM employees
)
SELECT * FROM ranked WHERE rn <= 3;
```

**面试加分：** 提到 `RANK()` 会有并列跳号（1,2,2,4），`DENSE_RANK()` 不跳号（1,2,2,3），`ROW_NUMBER()` 无并列（1,2,3,4）。
