# Section 2: PostgreSQL 进阶 - 学习笔记

## 1. PostgreSQL 索引类型

### B-tree（默认索引）
```
适用：等值查询(=)、范围查询(< >)、排序(ORDER BY)
语法：CREATE INDEX idx_name ON table(column)
特点：绝大多数场景用这个就够了
```

### 复合索引（Composite Index）
```
适用：多列联合查询
语法：CREATE INDEX idx_name ON table(col1, col2)

关键规则 —— 最左前缀原则：
  索引 (category, price)
  ✅ WHERE category = 'x'              → 命中
  ✅ WHERE category = 'x' AND price<100 → 完全命中
  ❌ WHERE price < 100                  → 不命中（跳过了第一列）

列顺序建议：高选择性（区分度高）的列放前面
```

### 部分索引（Partial Index）
```
适用：只索引满足条件的行，节省空间
语法：CREATE INDEX idx_name ON table(column) WHERE condition

示例：只索引活跃商品
  CREATE INDEX idx_active_price ON products(price) WHERE is_active = true

好处：
  - 索引更小（只包含 80% 的行）
  - 维护成本更低
  - 查询必须包含 WHERE 条件才能命中
```

### 覆盖索引（Covering Index / INCLUDE）
```
适用：高频查询只取少量列，避免"回表"
语法：CREATE INDEX idx_name ON table(col1) INCLUDE (col2, col3)

原理：
  普通索引：索引只存 col1 → 查到后还要回表取 col2, col3
  覆盖索引：索引存 col1 + col2 + col3 → 直接返回，不用回表

PostgreSQL 执行计划：
  → Index Only Scan（最快，数据全在索引里）
  → Index Scan（需要回表）
  → Seq Scan（全表扫描，最慢）
```

### GIN 索引（Generalized Inverted Index）
```
适用：JSONB、全文搜索、数组
语法：CREATE INDEX idx_name ON table USING gin(column)

JSONB 查询示例：
  WHERE tags @> '["热销"]'         → 包含"热销"
  WHERE tags @> '["热销","新品"]'  → 同时包含两者

PostgreSQL 独有优势，AI/RAG 场景必备：
  - 存储文档元数据（JSONB）
  - 全文搜索（tsvector）
  - 数组包含查询
```

### GiST / BRIN 索引
```
GiST：地理数据（PostGIS）、范围类型、相似度搜索
  → pgvector 的 ivfflat/hnsw 索引基于此

BRIN：大表按时间顺序存储（日志、时序数据）
  → 索引极小，适合超大表
```

## 2. 索引设计原则

```
┌─────────────────────────────────────────────────────┐
│ 索引的收益                                            │
│  → 查询从 Seq Scan 变成 Index Scan                    │
│  → 10万条数据：13ms → 4ms（快 3 倍）                  │
│  → 数据量越大，效果越明显                              │
├─────────────────────────────────────────────────────┤
│ 索引的代价                                            │
│  → 占用存储空间（通常是表大小的 10%-30%）              │
│  → 写入变慢（INSERT/UPDATE/DELETE 需要维护索引）       │
│  → 不要过度索引！只给高频查询加索引                    │
├─────────────────────────────────────────────────────┤
│ 什么时候加索引                                        │
│  → WHERE 条件中频繁出现的列                           │
│  → JOIN 的关联列（外键）                              │
│  → ORDER BY / GROUP BY 的列                          │
│  → 高选择性列（区分度高，如 email、user_id）          │
│                                                      │
│ 什么时候不加索引                                      │
│  → 数据量很小的表（< 1000 行）                        │
│  → 频繁写入、很少查询的表                             │
│  → 选择性很低的列（如 gender 只有 M/F）               │
└─────────────────────────────────────────────────────┘
```

## 3. EXPLAIN ANALYZE

```sql
EXPLAIN ANALYZE SELECT * FROM products WHERE category = '电子产品';
```

执行计划关键字段：
```
Seq Scan          → 全表扫描（慢，需要加索引）
Index Scan        → 索引扫描（快）
Index Only Scan   → 只读索引（最快，覆盖索引）
Bitmap Index Scan → 位图索引扫描（中等，适合返回多行）

cost=0.00..3320.00  → 估算成本（启动..总成本）
rows=12473          → 估算返回行数
actual time=6.404ms → 实际执行时间
Rows Removed by Filter → 被过滤掉的行数（越多越浪费）
```

## 4. 连接池

### 为什么需要连接池
```
没有连接池：每次查询 → 建TCP连接 → 认证 → 执行 → 关闭连接
有连接池：  启动时建N个连接 → 反复复用 → 执行 → 归还

节省了 TCP 握手 + PostgreSQL 认证的开销（每次约 5-20ms）
```

### 核心参数
```python
engine = create_engine(
    "postgresql+psycopg2://user:pass@host:5432/db",
    pool_size=20,         # 保持 20 个空闲连接
    max_overflow=10,      # 突发时最多再创建 10 个
    pool_timeout=30,      # 等不到连接等 30 秒
    pool_recycle=3600,    # 连接 1 小时后重建
    pool_pre_ping=True,   # 用前 ping 检测
)
# 最大并发 = 20 + 10 = 30
```

### 生产环境建议
```
pool_size = CPU核心数 * 2 + 1
max_overflow = pool_size
pool_recycle = 3600（防 PostgreSQL 超时断开）
pool_pre_ping = True（防连接已断开）

PostgreSQL max_connections 默认 = 100
→ 5 个服务实例 × pool_size=20 = 100（刚好用满）
```

### 同步 vs 异步
```python
# 同步（psycopg2）
engine = create_engine("postgresql+psycopg2://...")
Session(engine)

# 异步（asyncpg，快 2-5 倍）
async_engine = create_async_engine("postgresql+asyncpg://...")
AsyncSession(async_engine)

# FastAPI 推荐用异步
```

## 5. N+1 查询问题

### 问题描述
```python
# 1 次查 users + N 次查 orders = N+1 次 SQL
users = session.query(User).all()       # 1 次
for user in users:
    print(user.orders)                  # 每个用户触发 1 次 → N 次
```

### 解决方案
```python
# 方案1：joinedload（LEFT JOIN，1 次查询）
users = session.query(User).options(joinedload(User.orders)).all()

# 方案2：selectinload（IN 子查询，2 次查询）
users = session.query(User).options(selectinload(User.orders)).all()

# 选择建议：
# joinedload   → 一对一、多对一
# selectinload → 一对多（更通用，推荐）
```

## 6. 窗口函数

### 核心概念
```
普通聚合（GROUP BY）：多行合并成一行
窗口函数（OVER）：每行保留，同时计算聚合值

类比：
  GROUP BY = 全班算平均分，只得到一个数字
  窗口函数 = 每个学生旁边标上班级平均分，学生信息都还在
```

### 常用窗口函数
```sql
-- 编号（无并列）
ROW_NUMBER() OVER (PARTITION BY dept ORDER BY salary DESC)

-- 排名（有并列，有跳号：1, 2, 2, 4）
RANK() OVER (PARTITION BY dept ORDER BY salary DESC)

-- 分组聚合（不折叠行）
SUM(salary) OVER (PARTITION BY dept)

-- 累计求和
SUM(amount) OVER (ORDER BY date ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)
#逐行累加amount

-- 取前一行的值（环比计算）
LAG(amount) OVER (ORDER BY date)
#取前一行的amount

-- 取后一行的值
LEAD(amount) OVER (ORDER BY date)
```

### Top-N 模式（高频面试题）
```sql
-- 每个部门工资最高的 3 个人
WITH ranked AS (
    SELECT *, ROW_NUMBER() OVER (
        PARTITION BY dept ORDER BY salary DESC
    ) as rn
    FROM employees
)
SELECT * FROM ranked WHERE rn <= 3;
```

## 7. CTE（Common Table Expression）

### 基本语法
```sql
WITH temp_name AS (
    SELECT ...  -- 第一步：定义临时结果集
)
SELECT * FROM temp_name;  -- 第二步：使用它
```

### 优势
```
1. 可读性：复杂查询拆成可读的步骤
2. 可复用：同一个 CTE 可被引用多次
3. 递归：支持树形结构查询（组织架构、评论回复）
```

### CTE vs 子查询
```sql
-- 子查询（嵌套，难读）
SELECT * FROM (
    SELECT *, RANK() OVER (...) as rk
    FROM (SELECT ... GROUP BY ...) t1
) t2 WHERE rk = 1;

-- CTE（分步，清晰）
WITH totals AS (SELECT ... GROUP BY ...),
ranked AS (SELECT *, RANK() OVER (...) as rk FROM totals)
SELECT * FROM ranked WHERE rk = 1;
```
