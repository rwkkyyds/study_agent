## Q1: Retriever 在哪里用过？面试题里提到但 demo 里没看到

**原问题：** "组件化：Prompt、LLM、Parser、Retriever 可自由组合"，但我并没有看到 Retriever 在哪里用过。

**通俗解释：**
Retriever = 检索器，作用是"根据用户问题，从知识库中找到相关文档片段"。

类比图书馆场景：
- 没有 Retriever：LLM 凭"记忆"回答（可能编造，即幻觉）
- 有 Retriever：先去书架找到相关段落，再根据段落回答（有据可依）

在 RAG 系统中的位置：
```
用户问题 -> [Retriever 检索相关文档] -> Prompt(问题+文档) -> LLM -> 回答
```

Section 2 的 demo 用关键词匹配模拟 Retriever 行为。Section 4 会学习真正的向量检索（Embedding + 向量数据库），届时 Retriever 用向量相似度找到语义最相关的文档。

**配套代码：** 见 `demo4_real_llm_retriever.py` 第二、三部分。

## Q2: "统一接口"具体体现在哪里？

**原问题：** 面试题说"统一接口意味着任意组件可以替换"，但我没有看到实际演示。

**通俗解释：**
LangChain 所有组件都实现 `Runnable` 接口，调用方式完全一样：

```python
# 不管是 Prompt、LLM、Parser 还是 Retriever，都支持这三种调用：
component.invoke(input)      # 单次调用
component.batch([inputs])    # 批量调用（并发）
component.stream(input)      # 流式输出
```

这意味着：
1. 换 LLM（GLM -> GPT-4 -> Claude）不需要改其他代码
2. 换 Parser（StrOutputParser -> JsonOutputParser）不需要改 Prompt
3. 链可以自由组合：`chain_a | chain_b` = 新链

**配套代码：** 见 `demo4_real_llm_retriever.py` 第四部分（invoke/batch/stream 对比）。
