# Section 2: LangChain 核心组件 — 学习笔记

## 1. LangChain 设计哲学

LangChain 是 LLM 应用开发的"胶水框架"，核心理念：**把 LLM 应用拆成可组合的标准组件**。

```
用户输入 -> Prompt模板 -> LLM模型 -> 输出解析器 -> 结构化结果
           (PromptTemplate)  (ChatOpenAI)  (OutputParser)
```

每个组件都实现统一的 `Runnable` 接口，可以用 `|` 管道符自由组合。

## 2. Prompt Templates（提示词模板）

### 2.1 PromptTemplate — 纯文本模板

```python
from langchain_core.prompts import PromptTemplate

template = PromptTemplate.from_template("你是{role}专家，解释{topic}")
prompt = template.format(role="AI", topic="RAG")
# -> "你是AI专家，解释RAG"
```

适用场景：text completion 模型（如 GPT-3.5-turbo-instruct）。

### 2.2 ChatPromptTemplate — 聊天模型专用

```python
from langchain_core.prompts import ChatPromptTemplate

template = ChatPromptTemplate.from_messages([
    ("system", "你是资深{domain}工程师"),
    ("human", "{question}"),
])
messages = template.format_messages(domain="Python", question="装饰器是什么？")
```

三种消息角色：
| 角色 | 作用 | 类比 |
|------|------|------|
| system | 设定 AI 身份和行为规则 | 老板给员工的岗位说明书 |
| human | 用户输入 | 客户的问题 |
| ai | AI 的回复（Few-Shot 时用） | 员工的标准回答示例 |

### 2.3 Few-Shot 模板

在 prompt 中给 LLM 几个"输入-输出"示例，让它学会期望的格式：

```python
template = ChatPromptTemplate.from_messages([
    ("system", "判断情感：正面/负面/中性"),
    ("human", "这部电影太棒了！"),  # 示例1
    ("ai", "正面"),
    ("human", "服务态度很差"),      # 示例2
    ("ai", "负面"),
    ("human", "{input}"),           # 真正的输入
])
```

核心价值：不改模型、不微调，只靠示例就能改变 LLM 行为。

## 3. Output Parsers（输出解析器）

LLM 返回纯文本，但程序需要结构化数据。Output Parser = "人话" -> "程序数据"。

| Parser | 输入 | 输出 | 适用场景 |
|--------|------|------|----------|
| StrOutputParser | 任意文本 | str | 聊天、文案生成 |
| CommaSeparatedListOutputParser | "a, b, c" | list | 标签、关键词提取 |
| JsonOutputParser | JSON 字符串 | dict | 通用结构化输出 |
| PydanticOutputParser | JSON 字符串 | BaseModel | 严格 schema 校验（生产首选） |

### 关键机制：format_instructions

Parser 的 `get_format_instructions()` 会生成格式化指令，**必须注入到 prompt 中**，否则 LLM 不知道按什么格式输出：

```python
parser = PydanticOutputParser(pydantic_object=MovieReview) #pydantic_object=MovieReview：
#指定解析规则为 MovieReview 这个 Pydantic 数据模型（定义了字段、类型、校验规则）。
instructions = parser.get_format_instructions()  # -> "Return a JSON with title, rating..."
# 必须把 instructions 放进 prompt 的 system 或 human 消息中
```

## 4. LCEL（LangChain Expression Language）

### 4.1 核心语法

用 `|` 管道符把组件串联，数据从左往右流动：

```python
chain = prompt | llm | parser
result = chain.invoke({"concept": "RAG"})
```

等价于手动调用：
```python
messages = prompt.format_messages(concept="RAG")
response = llm.invoke(messages)
result = parser.parse(response.content)
```

### 4.2 Runnable 接口

每个 LCEL 组件都实现统一接口：
| 方法 | 用途 |
|------|------|
| `.invoke(input)` | 单次调用 |
| `.batch([input1, input2])` | 批量调用 |
| `.stream(input)` | 流式输出 |

### 4.3 链的组合

链可以像乐高一样组合：

```python
translate_chain = translate_prompt | llm | StrOutputParser()
summary_chain = summary_prompt | llm | StrOutputParser()

# 组合：原文 → 翻译链 → 翻译后的文本 → 摘要链 → 摘要内容
combined = translate_chain | summary_chain
```

### 4.4 为什么 LCEL 重要

1. 后续 RAG 的检索链、Agent 的工具调用链都基于 LCEL
2. 统一接口意味着任意组件可以替换（换 LLM、换 Parser 不影响其他部分）
3. 原生支持流式输出，用户体验好

## 5. 知识图谱

```
LangChain
├── Prompt Templates
│   ├── PromptTemplate      (纯文本)
│   └── ChatPromptTemplate  (多角色消息)
├── Output Parsers
│   ├── StrOutputParser     (字符串)
│   ├── ListOutputParser    (列表)
│   ├── JsonOutputParser    (字典)
│   └── PydanticOutputParser(BaseModel，生产首选)
└── LCEL
    ├── | 管道符串联
    ├── Runnable 接口 (invoke/batch/stream)
    └── 链的组合与复用
```
