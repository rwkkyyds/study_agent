# Section 3: RAG 文档加载与多格式文本分块策略 — 学习笔记

## 1. 为什么 RAG 需要文档加载和分块

```
外部文档(txt/pdf/md) -> Document Loader -> Document对象 -> 分块 -> 向量化 -> 存储
```

- LLM 有上下文长度限制（4K/8K/128K tokens），不能把整本书塞进去
- 向量检索精度与块大小相关：太大=噪音多，太小=语义不完整
- 分块是 RAG 系统质量的**关键调优点**

## 2. Document 对象结构

LangChain 的标准文档格式，所有 Loader 最终都输出这个：

```python
from langchain_core.documents import Document

doc = Document(
    page_content="文档文本内容",       # 必填，字符串
    metadata={"source": "file.txt"}   # 可选，字典
)
```

| 字段 | 类型 | 说明 |
|------|------|------|
| page_content | str | 文档正文 |
| metadata | dict | 元数据（来源文件、页码、作者等） |

分块后每块都会**继承原文档的 metadata**，用于追溯来源。

## 3. 文档加载器（Document Loader）

| Loader | 用途 | 安装 |
|--------|------|------|
| TextLoader | 单个 .txt 文件 | langchain-community |
| DirectoryLoader | 批量加载目录 | langchain-community |
| PyPDFLoader | PDF 文件 | pypdf |
| UnstructuredMarkdownLoader | Markdown | unstructured |
| Docx2txtLoader | Word 文档 | docx2txt |
| CSVLoader | CSV 表格 | langchain-community |

```python
from langchain_community.document_loaders import DirectoryLoader, TextLoader

loader = DirectoryLoader(
    "./docs",
    glob="*.txt",                    # 只加载 .txt
    loader_cls=TextLoader,
    loader_kwargs={"encoding": "utf-8"},
)
docs = loader.load()  # -> List[Document]
```

**核心输出统一为 `List[Document]`**，不同格式只是 Loader 不同。

## 4. 文本分块器（Text Splitter）

### 4.1 RecursiveCharacterTextSplitter（最推荐）

按分隔符优先级**递归**拆分，保留更多语义完整性：

```
优先级：\n\n（段落） -> \n（换行） -> 句号 -> 空格 -> 字符
```

如果一个块太大，就用下一级分隔符继续拆，直到符合要求。

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=200,      # 每块最大字符数
    chunk_overlap=20,    # 相邻块重叠字符数
    separators=["\n\n", "\n", "。", "，", " "],
)

chunks = splitter.split_text(text)        # 纯文本 -> List[str]
doc_chunks = splitter.split_documents(docs) # Document -> List[Document]
```

### 4.2 chunk_size 的影响

| chunk_size | 效果 | 适用场景 |
|------------|------|----------|
| 太小（<100） | 语义碎片化，检索到的内容不完整 | 短问答 |
| 适中（200~500） | 平衡语义完整性和检索精度 | 通用 RAG |
| 太大（>1000） | 噪音多，检索精度下降，浪费 token | 长文档摘要 |

经验值：**200~1000 字符**（中文场景），需根据实际效果调优。

### 4.3 chunk_overlap 的作用

```
问题：一句话被切断在两个块的边界

无 overlap：
  chunk1: "...FastAPI 是一个"      <- 语义不完整
  chunk2: "现代 Web 框架..."        <- 语义不完整

有 overlap：
  chunk1: "...FastAPI 是一个现代"   <- 完整
  chunk2: "一个现代 Web 框架..."    <- 完整（重叠部分）
```

经验值：**chunk_overlap = chunk_size 的 10%~20%**

## 5. 分块策略对比

| 策略 | 原理 | 推荐度 |
|------|------|--------|
| RecursiveCharacterTextSplitter | 按语义边界递归拆分 | 最推荐 |
| CharacterTextSplitter | 按单一分隔符拆分 | 简单场景 |
| TokenTextSplitter | 按 token 数拆分 | 精确控制 token |
| MarkdownHeaderTextSplitter | 按 Markdown 标题拆分 | Markdown 文档 |

## 6. 完整数据流

```
原始文档 (.txt/.pdf/.md)
    │
    ▼
Document Loader (TextLoader/DirectoryLoader)
    │
    ▼
List[Document]  (page_content + metadata)
    │
    ▼
Text Splitter (RecursiveCharacterTextSplitter)
    │
    ▼
List[Document]  (分块后的文档，保留元数据)
    │
    ▼
Embedding (Section 4)
    │
    ▼
Vector Database (Section 4)
```
