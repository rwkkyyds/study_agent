# Section 3: RAG 文档加载与分块策略 — 生产级高频面试题

---

## Q1: 为什么 RAG 需要对文档进行分块？直接把整篇文档塞给 LLM 不行吗？

**答：**
三个原因：
1. **上下文限制**：LLM 有 token 上限（GPT-4: 128K，但越长越贵、越慢）
2. **检索精度**：向量检索是按"块"匹配的，整篇文档的向量会丢失细节
3. **成本控制**：每次调用 LLM 按 token 计费，只发相关片段比发全文便宜 10~100 倍

```
不分块：整篇文档 -> 1个向量 -> 检索粗糙
分块后：多个片段 -> 多个向量 -> 精准定位到具体段落
```

## Q2: chunk_size 设多大合适？太大或太小有什么问题？

**答：**

| chunk_size | 问题 |
|------------|------|
| 太小（<100） | 语义碎片化，检索到的内容缺少上下文，LLM 无法理解 |
| 太大（>1000） | 噪音多（无关内容混入），浪费 token，检索精度下降 |
| 适中（200~500） | 平衡语义完整性和检索精度 |

**调优方法**：没有万能值，需要根据实际效果 A/B 测试：
- 用真实问题测试检索结果质量
- 观察 LLM 回答是否准确
- 一般从 500 开始，逐步减小到精度最佳

## Q3: chunk_overlap 为什么重要？设为 0 会怎样？

**答：**
chunk_overlap 让相邻块有重叠区域，防止关键语句在边界被截断。

```python
# 设为 0 的问题：
# 原文："FastAPI 是一个现代 Web 框架，支持异步处理"
# chunk1: "...FastAPI 是一个"      <- 语义断裂
# chunk2: "现代 Web 框架..."        <- 缺主语

# 设为 20：
# chunk1: "...FastAPI 是一个现代"   <- 语义完整
# chunk2: "一个现代 Web 框架..."    <- 语义完整
```

经验值：chunk_overlap = chunk_size 的 10%~20%。设太大会导致存储和检索时重复内容过多。

## Q4: RecursiveCharacterTextSplitter 和 CharacterTextSplitter 有什么区别？

**答：**

| 维度 | CharacterTextSplitter | RecursiveCharacterTextSplitter |
|------|----------------------|-------------------------------|
| 分隔符 | 单一分隔符（如 `\n`） | 多级分隔符递归拆分 |
| 拆分逻辑 | 遇到分隔符就切 | 先用高级分隔符，块太大再用低级 |
| 语义完整性 | 一般 | 更好 |
| 推荐度 | 简单场景可用 | RAG 项目首选 |

```python
# CharacterTextSplitter：只按换行切
"段落1内容\n\n段落2内容" -> 切成2块（如果每块<chunk_size）

# RecursiveCharacterTextSplitter：按优先级递归
1. 先尝试按 \n\n（段落）切
2. 如果某块太大，按 \n（换行）切
3. 还太大，按句号切
4. 还太大，按空格切
5. 最后按字符切
```

## Q5: 分块后 metadata 有什么用？

**答：**
metadata 用于**追溯来源**，是 RAG 系统可解释性的基础：

1. **引用标注**：回答时附上"来源：xxx.pdf 第5页"
2. **过滤检索**：只在特定文档范围内检索（如 `source="产品手册.pdf"`）
3. **去重/更新**：根据 source 字段判断哪些块需要更新
4. **权限控制**：不同用户只能检索有权限的文档

```python
# 分块后 metadata 自动继承
chunk.metadata
# -> {"source": "docs/rag_intro.txt", "page": 3, "author": "AI助手"}
```

## Q6: 生产环境中如何处理 PDF 中的表格和图片？

**答：**
普通 TextLoader 无法处理表格和图片，需要用专用工具：

| 工具 | 用途 |
|------|------|
| UnstructuredPDFLoader | 通用 PDF 解析（表格+图片+文字） |
| PyPDFLoader | 纯文字 PDF（轻量） |
| MinerU | 复杂 PDF（表格、公式、多栏） |
| pdfplumber | PDF 表格提取 |

本课程第2周 Day13 会专门学习复杂 PDF 解析。

## Q7: 如何评估分块质量？

**答：**
三个评估维度：
1. **语义完整性**：每个块是否包含完整的语义单元（不截断关键信息）
2. **检索命中率**：用真实问题测试，检索到的块是否包含正确答案
3. **块大小分布**：检查是否有过多极小块（噪音）或极大块（精度差）

```python
# 快速检查分块质量
sizes = [len(c.page_content) for c in chunks]
print(f"最小: {min(sizes)}, 最大: {max(sizes)}, 平均: {sum(sizes)//len(sizes)}")
# 理想：最小 > 100，最大 < 1000，分布均匀
```

## Q8: 除了按字符数分块，还有哪些分块策略？

**答：**

| 策略 | 原理 | 适用场景 |
|------|------|----------|
| 按字符数 | chunk_size 控制块大小 | 通用 |
| 按语义 | 用 Embedding 相似度判断语义边界 | 高质量 RAG |
| 按文档结构 | 按 Markdown 标题、HTML 标签拆分 | 结构化文档 |
| 按 token 数 | 精确控制 LLM 输入 token | 成本敏感场景 |
| 按句子 | 保证每个块是完整句子 | 短问答 |

语义分块（SemanticChunker）是高级方案，本课程后续会涉及。
