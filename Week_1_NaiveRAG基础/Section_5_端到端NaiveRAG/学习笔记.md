# Section 5: 端到端 Naive RAG 学习笔记

## 核心概念

### RAG 全链路数据流
```
【索引阶段】
原始文档 → Document 对象 → RecursiveCharacterTextSplitter.split_documents()
         → 文本块列表 → Embedding → FAISS 向量库

【查询阶段】
用户提问 → Embedding → FAISS.search() → Top-K 相关文档
         → format_docs() 拼接 context → Prompt | GLM | Parser → 回答
```

### LCEL 链的写法
```python
rag_chain = (
    {"context": RunnablePassthrough() | (lambda q: retrieve(q)) | format_docs,
     "question": RunnablePassthrough()}
    | rag_prompt
    | llm
    | StrOutputParser()
)
```

数据流向：`question` 【按字典的键名传递匹配】同时走两条路：
- 左路：question → retrieve → format_docs → 填入 prompt 的 `{context}`
- 右路：question → 原样传递 → 填入 prompt 的 `{question}`
- 两路合并后 → prompt → llm → parser → 最终文本

## 关键组件

### 1. RecursiveCharacterTextSplitter
- `chunk_size=200`：每块最大 200 字符
- `chunk_overlap=40`：相邻块重叠 40 字符，避免语义断裂
- `split_documents(docs)`：接受 Document 列表，返回分块后的 Document 列表（自动保留 metadata）

### 2. Document 对象
```python
Document(page_content="文本内容", metadata={"source": "文件名"})
```
- LangChain 的标准文档格式，所有组件都认这个类型
- metadata 会随分块自动传递，不需要手动管理

### 3. FAISS 向量库
- `IndexFlatIP(dim)`：内积索引，归一化后等价于余弦相似度
- `faiss.normalize_L2(vectors)`：L2 归一化
- `index.search(query_vec, k)`：返回 (相似度数组, 索引数组)

### 4. RAG Prompt 设计
```
System: 你是知识库问答助手。只根据参考资料回答，没有就直说。回答简洁。
        参考资料：{context}
Human:  {question}
```
- "只根据参考资料回答" — 限制 LLM 不要编造
- "没有就直说" — 防止幻觉
- temperature=0.3 — RAG 需要稳定输出，不要创造性

## 设计决策

| 参数 | 选择 | 原因 |
|------|------|------|
| chunk_size | 200 | 太大→检索不精确，太小→语义不完整 |
| chunk_overlap | 40 | 防止句子在块边界被切断 |
| top_k | 3 | 太多引入噪声，太少可能遗漏 |
| temperature | 0.3 | RAG 要忠于文档，不需要创造性 |
| Embedding | 哈希模拟 | 教学用，第2周换真实模型 |
