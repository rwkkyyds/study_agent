# Section 5: 不理解的部分

## Q: LCEL 链中 dict 的 context 和 question 是怎么执行的？为什么 format_docs 的结果变成 context？

### 原始问题
```python
{"context": RunnablePassthrough() | (lambda q: retrieve(q)) | format_docs, "question": RunnablePassthrough()}
```
- 为什么 `context` 放最前面？
- 为什么 `format_docs` 的结果作为 `context`？

### 通俗解释

**1. dict 的 key 顺序不影响执行顺序。**
这个 dict 不是"从左到右执行"，而是声明了两个**并行分支**。`context` 和 `question` 同时执行。

**2. key 名字 = Prompt 模板的变量名。**
Prompt 里写了 `{context}` 和 `{question}`，LCEL 会按 key 名字自动填入：
- `context` 这个 key 的输出 → 填入 `{context}`
- `question` 这个 key 的输出 → 填入 `{question}`

**3. 为什么需要 format_docs？**
`retrieve()` 返回的是 `list[Document]` 对象，但 Prompt 的 `{context}` 需要的是**字符串**。LangChain 不会自动转换，所以需要 `format_docs` 把 Document 列表拼成字符串。

### 数据流图
```
输入 question="FastAPI有什么特点"
         │
    ┌────┴────┐（并行，不分先后）
    │         │
  context   question
    │         │
    │       原样传递 → 填入 {question}
    │
  retrieve(question) → [Document, Document, ...]
    │
  format_docs(docs) → "[fastapi.txt]\nFastAPI是...\n\n[langchain.txt]\nLangChain是..."
    │
    └→ 填入 {context}
```

### 配套代码
```python
# Prompt 模板定义了 {context} 和 {question} 两个占位符
rag_prompt = ChatPromptTemplate.from_messages([
    ("system", "参考资料：\n{context}"),
    ("human", "{question}"),
])

# dict 的 key 名字和占位符一一对应
rag_chain = (
    {"context": RunnablePassthrough() | (lambda q: retrieve(q)) | format_docs,
     "question": RunnablePassthrough()}
    | rag_prompt | llm | StrOutputParser()
)

# 调用时只传 question，链自动分流
rag_chain.invoke("FastAPI有什么特点")
```

### 易错点
- 以为 dict 的 key 顺序决定执行顺序 → 实际是并行的
- 以为 LangChain 会自动把 Document 转成字符串 → 必须自己写 `format_docs`
- 以为 `RunnablePassthrough()` 有什么特殊作用 → 它就是"原样传递"，占个位
