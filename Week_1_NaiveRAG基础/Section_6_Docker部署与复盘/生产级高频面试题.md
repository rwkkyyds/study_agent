# Section 6: Docker 部署 + 第1周复盘 高频面试题

## Docker 题

### Q1: Dockerfile 中为什么先 COPY requirements.txt 再 COPY app.py？
**答：** 利用 Docker 的层缓存机制。Docker 按层构建，每层有缓存。先复制 requirements.txt 并安装依赖，如果依赖没变，这一层直接用缓存。如果先复制所有代码，改一行代码就会导致缓存失效，重新安装所有依赖，构建很慢。

### Q2: docker run -p 8000:8000 是什么意思？
**答：** `-p 宿主机端口:容器端口`，把宿主机的 8000 端口映射到容器内的 8000 端口。外部访问 `localhost:8000` 就能到达容器内的 FastAPI 应用。

### Q3: CMD 和 ENTRYPOINT 的区别？
**答：**
- `CMD`：默认命令，可以被 `docker run` 后面的参数覆盖
- `ENTRYPOINT`：入口命令，不会被覆盖，`docker run` 的参数会追加到 ENTRYPOINT 后面
- 常见用法：`ENTRYPOINT ["python"]` + `CMD ["app.py"]`，这样 `docker run myimage test.py` 会执行 `python test.py`

### Q4: .dockerignore 的作用？
**答：** 类似 .gitignore，告诉 Docker 构建时忽略哪些文件。排除 .venv、__pycache__、.git 等可以减小镜像体积，加快构建速度。

## 第1周综合题

### Q5: 从零搭建一个 RAG 系统，你会怎么做？
**答：**
1. **文档处理**：用 RecursiveCharacterTextSplitter 分块（chunk_size=200, overlap=40）
2. **向量化**：用 Embedding 模型（OpenAI/BGE）把文本块转向量
3. **向量库**：FAISS（本地）或 Milvus（生产）存储向量
4. **检索**：用户提问→Embedding→向量检索 Top-K
5. **生成**：Prompt(问题+检索结果) → LLM → 回答
6. **API**：FastAPI 封装，Pydantic 校验请求/响应
7. **部署**：Docker 打包，一键部署

### Q6: RAG 系统中，哪些地方最容易出问题？
**答：**
| 环节 | 常见问题 | 解决方案 |
|------|---------|---------|
| 分块 | 块太大/太小，语义断裂 | 调 chunk_size/overlap，语义分块 |
| Embedding | 模型语义能力弱 | 换更强的模型（BGE/OpenAI） |
| 检索 | 关键词匹配不到 | 混合检索（向量+BM25） |
| 检索 | Top-K 结果质量差 | Rerank 重排 |
| Prompt | 约束不够，LLM 编造 | 加"只根据资料回答" |
| LLM | 模型能力不足 | 升级模型 |

### Q7: 如何评估 RAG 系统的效果？
**答：**
- **检索评估**：Top-K 命中率（检索到的文档是否包含答案）
- **生成评估**：回答准确性、相关性、忠实度
- **工具**：RAGAs、DeepEval（第2周学）
- **人工评估**：抽样检查回答质量
- **A/B 测试**：对比不同参数/模型的效果
