# Section 3: MCP 协议实战 - 生产级高频面试题

## 基础题

### Q1: MCP 是什么？解决了什么问题？

**答：**

MCP（Model Context Protocol）是 Anthropic 推出的开放协议，定义了 LLM 与工具/数据源之间的标准通信方式。

**解决的问题：**
- 传统方式：每个框架（LangChain、LlamaIndex、AutoGen）各自定义工具接口，换框架要重写
- MCP 方式：工具作为独立服务运行，通过统一协议通信，写一次，任何框架都能用

**类比：** USB-C 统一了充电/数据/视频接口，MCP 统一了 LLM ↔ 工具的通信接口。

---

### Q2: MCP Server 的两个核心装饰器是什么？

**答：**

```python
@server.list_tools()    # 注册工具列表处理器
async def handle_list_tools() -> list[types.Tool]:
    return [types.Tool(name=..., description=..., inputSchema=...)]

@server.call_tool()     # 注册工具调用处理器
async def handle_call_tool(name: str, arguments: dict) -> list[types.TextContent]:
    if name == "calculator":
        return [types.TextContent(type="text", text=str(eval(arguments["expression"])))]
```

- `list_tools`：返回工具定义（name + description + inputSchema），Client 靠它发现工具
- `call_tool`：处理工具调用请求，接收工具名和参数，返回执行结果

---

### Q3: MCP 的传输方式有哪些？

**答：**

| 传输方式 | 特点 | 适用场景 |
|---------|------|---------|
| stdio | 通过 stdin/stdout 通信，最简单 | 本地工具、CLI 集成 |
| SSE | Server-Sent Events，HTTP 长连接 | Web 应用、远程 Server |
| WebSocket | 双向通信 | 实时交互场景 |

**最常用的是 stdio**：Client 启动 Server 作为子进程，通过 stdin/stdout 交换 JSON-RPC 消息。

## 进阶题

### Q4: MCP 工具在 LangGraph 中使用时有什么坑？

**答：**

1. **异步问题**：MCP 工具是异步的（StructuredTool），LangGraph 的 `invoke` 是同步调用会报错。必须用 `ainvoke`。

2. **进程管理**：MCP Server 是独立进程，需要确保：
   - 进程正常启动和关闭
   - 超时处理（Server 卡死时能终止）
   - 错误处理（Server 崩溃时 Agent 不挂）

3. **工具名冲突**：连接多个 MCP Server 时，工具名可能冲突。用 `tool_name_prefix=True` 给工具名加前缀。

---

### Q5: MCP 和直接用 @tool 装饰器定义工具有什么区别？

**答：**

| 维度 | @tool 装饰器 | MCP |
|------|-------------|-----|
| 工具位置 | 和 Agent 代码在同一进程 | 独立进程/服务 |
| 语言限制 | Python only | 任何语言（只要实现 MCP 协议） |
| 复用性 | 仅限当前项目 | 任何 MCP Client 都能用 |
| 部署 | 和 Agent 一起部署 | 独立部署、独立扩展 |
| 适用场景 | 简单项目、快速原型 | 企业级、多项目复用 |

**一句话：** @tool 适合开发阶段，MCP 适合生产阶段。

---

### Q6: 怎么连接多个 MCP Server？

**答：**

```python
mcp_client = MultiServerMCPClient(
    connections={
        "filesystem": {
            "transport": "stdio",
            "command": "npx",
            "args": ["@modelcontextprotocol/server-filesystem", "/data"],
        },
        "github": {
            "transport": "stdio",
            "command": "npx",
            "args": ["@modelcontextprotocol/server-github"],
        },
    }
)

# 发现所有 Server 的工具
tools = await mcp_client.get_tools()
# tools 包含 filesystem 和 github 两个 Server 的所有工具
```

## 生产级场景题

### Q7: 生产环境中 MCP Server 怎么部署？

**答：**

1. **本地模式**：Server 作为子进程由 Client 启动（本节 Demo 的方式）
   - 优点：简单，无需额外部署
   - 缺点：每个 Client 实例启动一个 Server 进程

2. **远程模式**：Server 作为独立服务运行，Client 通过 SSE/WebSocket 连接
   - 优点：多 Client 共享一个 Server，可独立扩展
   - 缺点：需要处理网络超时、重连、认证

3. **容器化**：Docker 部署 MCP Server，Docker Compose 编排多个 Server

**推荐：** 开发阶段用 stdio 本地模式，生产环境用 SSE 远程模式 + Docker 部署。

### Q8: MCP 的 inputSchema 是什么格式？有什么用？

**答：**

inputSchema 是 **JSON Schema** 格式，定义工具的输入参数。

```json
{
    "type": "object",
    "properties": {
        "expression": {
            "type": "string",
            "description": "数学表达式"
        }
    },
    "required": ["expression"]
}
```

**作用：**
1. Client 靠它知道怎么传参（参数名、类型、是否必填）
2. Server 靠它做输入校验（调用前验证参数合法性）
3. LLM 靠它生成正确的 tool_call（知道要传什么参数）
