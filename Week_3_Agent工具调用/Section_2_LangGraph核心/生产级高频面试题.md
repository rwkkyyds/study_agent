# Section 2: LangGraph 核心概念 - 生产级高频面试题

## 基础题

### Q1: LangGraph 和 LangChain Agent（create_agent）有什么区别？

**答：**

| 维度 | create_agent | LangGraph |
|------|-------------|-----------|
| 定义方式 | 一行代码，黑盒 | 手动定义图结构，白盒 |
| 灵活性 | 低，无法自定义推理流程 | 高，每个节点/边都可自定义 |
| 状态管理 | 无显式 State | TypedDict 定义 State，所有节点共享 |
| 条件路由 | 不支持 | 支持 Conditional Edge |
| 人工审批 | 不支持 | 支持 Human-in-the-Loop |
| 状态持久化 | 不支持 | 支持 Checkpointer（SQLite/PostgreSQL） |
| 适用场景 | 简单的单 Agent 任务 | 复杂工作流、多 Agent 协作、需要人工介入 |

**一句话总结：** create_agent 适合快速原型，LangGraph 适合生产级复杂场景。

---

### Q2: LangGraph 的 State 是什么？为什么用 Annotated[list, operator.add]？

**答：**

State 是图中流动的数据，所有 Node 都能读取和更新。

```python
class AgentState(TypedDict):
    messages: Annotated[list[BaseMessage], operator.add]
```

- 普通 TypedDict：Node 返回的字段会**覆盖**原值
- `Annotated[list, operator.add]`：Node 返回的列表会**追加**到原列表

为什么需要追加？因为 Agent 的消息历史是累积的：
- 第1轮：`[HumanMessage, AIMessage(tool_call), ToolMessage, AIMessage]`
- 第2轮追加新的消息，而不是覆盖之前的消息

### Q3: Conditional Edge 是怎么工作的？

**答：**

Conditional Edge 是根据 State 内容动态决定下一步走哪个节点的机制。

```python
def should_continue(state) -> str:
    last_message = state["messages"][-1]
    if last_message.tool_calls:
        return "tools"    # 有工具调用 → 去执行工具
    return "end"          # 无工具调用 → 结束

graph.add_conditional_edges(
    "agent",              # 从 agent 节点出发
    should_continue,      # 路由函数
    {"tools": "tools", "end": END}  # 返回值 → 目标节点映射
)
```

路由函数的返回值必须是映射表中的 key，否则报错。

## 进阶题

### Q4: LangGraph 的消息链是怎么累积的？画出问题3的消息流转。

**答：**

问题3："现在几点了？另外帮我算一下 2 的 20 次方"

```
轮次1: Agent Node → LLM 决定调用 get_current_time
  messages: [HumanMessage, AIMessage(tool_call: get_current_time)]

轮次2: Tool Node → 执行 get_current_time → 返回时间
  messages: [HumanMessage, AIMessage(tool_call), ToolMessage("2026-06-12...")]

轮次3: Agent Node → LLM 决定调用 calculator
  messages: [HumanMessage, AIMessage(tool_call), ToolMessage, AIMessage(tool_call: calculator)]

轮次4: Tool Node → 执行 calculator → 返回 1048576
  messages: [..., AIMessage(tool_call), ToolMessage("1048576")]

轮次5: Agent Node → LLM 决定直接回答
  messages: [..., ToolMessage, AIMessage("当前时间是...2的20次方等于1048576")]
```

共 5 轮，6 条消息。每轮 Agent Node 和 Tool Node 交替执行，messages 通过 `operator.add` 自动追加。

### Q5: 如果 Agent 陷入无限循环（反复调用工具不停止）怎么办？

**答：**

LangGraph 提供了几种防护机制：

1. **recursion_limit 参数**：`compiled.invoke(state, {"recursion_limit": 10})`
   - 超过限制自动抛出 GraphRecursionError

2. **在 Conditional Edge 中加判断**：
   ```python
   def should_continue(state):
       if len(state["messages"]) > 20:
           return "end"  # 强制结束
       # 正常逻辑...
   ```

3. **在 System Prompt 中约束 LLM**：明确告诉 LLM 何时停止调用工具

### Q6: LangGraph 怎么实现 Human-in-the-Loop（人工审批）？

**答：**

在 Conditional Edge 中加入一个"等待人工审批"的节点：

```python
def need_approval(state) -> str:
    # 判断是否需要人工审批（比如涉及删除操作）
    last_message = state["messages"][-1]
    if last_message.tool_calls:
        for tc in last_message.tool_calls:
            if tc["name"] in ["delete_file", "send_email"]:
                return "human_approval"
    return "tools"

graph.add_conditional_edges("agent", need_approval, {
    "human_approval": "human_approval_node",
    "tools": "tools"
})
```

人工审批节点可以暂停图的执行，等待人工确认后继续。LangGraph 的 Checkpointer 机制支持状态持久化，暂停后可以从断点恢复。

### Q7: ToolNode 是什么？可以自己写一个吗？

**答：**

ToolNode 是 LangGraph 内置的节点，负责：
1. 从 AIMessage 中提取 tool_calls
2. 逐一执行对应的工具函数
3. 将结果封装为 ToolMessage 返回

自己实现：
```python
def custom_tool_node(state: AgentState) -> dict:
    last_message = state["messages"][-1] 
    # eg: AIMessage(tool_calls=[{"name": "calculator", "args": {"expression": "2**20"}, "id": "123"}])
    results = []
    for tool_call in last_message.tool_calls:
        # 根据 tool_call["name"] 找到对应工具
        tool = {t.name: t for t in TOOLS}[tool_call["name"]]
        # 执行工具
        result = tool.invoke(tool_call["args"])
        results.append(ToolMessage(content=str(result), tool_call_id=tool_call["id"]))
    return {"messages": results}
```

实际项目中用 ToolNode 即可，不需要自己写。

## 生产级场景题

### Q8: 生产环境中 LangGraph Agent 需要做哪些防护？

**答：**

1. **递归限制**：`recursion_limit` 防止无限循环
2. **超时控制**：每个 Node 加 timeout，防止 LLM 或工具卡死
3. **异常捕获**：Tool Node 中每个工具调用都 try-except，单个工具失败不影响整体
4. **日志记录**：每个 Node 入口/出口记录日志，方便排查
5. **状态持久化**：用 Checkpointer 将 State 存入 Redis/PostgreSQL，支持断点恢复
6. **Token 限制**：监控 messages 列表长度，超过阈值时截断或摘要压缩历史消息
7. **速率限制**：对 LLM 调用加限流，防止触发 API 限流

### Q9: LangGraph 和 AutoGen/CrewAI 的区别？

**答：**

| 维度 | LangGraph | AutoGen | CrewAI |
|------|-----------|---------|--------|
| 核心思想 | 用图定义工作流 | 多 Agent 对话 | 角色扮演协作 |
| 控制粒度 | 最细（节点/边级别） | 中等 | 最粗（角色/任务级别） |
| 状态管理 | 显式 State + Checkpointer | 隐式消息传递 | 隐式 |
| 人工介入 | 原生支持 | 需自己实现 | 不支持 |
| 生态 | LangChain 生态 | 独立 | 独立 |
| 企业采用率 | 最高（2025-2026） | 下降中 | 低 |
| 适用场景 | 复杂工作流 | 多 Agent 对话 | 简单多角色任务 |

**面试建议：** 重点掌握 LangGraph，AutoGen/CrewAI 了解即可。
