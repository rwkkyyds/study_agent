# Section 2: LangGraph 核心概念 - 学习笔记

## 1. LangGraph 是什么

LangGraph 是 LangChain 团队推出的 Agent 框架，核心思想：**用有向图（Graph）显式定义 Agent 工作流**。

```
LangChain Agent（旧）：         LangGraph（新）：
  LLM 自己决定调用什么工具          你用"图"定义工作流
  → 黑盒，难以控制               → 白盒，完全可控
  → 简单场景够用                 → 复杂场景必须用
```

**为什么需要 LangGraph？**
- `create_agent` 是黑盒：LLM 自己决定调什么工具、什么时候停
- LangGraph 是白盒：你定义每个节点做什么、条件怎么判断、循环怎么走
- 复杂场景（多 Agent 协作、人工审批、状态持久化）必须用 LangGraph

## 2. StateGraph 四大要素

### 2.1 State（状态）

```python
class AgentState(TypedDict):
    messages: Annotated[list[BaseMessage], operator.add]
```

- State 是图中流动的数据，类似"全局变量"
- 所有 Node 都能读取 State、返回 State 的更新部分
- `Annotated[list, operator.add]` 表示"追加"而非"覆盖"

### 2.2 Node（节点）

```python
def agent_node(state: AgentState) -> dict:
    response = llm.invoke(state["messages"])
    return {"messages": [response]}  # 只返回要更新的字段
```

- Node 是处理函数：读 State → 计算 → 返回更新
- 只需要返回要更新的字段，LangGraph 自动合并到 State

### 2.3 Edge（边）

```python
graph.add_edge(START, "agent")      # START → agent
graph.add_edge("tools", "agent")    # tools → agent（循环）
```

- 定义节点之间的固定执行顺序

### 2.4 Conditional Edge（条件边）

```python
def should_continue(state: AgentState) -> str:
    last_message = state["messages"][-1]
    if last_message.tool_calls:
        return "tools"
    return "end"

graph.add_conditional_edges(
    "agent",                    # 从哪个节点出发
    should_continue,            # 路由函数
    {"tools": "tools", "end": END}  # 返回值 → 目标节点
)
```

- 根据 State 内容动态决定走哪条路
- 路由函数返回的字符串必须与映射表的 key 匹配

## 3. LangGraph ReAct Agent 架构

```
START
  │
  ▼
Agent Node ←──────────┐
  │                    │
  ▼                    │
Conditional Edge       │
  │                    │
  ├─ "tools" ──→ Tool Node ─┘  （循环：有工具调用就继续）
  │
  └─ "end" ──→ END             （结束：无工具调用）
```

**执行流程：**
1. 用户输入 → Agent Node 调用 LLM
2. LLM 返回：带 tool_calls（要调用工具）或不带（直接回答）
3. Conditional Edge 检查最后一条消息
4. 有 tool_calls → Tool Node 执行工具 → 结果追加到 messages → 回到 Agent Node
5. 无 tool_calls → END

## 4. 关键 API 速查

| API | 用途 |
|-----|------|
| `StateGraph(StateType)` | 创建状态图 |
| `graph.add_node("name", func)` | 添加节点 |
| `graph.add_edge(START, "name")` | 添加固定边 |
| `graph.add_conditional_edges(src, router, mapping)` | 添加条件边 |
| `graph.compile()` | 编译图，返回可调用对象 |
| `compiled.invoke(initial_state)` | 运行图 |
| `ToolNode(tools)` | LangGraph 内置的工具执行节点 |
| `llm.bind_tools(tools)` | 让 LLM 知道有哪些工具可用 |

## 5. 与 create_agent 对比

| 维度 | create_agent | LangGraph |
|------|-------------|-----------|
| 代码量 | 1 行 | 20-30 行 |
| 灵活性 | 低（黑盒） | 高（白盒） |
| 自定义节点 | 不支持 | 支持 |
| 条件路由 | 不支持 | 支持 |
| 状态持久化 | 不支持 | 支持（Checkpointer） |
| 人工审批 | 不支持 | 支持（Human-in-the-Loop） |
| 适用场景 | 简单 Agent | 复杂工作流、多 Agent |

## 6. State 的 Annotated[list, operator.add] 详解

```python
messages: Annotated[list[BaseMessage], operator.add]
```

- 普通 TypedDict：返回值会**覆盖**原字段
- `Annotated[list, operator.add]`：返回值会**追加**到列表
- Agent Node 返回 `[AIMessage]` → messages 列表自动追加
- Tool Node 返回 `[ToolMessage]` → messages 列表自动追加
- 这样每轮对话的消息历史自动累积，不需要手动管理
