# Section 1 面试题：Agent 核心概念与 ReAct 框架

## 基础题

### 1. 什么是 Agent？和普通 LLM 调用有什么区别？

**答：**
- **普通 LLM**：用户问题 → LLM → 回答（一次调用，无外部工具）
- **Agent**：用户问题 → LLM 思考 → 调用工具 → 观察结果 → 继续思考 → ... → 回答

Agent = LLM（大脑） + Tools（手脚） + 推理循环。核心区别：Agent 能**自主决策**调用什么工具、何时调用，而不是一次性回答。

---

### 2. ReAct 框架是什么？每一步做什么？

**答：**
ReAct = Reasoning + Acting，每一步包含三个阶段：

1. **Thought**：LLM 思考当前状态，决定下一步行动
2. **Action**：调用工具执行操作
3. **Observation**：获取工具返回的结果

循环直到 LLM 认为已有足够信息，给出最终回答。

---

### 3. @tool 装饰器的作用是什么？docstring 为什么重要？

**答：**
`@tool` 将普通 Python 函数转为 Agent 可调用的工具。

docstring 重要是因为 **Agent 根据 docstring 决定何时调用这个工具**。如果 docstring 写得不清楚，Agent 可能选错工具或不知道什么时候用它。

---

## 进阶题

### 4. Agent 和 RAG 是什么关系？能结合使用吗？

**答：**
可以结合。RAG 可以作为 Agent 的一个工具：

```python
@tool
def rag_search(query: str) -> str:
    """查询知识库获取相关信息"""
    return rag_chain.invoke(query)
```

区别：
- RAG 是被动的：总是先检索再回答
- Agent 是主动的：自主决定是否需要检索，还是直接用其他工具

---

### 5. Agent 的推理循环可能出什么问题？怎么处理？

**答：**

| 问题 | 解决方案 |
|------|----------|
| 无限循环 | 设置 max_iterations 限制 |
| 工具选错 | 优化 tool 的 docstring 描述 |
| 参数传错 | 明确参数类型注解和示例 |
| 工具报错 | 工具内部 try-except，返回错误信息 |
| 成本过高 | 限制循环次数 + 选择便宜的模型 |

---

### 6. 生产环境如何选择 Agent 框架？

**答：**

| 框架 | 特点 | 适用场景 |
|------|------|----------|
| LangChain create_agent | 简单易用，一行代码 | 快速原型、简单 Agent |
| LangGraph | 状态图，精细控制流 | 复杂多步 Agent |
| OpenAI Function Calling | 原生支持，最稳定 | 只用 OpenAI 模型时 |
| AutoGen / CrewAI | 多 Agent 协作 | 多智能体系统 |

---

## 生产实践题

### 7. 如何调试 Agent 的推理过程？

**答：**
1. **verbose=True**：打印每步 Thought/Action/Observation
2. **LangSmith**：链路追踪，可视化每步调用
3. **日志记录**：记录每轮推理的输入输出
4. **回放测试**：固定问题，验证推理路径一致性

---

### 8. Agent 的工具设计有什么最佳实践？

**答：**
1. **单一职责**：每个工具只做一件事
2. **描述清晰**：docstring 说明用途、输入格式、使用场景
3. **错误处理**：返回错误信息而非抛异常
4. **返回字符串**：统一返回 str，方便 LLM 理解
5. **幂等性**：相同输入相同输出，避免副作用
6. **超时控制**：外部 API 调用设置超时
