# Section 1 学习笔记：Agent 核心概念与 ReAct 框架

## 1. Agent 的本质

```
传统 LLM：用户问题 → LLM → 回答（一次调用，无工具）

Agent：  用户问题 → LLM 思考 → 调用工具 → 观察结果 → 继续思考 → ... → 最终回答
         ↑_________________________循环_________________________↑
```

**Agent = LLM（大脑） + Tools（手脚） + 推理循环（工作流）**

| 组件 | 作用 | 类比 |
|------|------|------|
| LLM | 理解问题、决策调用哪个工具 | 大脑 |
| Tools | 执行具体操作（计算、搜索、API调用） | 手脚 |
| 推理循环 | 控制思考→行动→观察的循环 | 工作流程 |

## 2. ReAct 框架

ReAct = **Re**asoning + **Act**ing

### 推理过程示例

```
用户问题: "北京今天多少度？"

Thought: 我需要查询北京今天的天气，应该用天气查询工具
Action:  weather_search("北京")
Observation: 北京今天 28°C，晴

Thought: 我已经知道了温度，可以回答用户了
Action:  给出最终回答
Answer:  北京今天 28°C，天气晴朗。
```

### ReAct vs 纯推理 vs 纯行动

| 模式 | 特点 | 问题 |
|------|------|------|
| 纯推理 (Reasoning) | LLM 直接回答，不调用工具 | 容易幻觉，无法获取实时信息 |
| 纯行动 (Acting) | 直接调用工具，不做思考 | 可能调错工具，无法处理复杂问题 |
| **ReAct** | 思考→行动→观察 循环 | 最佳：有计划地使用工具 |

## 3. LangChain Agent 架构

```python
# langchain 1.3.x 的 Agent 架构
agent = create_agent(
    model=llm,           # 大脑：ChatOpenAI
    tools=tools,         # 手脚：@tool 装饰器定义的工具
    system_prompt=...,   # 行为指导：告诉 Agent 如何思考
)
# 返回 CompiledStateGraph，可直接 invoke
```

### 内部工作流程

```
用户输入
    ↓
LLM 思考（Thought）
    ↓
是否需要调用工具？
    ├── 是 → 调用工具（Action）→ 获取结果（Observation）→ 回到 LLM 思考
    └── 否 → 直接输出最终回答
```

## 4. 工具定义（@tool 装饰器）

```python
@tool
def calculator(expression: str) -> str:
    """计算数学表达式。支持加减乘除、幂运算等。"""
    result = eval(expression)
    return str(result)
```

**关键点：**
- `@tool` 装饰器将普通函数转为 Agent 可调用的工具
- **docstring 是 Agent 决策的依据**：Agent 根据 docstring 判断何时调用这个工具
- 参数名和类型注解帮助 Agent 正确传参

### 工具设计原则

| 原则 | 说明 |
|------|------|
| 单一职责 | 每个工具只做一件事 |
| 描述清晰 | docstring 要说明用途和输入格式 |
| 错误处理 | 工具内部处理异常，返回错误信息而非崩溃 |
| 返回字符串 | 工具返回值统一为字符串，方便 LLM 理解 |

## 5. Agent 与 RAG 的关系

```
RAG：  用户问题 → 检索 → LLM 生成 → 回答
       （被动：总是先检索再回答）

Agent：用户问题 → LLM 思考 → 决定是否调用工具 → ... → 回答
       （主动：自主决定何时用什么工具）
```

**Agent 可以包含 RAG 作为工具：**
```python
@tool
def rag_search(query: str) -> str:
    """查询知识库获取相关信息"""
    # 内部调用 RAG 链路
    return rag_chain.invoke(query)
```

## 6. create_agent 新 API（langchain 1.3.x）

```python
from langchain.agents import create_agent

agent = create_agent(
    model="openai:gpt-4",           # 或 ChatOpenAI 实例
    tools=[tool1, tool2],           # 工具列表
    system_prompt="你是一个...",     # 行为指导
)

# 调用
result = agent.invoke({"messages": [("human", "用户问题")]})
final_answer = result["messages"][-1].content
```

**与旧 API 的区别：**

| 对比 | 旧 API (AgentExecutor) | 新 API (create_agent) |
|------|----------------------|----------------------|
| 创建方式 | create_tool_calling_agent + AgentExecutor | create_agent 一行搞定 |
| 底层 | 自定义循环 | langgraph StateGraph |
| 状态管理 | 手动 | 自动 |
| 生产推荐 | 已过时 | 推荐 |

## 7. Agent 的局限性

| 局限 | 说明 |
|------|------|
| 推理延迟 | 多轮 LLM 调用，比单次 RAG 慢 |
| 工具选择错误 | LLM 可能选错工具或传错参数 |
| 无限循环 | 需要 max_iterations 限制 |
| 成本高 | 每轮推理都消耗 token |
| 不确定性 | 同一问题可能走不同的推理路径 |
