## Q1: 用 LangGraph 构建 Agent 的核心步骤是什么？

**答：** 四步：
1. **定义 State**：`AgentState(TypedDict)` + `Annotated[list, operator.add]`
2. **Agent Node**：`llm.bind_tools(TOOLS).invoke(messages)` 让 LLM 决策
3. **Conditional Edge**：`should_continue` 检查 `tool_calls`，有则去 tools，无则结束
4. **图组装**：`StateGraph` + `add_node` + `add_edge` + `add_conditional_edges`

```python
graph = StateGraph(AgentState)
graph.add_node("agent", agent_node)
graph.add_node("tools", ToolNode(TOOLS))
graph.add_edge(START, "agent")
graph.add_conditional_edges("agent", should_continue, {"tools": "tools", "end": END})
graph.add_edge("tools", "agent")
```

## Q2: LangGraph 的 StateGraph 和 LangChain 的 create_agent 有什么区别？

**答：**

| 维度 | create_agent | StateGraph |
|------|-------------|------------|
| 复杂度 | 一行代码 | 手动定义每个节点和边 |
| 灵活性 | 低（黑盒） | 高（完全可控） |
| 自定义 | 有限 | 可加日志/重试/降级/多工具 |
| 学习价值 | 快速原型 | 理解 Agent 底层原理 |
| 生产推荐 | 简单场景 | 复杂场景（推荐） |

## Q3: `llm.bind_tools(TOOLS)` 做了什么？

**答：** 把工具的名称、描述、参数 schema 注入到 LLM 的 system prompt 中，让 LLM 知道有哪些工具可用。LLM 根据用户问题的语义，自主决定调用哪个工具、传什么参数。

```python
llm = ChatOpenAI(model="glm-4-flash")
llm_with_tools = llm.bind_tools([web_search, knowledge_search, sql_query])
response = llm_with_tools.invoke(messages)
# response.tool_calls → [{"name": "web_search", "args": {"query": "..."}}]
```

## Q4: `should_continue` 条件路由的判断逻辑是什么？

**答：** 检查最后一条消息是否有 `tool_calls`：

```python
def should_continue(state):
    last = state["messages"][-1]
    if isinstance(last, AIMessage) and last.tool_calls:
        return "tools"   # 有工具调用 → 去执行
    return "end"          # 无工具调用 → 结束
```

## Q5: ToolNode 和自定义 tool_node 有什么区别？

**答：**
- **ToolNode**：LangGraph 预构建节点，自动执行所有 `tool_calls`，内置错误处理
- **自定义 tool_node**：手动遍历 `tool_calls`，可加重试、降级、日志等逻辑

简单场景用 ToolNode，需要容错（Section 6）时用自定义。

## Q6: MemorySaver 如何实现多轮对话？

**答：**
1. `compile(checkpointer=memory)` 启用 Checkpoint
2. `invoke(state, config={"configurable": {"thread_id": "xxx"}})` 指定会话
3. 每次调用自动保存/恢复 State，消息历史累积

```python
memory = MemorySaver()
agent = graph.compile(checkpointer=memory)
config = {"configurable": {"thread_id": "user_001"}}
agent.invoke({"messages": [HumanMessage(content="...")]}, config=config)
```

## Q10: `operator.add` 在 State 中的作用是什么？

**答：** `Annotated[list[BaseMessage], operator.add]` 表示 messages 字段的更新方式是**追加**而非覆盖。每个节点返回 `{"messages": [new_msg]}` 时，new_msg 会追加到现有列表，保留完整消息历史。如果不加 `operator.add`，每次返回会覆盖之前的消息。
