# Section 4: PostgreSQL 基础 - 生产级高频面试题

## 基础题

### Q1: SQLAlchemy 的 Session 和 Engine 有什么区别？

**答：**

- **Engine**：数据库连接池，管理实际的数据库连接。全局只需一个。
- **Session**：数据库会话，是 Engine 上的"工作区"。每个请求创建一个 Session，跟踪所有变更，commit 提交，rollback 回滚。

类比：Engine 是工厂，Session 是工厂里的工位。工位上可以做多件事（增删改查），最后一次性提交（commit）或全部撤销（rollback）。

### Q2: SQLAlchemy 2.x 的 Model 定义方式是什么？

**答：**

```python
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column

class Base(DeclarativeBase):
    pass

class User(Base):
    __tablename__ = "users"
    id: Mapped[int] = mapped_column(Integer, primary_key=True)
    name: Mapped[str] = mapped_column(String(50), nullable=False)
```

与旧版区别：
- 旧版（1.x）：`Column(Integer, primary_key=True)`
- 新版（2.x）：`Mapped[int] = mapped_column(Integer, primary_key=True)`
- 新版有完整的类型提示，IDE 友好

### Q3: Pydantic Schema 和 SQLAlchemy Model 为什么要分离？

**答：**

两者职责不同：

| 维度 | SQLAlchemy Model | Pydantic Schema |
|------|-----------------|-----------------|
| 职责 | 数据库表结构 | API 请求/响应格式 |
| 字段 | 包含所有字段（含密码哈希） | 只暴露必要字段 |
| 校验 | 数据库约束 | Pydantic 校验 |
| 使用场景 | Session 操作 | FastAPI 路由 |

如果不分离：密码哈希会暴露给前端，请求字段和数据库字段混在一起。

## 进阶题

### Q4: 什么是软删除？什么时候用？

**答：**

软删除 = 不真正删除数据，而是标记 `is_active=False` 或 `deleted_at=时间戳`。

```python
# 硬删除（不可恢复）
session.delete(user)

# 软删除（可恢复）
user.is_active = False
session.commit()
```

适用场景：用户数据有关联数据（订单、日志），硬删除会导致外键约束报错或数据丢失。查询时加 `filter(User.is_active == True)` 即可过滤已删除数据。

### Q5: FastAPI 的 Depends(get_db) 是怎么工作的？

**答：**

```python
def get_db():
    db = Session(engine)
    try:
        yield db        # ← yield 期间请求处理中
    finally:
        db.close()      # ← 请求结束后自动关闭

@app.post("/register")
def register(data: UserCreate, db: Session = Depends(get_db)):
    ...
```

流程：请求进入 → FastAPI 调用 `get_db()` → `yield db` 暂停 → 路由函数使用 db → 路由结束 → `finally` 关闭 db

好处：每个请求独立 Session，不会连接泄漏，不会并发冲突。

### Q6: 事务的 ACID 是什么？

**答：**

- **A (Atomicity)**：原子性，事务中的操作要么全部成功，要么全部回滚
- **C (Consistency)**：一致性，事务前后数据满足所有约束
- **I (Isolation)**：隔离性，并发事务互不干扰
- **D (Durability)**：持久性，事务提交后数据永久保存

SQLAlchemy 的 Session 自动管理事务：`commit()` = 全部成功，`rollback()` = 全部撤销。

## 生产级场景题

### Q7: 生产环境数据库连接池怎么配置？

**答：**

```python
engine = create_engine(
    DATABASE_URL,
    pool_size=20,        # 连接池大小（常驻连接数）
    max_overflow=10,     # 允许额外创建的连接数
    pool_timeout=30,     # 获取连接超时（秒）
    pool_recycle=3600,   # 连接回收时间（防止数据库断开）
    pool_pre_ping=True,  # 使用前检测连接是否有效
)
```

- `pool_size`：并发量大就调大，但不要超过数据库的 `max_connections`
- `pool_pre_ping=True`：防止长时间空闲连接被数据库断开后报错

### Q8: 什么时候用 Alembic 迁移？什么时候直接 create_all？

**答：**

| 方式 | 适用场景 | 优点 | 风险 |
|------|---------|------|------|
| `create_all()` | 开发/测试、Demo | 快速、简单 | 已有表无法更新，无版本记录，多人冲突 |
| Alembic 迁移 | 生产环境 | 版本控制、可回滚、多人协作 | 需要维护迁移脚本 |

**原则：Demo 用 create_all()，生产必须用 Alembic。**

#### 生产环境完整流程

```bash
# 1️⃣ 初始化迁移（项目开始时做一次）
alembic init alembic

# 2️⃣ 配置数据库连接（编辑 alembic/env.py）
from myapp.models import Base
target_metadata = Base.metadata

# 3️⃣ 修改 Model
class User(Base):
    phone: Mapped[str] = mapped_column(String(20))  # ← 新加字段

# 4️⃣ 生成迁移脚本（自动对比 Model 和数据库差异）
alembic revision --autogenerate -m "add phone column"
# → 生成 alembic/versions/001_add_phone_column.py

# 5️⃣ 人工审查脚本（确保没有问题）
cat alembic/versions/001_add_phone_column.py

# 6️⃣ 执行迁移
alembic upgrade head
# → 应用所有迁移脚本到数据库

# 7️⃣ 如果有问题，回滚
alembic downgrade -1     # 回滚上一步
alembic downgrade 001    # 回滚到版本 001
```

#### 常用命令

| 命令 | 含义 | 示例 |
|------|------|------|
| `alembic init` | 初始化迁移目录 | `alembic init alembic` |
| `revision --autogenerate` | 自动生成迁移脚本 | `alembic revision --autogenerate -m "add users"` |
| `upgrade` | 应用迁移到指定版本 | `alembic upgrade head` 应用全部 |
| `downgrade` | 回滚迁移 | `alembic downgrade -1` 回滚一步 |
| `current` | 查看当前版本 | `alembic current` |
| `history` | 查看迁移历史 | `alembic history --verbose` |

#### 多人协作流程

```bash
# A 同学修改 Model，生成迁移脚本
$ alembic revision --autogenerate -m "add email field"
$ git add alembic/versions/
$ git commit -am "add email migration"
$ git push

# B 同学拉取代码
$ git pull

# B 同学执行迁移
$ alembic upgrade head
# → 自动执行所有未应用的迁移脚本
```

#### 生成的迁移脚本示例

```python
# alembic/versions/001_add_users_table.py
from alembic import op
import sqlalchemy as sa

def upgrade():
    """应用这个迁移（向上升级）"""
    op.create_table(
        'users',
        sa.Column('id', sa.Integer(), nullable=False),
        sa.Column('name', sa.String(50), nullable=False),
        sa.Column('phone', sa.String(20), nullable=True),
        sa.PrimaryKeyConstraint('id')
    )

def downgrade():
    """回滚这个迁移（向下回滚）"""
    op.drop_table('users')
```

**绝对不要在生产环境用 `create_all()`——会导致：**
- ❌ 已有表不会自动更新
- ❌ 无法追踪版本历史
- ❌ 多人协作时无法同步
- ❌ 遇到问题无法安全回滚
