# Section 6 生产级高频面试题：异常处理与降级

---

## Q1: Agent 工具调用失败时应该怎么处理？

**答：** 三级容错体系：
1. **异常捕获**：try-except 包裹工具执行，防止 Agent 崩溃
2. **自动重试**：对临时性异常（超时、限流）用指数退避重试
3. **优雅降级**：重试失败后切换 Fallback 工具，返回部分结果

关键是错误信息要返回给 LLM，让它决定下一步策略。

---

## Q2: 什么是指数退避？为什么不用固定间隔重试？

**答：**
- **指数退避**：第1次等1s，第2次等2s，第3次等4秒，每次等待时间翻倍
- **不用固定间隔的原因**：如果服务还没恢复，固定间隔重试会持续给服务压力
- **加随机抖动（Jitter）**：避免多个客户端同时重试（雷群效应），请求分散到达

```python
# tenacity 实现
@retry(wait=wait_exponential(min=1, max=10))
```

## Q3: 哪些异常应该重试，哪些不应该？

**答：**

| 应该重试 | 不应该重试 |
|---------|-----------|
| TimeoutError（超时） | 400 Bad Request（参数错误） |
| 429 Too Many Requests（限流） | 403 Forbidden（权限不足） |
| 502/503（服务暂时不可用） | 404 Not Found（资源不存在） |
| ConnectionError（网络抖动） | 工具不存在（LLM 幻觉） |

原则：**临时性错误重试，永久性错误不重试。**

---

## Q4: 如何设计 Fallback 工具链？

**答：**
1. **注册表模式**：维护主工具 → 备用工具的映射关系
2. **逐级降级**：功能从强到弱，稳定性从低到高
3. **示例**：
   ```
   web_search（实时但不稳定）
     → cache_search（缓存，较稳定但可能过期）
       → static_faq（静态兜底，最稳定但功能最弱）
   ```
4. **信息透明**：告诉用户结果来自哪个数据源

---

## Q5: 在 LangGraph 中如何实现条件降级路由？

**答：** 用 `add_conditional_edges` 根据降级等级路由：

```python
graph.add_conditional_edges(
    "tool_call",
    lambda state: "normal" if state["level"] == 0 else "degraded",
    {"normal": "normal_response", "degraded": "degraded_response"}
)
```

State 中记录降级等级（0=正常, 1=重试成功, 2=使用Fallback, 3=全部失败），不同等级走不同回复路径。

---

## Q6: 如何处理 LLM 幻觉调用不存在的工具？

**答：**
1. 在工具调用节点中检查 `tools_by_name` 字典
2. 工具不存在时返回明确错误信息：
   ```python
   tool_func = tools_by_name.get(tool_name)
   if tool_func is None:
       return ToolMessage(content=f"[ERROR] 工具 '{tool_name}' 不存在")
   ```
3. 错误信息返回给 LLM，它通常会换一个存在的工具重试

## Q7: tenacity 库的核心参数有哪些？

**答：**
- `retry`：指定哪些异常需要重试（`retry_if_exception_type`）
- `stop`：停止条件（`stop_after_attempt(3)` 最多3次）
- `wait`：等待策略（`wait_exponential(min=1, max=10)` 指数退避）
- `before_sleep`：每次重试前的回调（记录日志）

---

## Q8: 生产环境中重试/降级的监控指标有哪些？

**答：**
- **重试率**：重试次数 / 总调用次数（过高说明工具不稳定）
- **降级率**：降级次数 / 总调用次数（过高说明主工具需要修复）
- **P99 延迟**：重试会拉高延迟，需要监控
- **工具成功率**：每个工具的成功/失败比例
- **Fallback 工具使用频率**：哪个 Fallback 用得最多

可以用 Prometheus counter 记录，Grafana 展示。

---

## Q9: 重试和降级有什么区别？什么时候用哪个？

**答：**

| 维度 | 重试 | 降级 |
|-----|------|------|
| 目的 | 给临时故障恢复的机会 | 主方案不可用时提供替代 |
| 时机 | 异常发生后立即尝试 | 重试失败后才触发 |
| 工具 | 同一个工具再调一次 | 换一个备用工具 |
| 结果 | 完全一致的结果 | 可能是功能较弱的结果 |

流程：异常 → 重试 → 降级，层层递进。

---

## Q10: 设计一个完整的容错 Agent 需要考虑什么？

**答：**
1. **异常分类**：区分可恢复和不可恢复的错误
2. **重试策略**：指数退避 + 抖动 + 最大次数
3. **Fallback 注册**：主工具 → 备用工具映射
4. **状态追踪**：State 中记录错误、重试次数、降级等级
5. **条件路由**：根据状态选择不同回复路径
6. **信息透明**：告知用户结果的可靠性
7. **监控告警**：重试率、降级率超过阈值告警
8. **超时控制**：每个工具调用必须有 timeout
