# Section 6 面试题：Advanced RAG 系统

## 基础题

### 1. Naive RAG 和 Advanced RAG 的核心区别是什么？

**答：**
- **Naive RAG**：用户问题 → 向量检索 Top-K → 直接丢给 LLM 回答
- **Advanced RAG**：用户问题 → 混合检索(BM25+向量) → RRF 融合 → Rerank 精排 → LLM 回答

核心差异在**检索精度**：Naive RAG 只靠向量相似度，容易漏召回；Advanced RAG 通过多路检索+精排，显著提升检索质量。

---

### 2. 什么是 RRF 融合？为什么用排名而不是分数？

**答：**
RRF（Reciprocal Rank Fusion）公式：`score = Σ 1/(k + rank_i)`，k=60。

用排名而不是分数的原因：
- BM25 的分数范围和向量相似度的分数范围不同，无法直接比较
- 排名是归一化的（1, 2, 3...），天然可比
- 不需要复杂的分数归一化逻辑

---

### 3. CrossEncoder 和 Bi-Encoder 的区别？为什么 Rerank 要用 CrossEncoder？

**答：**
- **Bi-Encoder**：Query 和 Doc 分别编码成向量，用余弦相似度比较。速度快（Doc 可预计算），但精度低。
- **CrossEncoder**：Query+Doc 拼接后一起编码，能捕捉更细粒度的语义关系。精度高，但速度慢。

Rerank 用 CrossEncoder 的原因：第二阶段只对 Top-K（如 10-20 条）做精排，数量少，速度可接受，但精度大幅提升。

## 进阶题

### 4. 画出 Advanced RAG 的完整架构图

**答：**
```
用户问题
    ↓
[1] 混合检索（双路并行）
    ├── BM25：按字符分词 → BM25Okapi 评分 → Top-5
    └── 向量：Embedding → Milvus HNSW → Top-5
    ↓
[2] RRF 融合：score = Σ 1/(60 + rank) → 去重排序
    ↓
[3] Rerank 精排：CrossEncoder/FlashRank → Top-3
    ↓
[4] Prompt 组装：{context: 检索结果, question: 用户问题}
    ↓
[5] LLM 生成 → 回答
```

---

### 5. 为什么表格必须整体保留？切碎了对 RAG 有什么影响？

**答：**
表格的语义在于**行列关系**（对比、汇总）。切碎后：
- 只剩孤立数据点，LLM 无法做对比分析
- "哪些数据库支持分布式？"这种跨行查询无法回答

正确做法：按元素类型解析 → Table 整体保留 → 转 Markdown → 存入向量库时标记 `is_table=True`。

---

### 6. LCEL 链路中的 `RunnablePassthrough()` 是什么？

**答：**
`RunnablePassthrough()` 是透传器，把输入原样传给下一个环节。

```python
{"context": retriever | format_docs, "question": RunnablePassthrough()}
```

- `context` 路径：输入 → retriever 检索 → format_docs 格式化
- `question` 路径：输入 → 原样透传

两条路径并行执行，结果合并后传给 prompt。

## 生产实践题

### 7. 生产环境如何选择 Rerank 方案？

**答：**

| 场景 | 推荐方案 | 原因 |
|------|----------|------|
| 低延迟要求 | FlashRank (onnxruntime) | CPU 推理快，无 GPU 依赖 |
| 最高精度 | Cohere Rerank API | 云端大模型，精度最高 |
| 自建部署 | sentence-transformers CrossEncoder | 灵活，可微调 |
| Windows 兼容 | FlashRank | 无 PyTorch DLL 冲突 |

---

### 8. BM25 中文分词用字符还是 jieba？各有什么优缺点？

**答：**
- **按字符分词**：`list("RAG系统")` → `['R','A','G','系','统']`。简单，无依赖，但会丢失词级语义。
- **jieba 分词**：`jieba.cut("RAG系统")` → `['RAG','系统']`。更准确，但需要额外依赖，且分词错误会传播。

**推荐**：Demo 用字符分词够用；生产环境用 jieba 或其他分词器。

---

### 9. 如何评估 Advanced RAG 比 Naive RAG 好？

**答：**
1. **检索评估**：对比两者的 Recall@K、MRR（检索到了多少正确文档）
2. **生成评估**：用 RAGAs/DeepEval 评估 Faithfulness、Answer Relevancy
3. **端到端评估**：准备 Q&A 测试集，对比回答准确率

本 Demo 的对比方式：同一问题，分别用 Naive 和 Advanced 回答，人工判断哪个更好。

---

### 10. Advanced RAG 的瓶颈在哪？如何进一步优化？

**答：**

| 瓶颈 | 优化方向 |
|------|----------|
| BM25 分词不准 | 用 jieba/HanLP 专业分词器 |
| 向量检索语义不足 | 换更大的 Embedding 模型 |
| Rerank 速度慢 | 用 GPU 推理或 FlashRank |
| 表格理解弱 | 表格转 Text2SQL 或结构化存储 |
| 长文档丢失上下文 | Parent-Child 分块策略 |
| 多轮对话 | 加入对话历史压缩 |
