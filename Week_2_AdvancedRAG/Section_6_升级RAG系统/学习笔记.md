## 2. Advanced RAG 完整链路

```
用户问题
    ↓
[1] 混合检索（双路粗召回）
    ├── BM25 稀疏检索：按字符分词 → BM25Okapi 评分 → Top-K
    └── Milvus 向量检索：Embedding → HNSW 近邻搜索 → Top-K
    ↓
[2] RRF 融合排序
    公式：score = Σ 1/(k + rank_i)，k=60
    优势：不需要归一化分数，直接用排名融合
    ↓
[3] Rerank 重排（精排）
    FlashRank（onnxruntime）/ CrossEncoder（PyTorch）
    将 Query+Document 拼接编码，捕捉细粒度语义
    ↓
[4] Top-K 文档 → Prompt → LLM → 回答
```

## 3. 核心组件对比

### 3.1 Naive RAG vs Advanced RAG

| 维度 | Naive RAG | Advanced RAG |
|------|-----------|--------------|
| 检索方式 | 仅向量检索 | BM25 + 向量混合 |
| 排序 | 直接取 Top-K | RRF 融合 + Rerank 精排 |
| 文档解析 | TextSplitter 按字符切 | 按元素类型解析 |
| 表格处理 | 切碎，语义丢失 | 整体保留，转 Markdown |
| 检索精度 | 低 | 显著提升 |
| 复杂度 | 低 | 中 |

### 3.2 Bi-Encoder vs CrossEncoder

| 维度 | Bi-Encoder | CrossEncoder |
|------|------------|--------------|
| 编码方式 | Query 和 Doc 分别编码 | Query+Doc 拼接后一起编码 |
| 速度 | 快（可预计算 Doc 向量） | 慢（每次都要重新编码） |
| 精度 | 中 | 高 |
| 用途 | 向量检索（第一阶段） | 精排（第二阶段） |

### 3.3 Rerank 方案选型

| 方案 | 依赖 | Windows 兼容 | 速度 | 精度 |
|------|------|-------------|------|------|
| sentence-transformers CrossEncoder | PyTorch | 有 DLL 冲突 | 中 | 高 |
| FlashRank | onnxruntime | 完全兼容 | 快 | 中高 |
| Cohere Rerank API | 无（云服务） | 完全兼容 | 快 | 高 |

## 4. LCEL 链路构建

```python
# Advanced RAG 链路
chain = (
    {
        "context": RunnablePassthrough() | advanced_retrieve | format_docs,
        "question": RunnablePassthrough()
    }
    | prompt
    | llm
    | StrOutputParser()
)
```

关键理解：
- `RunnablePassthrough()` 透传原始输入
- `advanced_retrieve` 是自定义函数，内部实现混合检索+RRF+Rerank
- `format_docs` 将 Document 列表格式化为字符串
- `|` 是 LCEL 的管道运算符，数据从左往右流

## 5. BM25 分词策略

```python
# 中文按字符分词（简单方案）
tokenized = [list(doc.page_content) for doc in documents]

# 生产环境用 jieba 分词
import jieba
tokenized = [list(jieba.cut(doc.page_content)) for doc in documents]
```

按字符分词对中文的效果：每个汉字作为一个 token，BM25 按字匹配。
对英文效果较差（整个单词是一个 token），生产环境建议用 jieba。

## 6. RRF 融合公式

```
RRF_score(d) = Σ 1/(k + rank_i(d))

其中：
- k = 60（常数，避免排名靠前的文档权重过大）
- rank_i(d) = 文档 d 在第 i 路检索中的排名
- 求和是对所有检索路的结果
```

优势：不需要归一化不同检索器的分数，直接用排名融合。

## 7. Docker 化部署要点

```dockerfile
FROM python:3.10-slim
# 1. 先装 PyTorch CPU（避免 CUDA 体积）
RUN pip install torch --index-url https://download.pytorch.org/whl/cpu
# 2. 再装其他依赖
RUN pip install -r requirements.txt
# 3. 环境变量配置 Milvus 地址
ENV MILVUS_URI="http://host.docker.internal:19530"
```

容器访问宿主机服务：`--add-host host.docker.internal:host-gateway`

## 8. 踩坑记录

1. **Windows PyTorch DLL 冲突**：c10.dll 加载失败 → 用 Docker 或换 FlashRank
2. **HuggingFace 下载慢**：容器内不走宿主机 VPN → 设置 HTTP_PROXY 环境变量
3. **langchain-milvus 兼容性**：v0.3.x 与 pymilvus 3.x 不兼容 → 手写 MilvusVectorStore 适配器
4. **中文字体缺失**：Linux 容器无中文字体 → PDF 中文显示为方块（不影响文本提取）
