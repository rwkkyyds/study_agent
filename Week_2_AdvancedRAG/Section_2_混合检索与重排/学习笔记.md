# 第2周-Section_2：混合检索 + Rerank 重排 — 学习笔记

## 1. 为什么需要混合检索？

单一向量检索的局限：
- **语义检索**：擅长理解含义（"怎么减肥" → "控制饮食+运动"），但精确匹配弱
- **关键词检索**：擅长精确匹配（"Error 403"），但无法理解语义

混合检索 = 两者互补，效果最好。

## 2. BM25 关键词检索

### 原理
```
TF（词频）：词在文档中出现越多 → 越相关
IDF（逆文档频率）：词在整个语料库中越罕见 → 越有区分度
BM25 = TF × IDF（带长度归一化）
```

### 代码实现
```python
from langchain_community.retrievers import BM25Retriever

bm25_retriever = BM25Retriever.from_documents(documents=docs, k=5)
results = bm25_retriever.invoke("Python match 语法")
```

### 优缺点
| 优点 | 缺点 |
|------|------|
| 精确匹配能力强 | 无法理解语义 |
| 不需要 Embedding 模型 | "猫"和"猫咪"不会匹配 |
| 速度快 | 依赖词频统计 |

## 3. RRF（Reciprocal Rank Fusion）融合策略

### 公式
```
score = Σ 1 / (k + rank_i)
k 通常取 60（平滑常数）
```

### 代码实现
```python
def rrf_fusion(retriever_results, k=60, top_n=5):
    scores = {}
    doc_map = {}
    for results in retriever_results:
        for rank, doc in enumerate(results):
            doc_id = doc.page_content
            if doc_id not in scores:
                scores[doc_id] = 0.0
                doc_map[doc_id] = doc
            scores[doc_id] += 1.0 / (k + rank)
    sorted_docs = sorted(scores.items(), key=lambda x: x[1], reverse=True)
    return [doc_map[doc_id] for doc_id, _ in sorted_docs[:top_n]]
```

### 为什么用 RRF 而不是简单加权？
- RRF 只看排名，不看分数 → 不同检索器的分数尺度不同，无法直接比较
- RRF 对排名靠前的文档给更高权重
- 实践证明 RRF 效果稳定

## 4. Rerank 重排序

### 两阶段检索架构
```
第一阶段（召回）：BM25 + 向量检索 → 粗筛 Top-20
    ↓
第二阶段（精排）：Cross-Encoder 逐个打分 → 重排序 → 输出 Top-5
```

### Bi-Encoder vs Cross-Encoder
| 维度 | Bi-Encoder | Cross-Encoder |
|------|-----------|---------------|
| 输入 | 问题和文档分别编码 | 问题和文档拼接后一起编码 |
| 速度 | 快（可预计算文档向量） | 慢（每次都要重新计算） |
| 精度 | 粗糙 | 精准 |
| 用途 | 检索阶段（召回） | Rerank 阶段（精排） |

### 代码实现（用 LLM 模拟）
```python
# 生产环境用专门的 Rerank 模型（如 bge-reranker）
# 这里用 LLM 模拟打分

```

### 生产级 Rerank 方案
```python

```

## 5. 完整 RAG 检索流程

```
用户问题
  ↓
Query Transformation（Section 1）
  ↓
混合检索：BM25 + 向量检索 → RRF 融合
  ↓
Rerank 重排序（Cross-Encoder）
  ↓
Top-K 文档 → LLM 生成回答
```

## 6. 总结

| 技术 | 作用 | 阶段 |
|------|------|------|
| BM25 | 关键词精确匹配 | 召回 |
| 向量检索 | 语义匹配 | 召回 |
| RRF | 融合多路检索结果 | 召回后 |
| Rerank | 精细重排序 | 精排 |
