# Section 5 学习笔记：复杂文档解析

## 一、为什么需要复杂文档解析？

### Naive RAG 的 TextSplitter 问题
Week 1 用 `RecursiveCharacterTextSplitter` 按字符数切分，存在严重问题：

| 问题 | 后果 |
|------|------|
| 表格被切碎 | 表头和数据行分到不同 chunk，LLM 无法理解 |
| 图片被忽略 | 视觉信息完全丢失 |
| 标题/正文混在一起 | 语义边界模糊 |
| 页眉页脚混入 | 噪音数据 |

### Unstructured 的核心思想
**不是按字符数切分，而是按元素类型分别解析。**

```
TextSplitter 思路：  文本 → 按500字符切 → chunk1, chunk2, chunk3...
Unstructured 思路：  文本 → 识别结构 → Title, Table, ListItem, NarrativeText...
```

## 二、Unstructured 的 Element 体系

Unstructured 将文档解析为结构化元素：

| 元素类型 | 含义 | 处理方式 |
|----------|------|----------|
| `Title` | 标题 | 保留层级关系 |
| `NarrativeText` | 正文段落 | 按语义分块 |
| `Table` | 表格 | **整体保留，不切碎** |
| `ListItem` | 列表项 | 按条目分块 |
| `Image` | 图片 | OCR + 描述 |
| `Header`/`Footer` | 页眉页脚 | 过滤掉 |

### 与 TextSplitter 的本质区别

```python
# TextSplitter：不理解文档结构
chunks = text_splitter.split_text(document)  # 按字符数切

# Unstructured：先理解结构，再按类型处理
elements = partition_pdf("doc.pdf")  # 识别元素类型
for elem in elements:
    if isinstance(elem, Table):
        keep_whole(elem)  # 表格整体保留
    elif isinstance(elem, NarrativeText):
        semantic_split(elem)  # 正文按语义分块
```

## 三、partition_pdf 核心 API

```python
from unstructured.partition.pdf import partition_pdf

elements = partition_pdf(
    filename="doc.pdf",
    strategy="fast",              # fast / hi_res / ocr_only / auto
    infer_table_structure=True,   # 表格结构推断
    extract_images_in_pdf=True,   # 提取图片
)
```

### 解析策略
| 策略 | 速度 | 精度 | 适用场景 |
|------|------|------|----------|
| `fast` | 最快 | 中 | 纯文本、简单 PDF |
| `hi_res` | 慢 | 最高 | 复杂 PDF、扫描件 |
| `ocr_only` | 中 | 中 | 纯扫描件 |

## 四、表格处理的关键

**表格必须整体保留，不能被切碎！**

```python
# 错误：TextSplitter 切碎表格
Chunk 1: "数据库 | 定位 | 最大规模"  # 只有表头
Chunk 2: "FAISS | 向量检索库 | 千万级"  # 只有一行

# 正确：整体保留，转 Markdown
Chunk: "| 数据库 | 定位 | 最大规模 |
        | FAISS | 向量检索库 | 千万级 |
        | Milvus | 生产级向量库 | 十亿级 |"
```

### 表格转 Markdown 的好处
1. 保留行列结构
2. LLM 训练数据中有大量 Markdown，能理解
3. 文本化后可被 embedding 向量化

## 五、Windows 上的 Unstructured 依赖问题

Unstructured 依赖 PyTorch + onnxruntime，在 Windows 上有严重的 DLL 冲突：
- `onnxruntime` 1.25+ 的 `pybind11_state` DLL 加载失败
- PyTorch 的 `c10.dll` 初始化失败

**解决方案**：
1. 生产环境用 Linux Docker（推荐）
2. 用 pdfplumber 实现相同的解析逻辑（本 demo 的做法）
