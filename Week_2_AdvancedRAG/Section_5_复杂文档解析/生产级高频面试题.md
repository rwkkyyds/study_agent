# Section 5 面试题：复杂文档解析

## 基础题

### 1. TextSplitter 和 Unstructured 的本质区别是什么？

**答：**
- **TextSplitter**：不理解文档结构，按字符数固定切分。表格会被切碎，标题和正文混在一起。
- **Unstructured**：先识别文档结构（Title/Table/ListItem/NarrativeText），再按元素类型分别处理。

核心区别：
```
TextSplitter:  文本 → 按500字符切 → chunk1, chunk2...
Unstructured:  文本 → 识别结构 → Title, Table, ListItem → 按类型处理
```

---

### 2. 为什么表格必须整体保留？切碎了会怎样？

**答：**
表格的语义在于**行列关系**（对比、汇总）。切碎后只剩孤立数据点，LLM 无法做对比分析。

错误示例：
```
Chunk 1: "数据库 | 定位 | 最大规模"     # 只有表头
Chunk 2: "FAISS | 向量检索库 | 千万级"  # 只有一行
```
LLM 无法回答"哪些数据库支持分布式？"因为信息被分散了。

正确做法：整体保留，转 Markdown 格式，LLM 能理解并做对比。

---

### 3. Unstructured 的 partition_pdf 有哪些策略？各适合什么场景？

**答：**

| 策略 | 速度 | 精度 | 适用场景 |
|------|------|------|----------|
| `fast` | 最快 | 中 | 纯文本、简单 PDF |
| `hi_res` | 慢 | 最高 | 复杂 PDF、扫描件、多栏 |
| `ocr_only` | 中 | 中 | 纯扫描件 |
| `auto` | 自动 | 自动 | 不确定类型时 |

`fast` 策略不依赖 PyTorch/OCR，速度最快；`hi_res` 需要下载版面分析模型，首次运行较慢。

## 进阶题

### 4. 如何设计 RAG 系统的文档解析 Pipeline？

**答：**
```python
def parse_pipeline(pdf_path):
    # Step 1: 按元素类型解析
    elements = partition_pdf(pdf_path)

    # Step 2: 按类型分别处理
    chunks = []
    for elem in elements:
        if isinstance(elem, Table):
            # 表格整体保留，转 Markdown
            chunks.append(table_to_markdown(elem))
        elif isinstance(elem, NarrativeText):
            # 正文按语义分块
            chunks.extend(semantic_split(elem))
        elif isinstance(elem, ListItem):
            # 列表按条目分块
            chunks.extend(split_list_items(elem))
        # Title、Header、Footer 过滤或特殊处理

    # Step 3: 向量化 → 存入 Milvus
    return chunks
```

### 5. 表格转 Markdown 和转 HTML 哪个更好？

**答：**
- **Markdown**：更简洁，LLM 训练数据中大量 Markdown，理解能力更强
- **HTML**：更精确，保留完整结构，但冗长

**推荐 Markdown**：在 RAG 场景中，表格最终要给 LLM 理解，Markdown 更友好。

```python
# Markdown（推荐）
"| 数据库 | 定位 |\n| FAISS | 检索库 |"

# HTML（保留用）
"<table><tr><th>数据库</th><th>定位</th></tr>...</table>"
```

### 6. Unstructured 在 Windows 上有什么问题？怎么解决？

**答：**
**问题**：Unstructured 依赖 PyTorch + onnxruntime，在 Windows 上有 DLL 冲突：
- `onnxruntime` 1.25+ 的 `pybind11_state` DLL 加载失败
- PyTorch 的 `c10.dll` 初始化失败

**解决方案**：
1. **生产环境用 Linux Docker**（推荐）：无 DLL 问题
2. **用 pdfplumber 实现相同逻辑**：无 PyTorch 依赖，本 demo 的做法
3. **等官方修复**：Unstructured 团队在优化 Windows 支持

## 生产实践题

### 7. 如何评估文档解析的质量？

**答：**
1. **表格完整性**：解析后的表格是否行列完整，数据无遗漏
2. **元素类型准确率**：Title/Table/ListItem 是否被正确识别
3. **端到端效果**：解析后接入 RAG，问答质量是否提升

评估方法：人工对比原始 PDF vs 解析结果，重点关注表格数据。

### 8. 生产环境的文档解析架构怎么设计？

**答：**
```
用户上传文档
    ↓
格式识别（PDF/DOCX/HTML/图片）
    ↓
解析策略选择
    ├── 纯文本 PDF → fast 策略
    ├── 表格 PDF → partition_pdf + infer_table_structure
    ├── 扫描件 → hi_res 策略 + OCR
    └── 复杂文档 → hi_res + 版面分析
    ↓
按元素类型分块
    ├── Table → 整体保留（Markdown）
    ├── NarrativeText → 语义分块
    ├── ListItem → 按条目分块
    └── Title/Header/Footer → 过滤或特殊处理
    ↓
向量化 → 存入 Milvus
```

**关键原则**：表格必须整体保留，不能被切碎。
