# Section 4 学习笔记：Milvus 生产级向量库

## 一、为什么需要 Milvus？

### FAISS 的局限
- 只是向量检索**库**，不是数据库
- 没有持久化（需要手动 save/load）
- 没有分布式能力（单机内存限制）
- 没有 CRUD（只有 Add/Search，删除很麻烦）

### Milvus 的定位
- 生产级向量**数据库**
- 支持十亿级向量存储
- 支持分布式部署（Kubernetes）
- 完整的 CRUD + 标量过滤 + 混合检索

### 选型总结

| 场景 | 推荐 | 原因 |
|------|------|------|
| 本地实验/原型 | FAISS | 零依赖，速度快 |
| 轻量原型 | Chroma | API 简洁，开箱即用 |
| 生产环境 | Milvus | 持久化、分布式、高可用 |

## 二、Milvus 核心概念

### Collection（集合）
相当于关系数据库的"表"，包含 Schema 定义和数据。

### Schema（字段定义）
```python
fields = [
    FieldSchema(name="id", dtype=DataType.INT64, is_primary=True, auto_id=True),
    FieldSchema(name="text", dtype=DataType.VARCHAR, max_length=2048),
    FieldSchema(name="vector", dtype=DataType.FLOAT_VECTOR, dim=512),
    FieldSchema(name="source", dtype=DataType.VARCHAR, max_length=256),
]
```

### Index（向量索引）
| 索引类型 | 特点 | 适用场景 |
|----------|------|----------|
| HNSW | 图索引，查询快，内存大 | 中小规模高召回 |
| IVF_FLAT | 倒排+暴力搜索 | 中等规模 |
| IVF_SQ8 | 倒排+标量量化 | 节省内存 |
| DISKANN | 磁盘索引 | 超大规模 |

### Search（搜索）
- 向量相似度搜索（ANN）
- 标量过滤（`filter='source == "tech_doc"'`）
- Top-K 查询

## 三、pymilvus SDK 操作

### 新旧 API 对比

| 操作 | 旧 API（ORM） | 新 API（MilvusClient） |
|------|--------------|----------------------|
| 连接 | `connections.connect()` | `MilvusClient(uri=...)` |
| 创建 | `Collection(schema)` | `client.create_collection()` |
| 插入 | `collection.insert()` | `client.insert()` |
| 搜索 | `collection.search()` | `client.search()` |
| 删除 | `collection.delete()` | `client.delete()` |

**新 API 更简洁，是 pymilvus 3.x 的推荐方式。**

### 关键操作流程
```python
# 1. 连接
client = MilvusClient(uri="http://localhost:19530")

# 2. 创建 Collection + 索引
client.create_collection(collection_name="demo", schema=schema)
index_params = client.prepare_index_params()
index_params.add_index(field_name="vector", index_type="HNSW", metric_type="COSINE")
client.create_index(collection_name="demo", index_params=index_params)

# 3. 插入
client.insert(collection_name="demo", data=[{"text": "...", "vector": [...]}])

# 4. 加载到内存（搜索前必须）
#内存指的是 Milvus 的内存
client.load_collection("demo")

# 5. 搜索
results = client.search(collection_name="demo", data=[query_vector], limit=3)

# 6. 过滤搜索
results = client.search(collection_name="demo", data=[query_vector],
                        filter='source == "tech_doc"', limit=3)
```

## 五、Docker 部署 Milvus

### 架构组成（standalone 模式） 
- standalone 模式适合开发和小规模生产，包含 Milvus 核心、etcd（元数据存储）和 MinIO（对象存储）。对于大规模生产环境，推荐使用 Milvus Operator 在 Kubernetes 上部署。
```
┌─────────────┐
│  Milvus      │ ← 向量数据库核心
│  Standalone  │
└──────┬──────┘
       │
  ┌────┴────┐
  │         │
┌─┴──┐  ┌──┴─┐
│etcd│  │MinIO│ ← 元数据 + 对象存储
└────┘  └────┘
```

### docker-compose.yml 关键配置
- **etcd**: 元数据存储
- **MinIO**: 对象存储（向量数据持久化）
- **Milvus**: 数据库核心
- 端口：19530（gRPC）、9091（健康检查）

## 六、踩坑记录

1. **pymilvus 版本兼容**：3.x 废弃旧 ORM API，langchain-milvus 与 3.x 有兼容问题
2. **搜索前必须 load**：`client.load_collection()` 把数据加载到内存
3. **onnxruntime DLL 问题**：Windows 上需要降级到 1.19.x
4. **中文引号冲突**：Python 字符串中的中文引号 `""` 会截断字符串
