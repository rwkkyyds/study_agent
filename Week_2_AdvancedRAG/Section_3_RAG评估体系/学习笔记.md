# 第2周-Section_3：RAGAs、DeepEval RAG 自动化评估体系 — 学习笔记

## 1. 为什么需要 RAG 评估？

RAG 系统搭好了，怎么知道它好不好？

| 评估方式 | 优点 | 缺点 |
|----------|------|------|
| 人工评估 | 准确、能判断语义 | 慢、贵、不可持续 |
| 自动化评估 | 快、可量化、可集成CI/CD | 依赖评估模型质量 |

**评估维度**：
- **检索质量**：找到的文档是否相关？
- **生成质量**：LLM 的回答是否忠实于检索结果？

## 2. RAGAs 框架

RAGAs（Retrieval Augmented Generation Assessment）是 RAG 评估的标准框架。

### 核心指标

| 指标 | 含义 | 评估什么 | 计算方式 |
|------|------|----------|----------|
| Faithfulness | 忠实度 | 回答是否基于检索文档（不编造） | LLM 判断每句话是否有文档支撑 |
| Answer Relevancy | 答案相关性 | 回答是否切题 | 生成反向问题，计算相似度 |
| Context Precision | 上下文精确度 | 相关文档排名是否靠前 | 看相关文档在 Top-K 中的位置 |
| Context Recall | 上下文召回率 | 相关文档是否都被检索到 | 和 ground_truth 对比 |

### 代码实现要点
```python
from ragas import evaluate
from ragas.metrics import faithfulness, answer_relevancy, context_precision, context_recall

# 准备评估数据（需要 question, answer, contexts, ground_truth）
dataset = Dataset.from_dict({
    "question": [...],
    "answer": [...],        # LLM 生成的回答
    "contexts": [...],      # 检索到的文档列表
    "ground_truth": [...],  # 标准答案
})

# 运行评估
result = evaluate(
    dataset=dataset,
    metrics=[faithfulness, answer_relevancy, context_precision, context_recall],
    llm=llm,           # 评估用的 LLM
    embeddings=embeddings,  # 评估用的 Embedding
)
```

### 注意事项
- RAGAs 内部会用 LLM 做评估（如判断忠实度），需要配置评估用 LLM
- `ground_truth` 是可选的，但有它才能计算 Context Recall
- 评估数据质量直接影响评估结果

## 3. DeepEval 框架

DeepEval 是另一个 RAG 评估框架，特点：
- 支持 pytest 集成（可写成单元测试）
- 支持 G-Eval 自定义评估标准
- 评估指标和 RAGAs 类似，但接口不同

### 核心指标

| DeepEval 指标 | 对应 RAGAs 指标 | 含义 |
|---------------|-----------------|------|
| FaithfulnessMetric | Faithfulness | 忠实度 |
| AnswerRelevancyMetric | Answer Relevancy | 答案相关性 |
| ContextualPrecisionMetric | Context Precision | 上下文精确度 |
| ContextualRecallMetric | Context Recall | 上下文召回率 |

### 代码实现要点
```python
from deepeval import evaluate
from deepeval.test_case import LLMTestCase
from deepeval.metrics import FaithfulnessMetric, AnswerRelevancyMetric

# 创建测试用例
test_case = LLMTestCase(
    input="什么是RAG？",
    actual_output="RAG是检索增强生成技术...",
    retrieval_context=["RAG通过检索外部知识来增强大模型回答..."],
    expected_output="RAG是检索增强生成技术...",
)

# 定义评估指标
metric = FaithfulnessMetric(threshold=0.7) # 设定忠实度阈值

# 评估
metric.measure(test_case)
print(f"Score: {metric.score}, Pass: {metric.is_successful()}")
```

### pytest 集成
```python
# 可以写成 pytest 测试用例
def test_rag_faithfulness():
    test_case = LLMTestCase(...)
    metric = FaithfulnessMetric(threshold=0.7) 
    #metric 内部会调用 LLM 来判断回答是否忠实于检索上下文
    assert metric.measure(test_case)
```

## 4. RAGAs vs DeepEval 对比

| 维度 | RAGAs | DeepEval |
|------|-------|----------|
| 指标 | 4 个核心指标 | 更多指标（含 G-Eval） |
| 接口 | Dataset 批量评估 | TestCase 逐个评估 |
| pytest | 不支持 | 原生支持 |
| 自定义 | 较难 | 支持 G-Eval 自定义 |
| 适用 | 批量评估、报告生成 | CI/CD、单元测试 |

**生产建议**：
- 开发阶段用 DeepEval（集成 pytest，每次提交自动评估）
- 定期用 RAGAs 生成评估报告（批量评估、趋势分析）

## 5. 评估数据集构建

### 必需字段
| 字段 | 来源 | 是否必需 |
|------|------|----------|
| question | 用户真实问题 | 必需 |
| answer | LLM 生成的回答 | 必需 |
| contexts | 检索到的文档 | 必需 |
| ground_truth | 人工标注的标准答案 | 可选（有它才能算 Recall） |

### 构建方法
1. **从线上日志收集**：收集真实用户问题和 RAG 系统的回答
2. **人工标注**：标注每个问题的标准答案和相关文档
3. **LLM 辅助生成**：用 LLM 生成候选答案，人工审核

## 6. 总结

| 框架 | 核心价值 | 适用场景 |
|------|----------|----------|
| RAGAs | 标准化评估、批量报告 | 定期评估、趋势分析 |
| DeepEval | pytest 集成、CI/CD | 开发阶段、自动化测试 |

**关键指标**：
- Faithfulness < 0.8 → 检查 LLM 幻觉问题
- Context Precision < 0.8 → 检查检索排序质量
- Context Recall < 0.8 → 检查检索召回率（需要 ground_truth）
