# 第2周-Section_3：RAGAs、DeepEval RAG 自动化评估体系 — 生产级高频面试题

## Q1: 为什么需要 RAG 自动化评估？

**答**：
1. **人工评估太慢太贵**：每次改 Prompt/换模型/调参数，都需要重新评估
2. **需要量化指标**：无法用"感觉还行"来判断系统好坏
3. **CI/CD 集成**：每次代码提交自动评估，防止退化
4. **A/B 测试**：对比不同方案的效果差异

**评估维度**：
- 检索质量：找到的文档是否相关？
- 生成质量：回答是否忠实于检索结果？

---

## Q2: RAGAs 的四个核心指标是什么？

**答**：
| 指标 | 含义 | 评估什么 |
|------|------|----------|
| Faithfulness | 忠实度 | 回答是否基于检索文档（不编造） |
| Answer Relevancy | 答案相关性 | 回答是否切题 |
| Context Precision | 上下文精确度 | 相关文档排名是否靠前 |
| Context Recall | 上下文召回率 | 相关文档是否都被检索到 |

**关键点**：
- Faithfulness 最重要：如果回答编造内容，其他指标再好也没用
- Context Recall 需要 ground_truth（标准答案），其他三个不需要

---

## Q3: Faithfulness 低说明什么问题？怎么优化？

**答**：
**Faithfulness 低** = LLM 在编造内容（幻觉）

**优化方法**：
1. **Prompt 工程**：明确告诉 LLM "只基于提供的文档回答，不要编造"
2. **温度设为 0**：`temperature=0`，减少随机性
3. **检索质量**：确保检索到的文档确实包含答案
4. **换更强的模型**：强模型幻觉更少

---

## Q4: Context Precision 低说明什么问题？怎么优化？

**答**：
**Context Precision 低** = 相关文档排名靠后，不相关文档排在前面

**优化方法**：
1. **加 Rerank**：用 Cross-Encoder 精排
2. **优化 Embedding**：换更强的 Embedding 模型
3. **混合检索**：BM25 + 向量检索互补
4. **调整 Top-K**：减少检索数量，只保留最相关的

---

## Q5: RAGAs 和 DeepEval 有什么区别？

**答**：
| 维度 | RAGAs | DeepEval |
|------|-------|----------|
| 指标 | 4 个核心指标 | 更多指标（含 G-Eval） |
| 接口 | Dataset 批量评估 | TestCase 逐个评估 |
| pytest | 不支持 | 原生支持 |
| 自定义 | 较难 | 支持 G-Eval 自定义 |
| 适用 | 批量评估、报告生成 | CI/CD、单元测试 |

**生产建议**：
- 开发阶段用 DeepEval（集成 pytest）
- 定期用 RAGAs 生成评估报告

---

## Q6: 如何构建 RAG 评估数据集？

**答**：
**必需字段**：
- `question`：用户真实问题
- `answer`：LLM 生成的回答
- `contexts`：检索到的文档列表
- `ground_truth`：人工标注的标准答案（可选，有它才能算 Recall）

**构建方法**：
1. **线上日志收集**：收集真实用户问题和 RAG 系统回答
2. **人工标注**：标注标准答案和相关文档
3. **LLM 辅助**：用 LLM 生成候选答案，人工审核

**数据量建议**：至少 50-100 条，覆盖主要场景

---

## Q7: 评估指标不达标怎么办？

**答**：
| 指标 | 不达标原因 | 优化方向 |
|------|-----------|----------|
| Faithfulness < 0.8 | LLM 幻觉 | Prompt 工程、temperature=0、换模型 |
| Answer Relevancy < 0.8 | 回答不切题 | 优化 Prompt、加指令约束 |
| Context Precision < 0.8 | 检索排序差 | 加 Rerank、优化 Embedding |
| Context Recall < 0.8 | 检索召回低 | 混合检索、多查询改写、扩大 Top-K |

**排查顺序**：先看 Context Recall → 再看 Context Precision → 最后看 Faithfulness

---

## Q8: 如何将 RAG 评估集成到 CI/CD？

**答**：
```python
# 用 DeepEval + pytest
def test_rag_faithfulness():
    test_case = LLMTestCase(
        input="什么是RAG？",
        actual_output=rag_system.answer("什么是RAG？"),
        retrieval_context=rag_system.retrieve("什么是RAG？"),
    )
    metric = FaithfulnessMetric(threshold=0.8)
    assert metric.measure(test_case)
```

**CI/CD 流程**：
1. 代码提交 → 触发 pytest
2. 运行 RAG 评估测试用例
3. 指标不达标 → 阻断合并
4. 指标达标 → 允许合并 + 记录趋势
