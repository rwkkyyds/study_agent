# 第2周-Section_1：Query Transformation — 学习笔记

## 1. 为什么需要 Query Transformation？

用户原始问题直接做向量检索，效果往往不好，原因：
- **问题太短**：如"什么是RAG？"，只有几个字，Embedding 语义信息少
- **语义鸿沟**：用户口语化表述 vs 文档书面化表述，向量距离远
- **多意图模糊**：如"RAG有什么优缺点？"，一个问题包含多个子意图

**解决思路**：在检索前，用 LLM 把问题"变换"成更适合检索的形式。

## 2. HyDE（Hypothetical Document Embeddings）

### 原理
```
用户问题 → LLM生成假设性答案文档 → 对假设文档做Embedding → 向量检索
```

### 为什么有效？
- 假设性文档比原始问题更长、语义更丰富
- 假设文档的表述更接近目标文档，向量相似度更高
- 相当于用"答案"去找"答案"，而不是用"问题"找"答案"

### 代码实现要点
```python
# HyDE链：问题 → 假设性文档
hyde_prompt = ChatPromptTemplate.from_template("""
请根据以下问题，写一段可能包含答案的技术文档内容（约100字）。
问题：{question}
假设性文档：
""")
hyde_chain = hyde_prompt | llm | StrOutputParser()

# 用假设性文档检索（而不是原始问题）
hypothetical_doc = hyde_chain.invoke({"question": question})
results = retriever.invoke(hypothetical_doc)
```

### 代价
- 多一次 LLM 调用 → 增加延迟和成本
- 假设文档质量取决于 LLM 能力

## 3. 多查询改写（Multi-Query）

### 原理
```
原始问题 → LLM改写成N个子问题 → 分别检索 → 合并去重
```

### 为什么有效？
- 单一问题只能命中部分文档
- 不同角度的子问题能覆盖更多相关文档
- 合并去重后，召回范围显著扩大

### 代码实现要点
```python
# 多查询改写链
multi_query_prompt = ChatPromptTemplate.from_template("""
请将以下问题改写成3个不同角度的子问题，每个子问题单独一行。
原始问题：{question}
""")
multi_query_chain = multi_query_prompt | llm | StrOutputParser()

# 分别检索 + 去重
raw_output = multi_query_chain.invoke({"question": question})
sub_questions = raw_output.strip().split("\n")
all_docs = []
for q in sub_questions:
    all_docs.extend(retriever.invoke(q))

# 去重
seen = set()
unique_docs = [doc for doc in all_docs
               if hash(doc.page_content) not in seen
               and not seen.add(hash(doc.page_content))]
               #这里的set.add()返回None,就是说and的后面永远是True,
               # 所以只要hash(doc.page_content)不在seen中就会被加入unique_docs中
```

### 代价
- 多次 LLM 调用（生成子问题）+ 多次检索
- 需要做结果去重

## 4. 本地 Embedding 方案：fastembed + BGE

### 为什么用本地模型？
- 不依赖外部 API，无配额限制
- 无网络延迟，速度快
- 数据不出本地，隐私安全

### 技术选型
| 方案 | 依赖 | 说明 |
|------|------|------|
| fastembed + BGE | onnxruntime | 基于 ONNX，不依赖 torch，轻量 |
| langchain_huggingface | sentence-transformers + torch | 功能全，但依赖重 |

### 适配 LangChain 接口
```python
from fastembed import TextEmbedding
from langchain_core.embeddings import Embeddings

class FastEmbedEmbeddings(Embeddings):
    def __init__(self, model_name="BAAI/bge-small-zh-v1.5"):
        self._model = TextEmbedding(model_name)

    def embed_documents(self, texts):
        return [list(v) for v in self._model.embed(texts)]

    def embed_query(self, text):
        return list(list(self._model.embed([text]))[0])
```

**注意**：fastembed 的 `embed()` 返回 generator，需要 `list()` 转换。

### Demo2 多查询改写

- 3 个子问题改写后，合并去重命中 3 个文档（多了 rag_eval）
- 召回范围扩大 50%

## 6. 总结

| 技术 | 核心思想 | 适用场景 | 代价 |
|------|----------|----------|------|
| HyDE | 用答案找答案 | 问题短/口语化 | +1次LLM调用 |
| 多查询改写 | 多角度扩大召回 | 多意图/模糊问题 | +N次LLM+检索 |

**生产建议**：
- HyDE 适合单轮精确检索
- 多查询改写适合需要高召回的场景
- 两者可组合使用
